# Changelog

All notable changes to `precision-soft/melody/integrations/amqp/v4` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `module.go`, `service_resolver.go`: `ModuleConfig.ConnectionBuiltAtBoot` builds `service.amqp.connection` inside `Boot`, under the boot runtime, so an unreachable broker is known before the first request, and `ModuleConfig.ConnectionBootFailure` is its boot failure mode, `BootFailureWarns` when left out; a boot mode with no `Connection`, and a failure mode on a connection not built at boot, are refused at registration naming the field and what it requires.
- `transport.go`: `HeaderNameMaximumLength`, 239, what a 255-byte amqp header key holds behind `ApplicationHeaderPrefix`; `NewTransport` refuses a `TransportConfig.Headers.MaxNameLength` above it naming the field, so a name of 240 to 255 bytes, which the messagebus rule admits, is refused at construction rather than failing inside the client at the publish.
- `plaintext_dsn.go`, `connection.go`, `transport.go`, `server_sent_event_backplane.go`: a plain `amqp://` dsn whose host is not `localhost` or a loopback address is named by the warning `amqp.plaintextDsn` (`PlaintextDsnBootWarningName`) once per host of the provider, naming the host and never the dsn: `Provider.Open` writes it in the runtime's journal honouring `MELODY_BOOT_WARNINGS_IGNORED`, and a dialer from `Provider.Dialer` at a dial, in the journal of the first runtime its transport served, honouring the key too, or through a backplane's `ServerSentEventBackplaneConfig.Logger`; `Module.RegisterBootWarnings` declares the code, the module now a `BootWarningModule`.
- `transport.go`: `TransportConfig.DeadLetterMaxLength` (a `bound.Count`, at least 1) and `TransportConfig.DeadLetterTtl` (a `bound.Duration`, 1ms to the 32-bit millisecond limit, whole milliseconds) cap the `<queue>.dlq` queue, declared as its `x-max-length` and `x-message-ttl`; each is unlimited when left out and then declares no argument, so the default declare is unchanged; a cap beside `DeadLetterDisabled` is refused naming the field, and a `PRECONDITION_FAILED` declare of the `.dlq` names both fields under `fields`.
- `ConnectionMustFromRuntime(runtimeInstance)`, the connection read through the runtime's scope under its context, for code that holds a runtime; a nil runtime is refused. `ConnectionMustFromResolver` stays the door of a provider.
- **Breaking** — `service_resolver.go`: `ConnectionMustFromContainer` is removed, `ConnectionMustFromResolver` taking the container as it takes a scope.
- This major includes every change of the third major up to v3.3.0; that history is in the third major's changelog, and the third-major fixes released after it are listed below as carried.
- `transport.go`: the envelope's headers, `messagebus.HeadersStamp`, cross the broker as AMQP headers named `ApplicationHeaderPrefix` + the name, `x-melody-header-<name>`, rebuilt as one `HeadersStamp` on receive from every prefixed header carrying a string, a prefixed header of another type skipped with one warning naming the header and its Go type; `TransportConfig.Headers`, a `messagebus.HeaderLimitsConfig`, bounds one publish, a refusal caused by `messagebus.ErrHeadersRefused` answered before any dial or write and not marked as an outage; a redelivery and a delay keep the headers.
- `connection.go`, `transport.go`, `server_sent_event_backplane.go`: `CloseTimeout` on `ProviderConfig`, `TransportConfig` and `ServerSentEventBackplaneConfig` bounds each stretch of a close that cannot observe its signal and every wait on a call the client may park behind a wedged write, 30s when left out as the package constant was, at least 1ms, unlimited refused; a transport or a backplane built through the provider takes the provider's when its own is left out.

### Changed

- `transport.go`, `stamp.go`: a header name is bounded by `TransportConfig.Headers.MaxNameLength` on write; a delivery's header names are read up to `messagebus.HeaderNameMaximumLength`, so a name a longer-configured producer wrote is no longer skipped, and a requeue admits the longer of the transport's name length and the longest name the delivery arrived with, a longer name the handler added dropped with its warning.
- `transport.go`: the GoDoc of `TransportConfig.Prefetch` states that its range is the one of the 16-bit prefetch count of `basic.qos` and that unlimited is refused
- **Breaking** — `server_sent_event_backplane.go`: `NewServerSentEventBackplane` refuses a typed-nil `ServerSentEventBackplaneConfig.Logger` as `amqp server sent event backplane logger is a typed nil`, naming the field, where it read as absent; **Behavioural change**: a backplane built without a logger reports its failures on the emergency logger, where only a terminal stop reached it.
- `README.md`: the bus samples dispatch with the fourth major's `messagebuscontract.DispatchOptions{}` and build the handle middleware with `messagebus.HandleMiddlewareConfig{}`.
- **Breaking** — `server_sent_event_backplane.go`: `ServerSentEventBackplane.Publish(runtimeInstance, topic, event)` takes the caller's runtime, as `http.ServerSentEventBackplane` now declares; a nil runtime is refused naming `door` `amqp.ServerSentEventBackplane.Publish`, a done context is refused before the event is encoded with `sse backplane publish refused: the caller's context is done` and the context's cause, and the wait for the turn ends at the earlier of `CallTimeout`, the caller's context and the backplane's close, a turn lost to the caller's context keeping the channel and marking nothing, and a write once begun is waited for under `CallTimeout` alone.
- **Breaking** — `connection.go`, `server_sent_event_backplane.go`: `NewProvider(namespace, config)` takes the application namespace, a namespace outside `config.ValidateNamespace` panicking naming the argument, and a backplane built through the provider derives its default exchange from it, `<namespace>.sse`, byte-identical under `melody`; the package's own `NewServerSentEventBackplane` keeps `melody.sse`, an `Exchange` set is used verbatim, and a transport's names never take the namespace. See the framework's `UPGRADE.md`.
- **Breaking** — `connection.go`, `connection_owner.go`: a connection has one owner, `*amqp.Connection`, answered by `Provider.Open(runtimeInstance, dsn)` and by every `Dialer`, carrying the close timeout of what built it and closed once through its own `CloseWithContext`, bounded as the provider's close was; `connection.Raw()` reaches the client's connection, and `NewConnection(raw, ConnectionConfig{CloseTimeout})` wraps one dialled elsewhere, a nil one refused naming `raw`. `Provider.Close` and `Provider.CloseWithContext` are removed. A nil runtime is refused naming `amqp.Provider.Open`. See `UPGRADE.md`.
- **Breaking** — `connection.go`: the dial runs under the caller's context bounded by `ProviderConfig.DialTimeout`, 30s when left out, at least 1ms, unlimited refused, the dsn's `connection_timeout` no longer read: a context already done refuses before the dial, one that ends during the dial or the handshake closes the socket and the refusal carries its cause beside the redacted dial error. `ProviderConfig.TlsConfig` is copied at `NewProvider` and handed to each dial as a clone, a dsn that is not `amqps` beside it refused naming the field; `ProviderConfig.ConnectionName`, at most 255 bytes with no control character, is shown by the broker beside the client's own properties.
- **Breaking** — `connection_owner.go`, `transport.go`, `server_sent_event_backplane.go`: `amqp.Dialer` is `func(dialContext context.Context) (*amqp.Connection, error)`, cancelled by a transport or a backplane when its close stops waiting for the dial; `Provider.Dialer(dsn)` refuses an empty dsn, and a TLS configuration beside a plain one, when it is built. A dialer answering neither a connection nor an error is refused as a failed dial.
- **Breaking** — `connection_owner.go`, `transport.go`, `server_sent_event_backplane.go`: `NewTransport(queue, registry, source, config)` and `NewServerSentEventBackplane(hub, source, config)`, the provider's doors alike, take a required `ConnectionSource` built by `FromConnection(connection)`, a borrowed connection whose loss is terminal, or `FromDialer(dialer)`, which dials on first use and after every loss; `Connection` and `Dialer` leave `TransportConfig` and `ServerSentEventBackplaneConfig`, so a connection with a dialer after its loss has no spelling left; the zero source is refused naming `source` and both doors, a nil connection or dialer at its door.
- **Breaking** — `module.go`, `service_resolver.go`: `ModuleConfig.Connection` is the factory of `ServiceConnection`, `func(resolver) (*amqp.Connection, error)`, and `ModuleConfig.Transports` maps each service name to the factory of its transport, both run at first resolution, so a transport over the shared connection resolves it; the container closes the connection through the owner's close and the close timeout it carries. `ModuleConfig.CloseTimeout`, `ConnectionServiceConfig`, `RegisterConnectionService`, `RegisterTransportService` and the `ServiceRegistrar` interface are removed, the module being the one door; `ConnectionMustFromRuntime` and `ConnectionMustFromResolver` answer the owner.

- **Behavioural change** — `transport.go`, `server_sent_event_backplane.go`: the close of a connection a transport or a backplane dialed itself, and of a dial that lands after their close began or that their close stopped waiting for, is bounded by `CloseTimeout`, where it was bounded by `CallTimeout`; the publish join of a close and every send keep `CallTimeout`. See `UPGRADE.md`.
- **Breaking** — `transport.go`, `server_sent_event_backplane.go`, `connection.go`: `NewTransport(queue, registry, config)` and `NewServerSentEventBackplane(hub, config)`, and the provider's doors alike, take the queue, the registry and the hub positionally, an empty or nil one refused with the same message and its context naming `argument`; `Queue`, `Registry` and `Hub` leave the config structs.
- **Breaking** — `transport.go`: `TransportConfig.DeadLetter` is `DeadLetterDisabled`, so the transport declares `<queue>.dlx` and `<queue>.dlq` and dead-letters a poison message unless the door is set; a queue declared earlier without `x-dead-letter-exchange` fails the declare with `PRECONDITION_FAILED`, the error's context naming `TransportConfig.DeadLetterDisabled` unless the door is already set, and leaves the `<queue>.dlx` and `<queue>.dlq` the default declared, which an upgrader taking the door deletes by hand.
- **Breaking** — `transport.go`: `Receive` answers a `messagebuscontract.Subscription`, whose `Err()` names why the consume loop ended for good, the connection gone with no dialer or the channel it could not reopen, nil for a stop through the runtime or `CloseWithContext`; `Nack` takes a `messagebuscontract.NackConfig{Requeue}`.
- **Breaking** — `transport.go`: `TransportConfig.PublishTimeout` is `CallTimeout`, the name the backplane uses for the same bound, its refusal naming `TransportConfig.CallTimeout` and its log and error context key `callTimeout`, and the publish refusals read "within the call timeout" where they read "within the publish timeout". See `UPGRADE.md`.
- **Breaking** with the framework: the fourth major's runtime is read from `v4/container/contract` and built through `v4/container/runtime`, a runtime resolving through its scope only; `runtime.New` and `Runtime.Container()` are gone. See the framework's `UPGRADE.md`.
- **Behavioural change** — `transport.go`: `Transport.Send` marks a failed publish with `exception.MarkInfrastructureFailure`, except the broker's verdict on the message (an unroutable return, a channel the broker closed over a live connection, each carrying a cause naming the verdict), a failure the caller's own context explains and a transport that is closing, so the outbox relay hands the row back uncharged and an http handler answers 503 with Retry-After where it answered 500; a nack (a `reject-publish` overflow, an internal queue error) is an outage like an unreachable broker, marked, and a retry re-publish keeps trying through it under the reconnect backoff where it gave the delivery up at the first nack; a nack does not mean no queue took the message, so each further attempt delivers one more copy to the other queues of a fan-out whose one full queue refused it.
- **Behavioural change** — `module.go`: `RegisterServices` refuses a nil entry of `Transports`, naming the transport, before it registers anything, where it skipped the transport.
- **Behavioural change** — `service_resolver.go`: the module registers the connection and the transports with `TeardownReflectionDisabled`, so the teardown, which walks what each service holds by default in the fourth major, never reads a live connection or transport, and every transport declares `ServiceConnection` as an optional teardown dependency, so every transport closes before the registered connection, where the order was inferred from the connection pointer the transport holds.
- **Breaking** — `service_resolver.go`: `ConnectionMustFromResolver` and `TransportMustFromResolver` take a `context.Context` first, the fourth major's resolver form, which bounds the wait on a connection or a transport another goroutine is building.
- **Breaking** — `connection.go`, `reconnect_config.go`: `NewProvider` takes one `ProviderConfig` of `Heartbeat`, `Reconnect`, `CloseTimeout`, `DialTimeout`, `TlsConfig` and `ConnectionName`, resolved once, a value outside its rule panicking naming the field; `ReconnectConfig` is a value of the bound limits `InitialBackoff` 1s and `MaxBackoff` 30s, at least 1ms, unlimited refused, and `BackoffFactor`, 2 when left out, and `TransportConfig.Reconnect` and `ServerSentEventBackplaneConfig.Reconnect` take it by value where they took a pointer. A field a transport or a backplane leaves out is the provider's for one the provider built and the default otherwise, the backoff judged on the merged result.
- **Breaking** — `reconnect_config.go`: an initial backoff above the cap is refused naming both fields, a cap a component lowers under an inherited initial included, where the first wait silently exceeded the cap; a `BackoffFactor` below 1 or NaN is refused naming the field where it silently kept the layer under it.
- **Breaking** — `connection.go`: the heartbeat is always installed, 10s when left out, the figure the client applied, at least 1s, unlimited refused, where a value under one second was passed and read by the client as the server's interval.
- **Breaking** — `transport.go`: `Prefetch` and `PublishReturnBuffer` are `bound.Count` and `CallTimeout` a `bound.Duration`; `Prefetch` is 10 when left out where it was 1, at least 1 and at most 65535, refused above where it was clamped onto the wire limit; `PublishReturnBuffer` 16 and `CallTimeout` 30s when left out, at least 1 and 1ms, unlimited refused, and a zero is refused where it took the default.
- **Breaking** — `server_sent_event_backplane.go`: `CallTimeout` is a `bound.Duration`, 1s when left out, at least 1ms, unlimited refused, resolved before the backplane is installed on the hub, so a refused config leaves the hub without a backplane.
- **Breaking** — `transport.go`, `server_sent_event_backplane.go`: `Transport` and `ServerSentEventBackplane` lose `Close`, which was `CloseWithContext` under no deadline; `CloseWithContext` is their one door, the fourth major's teardown door, and the messagebus `Transport` contract declares it.
- `transport.go`: a decoded delivery is built with `messagebus.NewEnvelope(message, stamps)`, the fourth major's envelope form, where it spread the stamps into the variadic; the readme's bus and consumer samples take the fourth major's slice and config forms.
- `server_sent_event_backplane.go` and `transport.go`: the log records are built through `exception.LogContext(err, exception.LogContextConfig{...})`, the fourth major's form, which takes the extra context in a struct; nothing of this module's own surface changes.
- **Breaking** — `reconnect_config.go`: `ReconnectConfig.InitialBackoff`, `MaxBackoff` and `BackoffFactor` are one `ReconnectConfig.Backoff bound.Backoff` (1s, 30s, 2), each field left out still the parent's, the merged backoff refused naming `ReconnectConfig.Backoff.<field>`; the transport's subscribe, consume and republish loops and the backplane's re-subscription count their attempts and wait `ResolvedBackoff.Delay(attempt)`, the sequences on the defaults unchanged.

### Removed

- **Breaking** — `parameter.go`, `module.go`: `ParameterDsn`, `ParameterExchange`, `ParameterPrefetch`, `ParameterRegistrar`, `RegisterDefaultParameters` and `ModuleConfig.WithDefaultParameters`; the module no longer implements `ParameterModule`. Nothing of the module read the three parameters, and the default dsn was a credential registered in clear; the application reads its own key for the dsn, as the example does.
- **Breaking** — `connection.go`, `reconnect_config.go`: `ProviderOption`, `WithHeartbeat`, `WithReconnectConfig`, `DefaultReconnectConfig` and `NewReconnectConfig`.

### Fixed

- `transport.go`: a received `x-melody-header-*` string header whose name or value fails the header rule is skipped with a warning naming the header, never its value, and the requeue, delay and retry re-publish of a received envelope is bounded by the larger of `TransportConfig.Headers` and the count and bytes the delivery arrived with, a header the handler added that fails the name and value rule dropped with a warning naming it, so a message another producer sent with such a header or with more headers than this transport writes is requeued with its advanced counts, where the re-publish was refused and the delivery dead-lettered at its first failure, or, under `DeadLetterDisabled`, returned uncounted at once in a loop while `Nack` answered nil.
- `publish_half.go`, `transport.go`, `server_sent_event_backplane.go` — carried from the third major (v3.3.2): a publish whose write outlived its budget on a connection the transport or the backplane dialed itself lets go of that connection, with the channels that ride it, in the same critical section that decides to cut it, so the `Send`'s one retry and the backplane's next publish redial instead of being handed the cut connection back; the client reports a connection closed only once the close the cut starts has returned, which the cut does not wait for, and an attempt reaching the cut connection in that window failed with `amqp channel open failed` on the transport and `amqp sse backplane channel open failed` on the backplane (6 of 200 wedged sends on the live suite, 0 of 200 after the fix); a `Close` that finds a write still blocked on the owned connection already cut reports it, where it would have found nothing left to close.
- `publish_half.go`, `transport.go`, `server_sent_event_backplane.go` — carried from the third major (v3.3.2): the abandon of a write that outlived its budget cuts the connection that write's channel rides, never another: each owner keeps the connection its publish channel was opened on beside the channel, and cuts and lets go of it only while it still holds it, where it cut whichever connection it held by then; a write wedged on a connection whose own shutdown had begun, while the consume or listen loop had already redialed, cut the fresh healthy connection, left the write where it was and held the `Send` for the whole join bound; a write on a connection the owner no longer holds is waited for under the same bound, with nothing cut.
- `transport.go`, `server_sent_event_backplane.go`, `publish_half.go` — carried from the third major (v3.3.3): the error a timed-out publish answers on a connection the transport or the backplane dialed itself names the connection the write rides as torn down, where it said the owned connection was cut or closed also when the write rode a connection the owner had already replaced, whose own shutdown was ending it and which nothing cut; the verdicts' and the cut's documentation read the same, and neither they nor `connection.go`'s `CloseWithContext` say any longer that the client's close first takes the connection mutex.
- transport: a dialer's error whose `Unwrap` chain reaches itself no longer holds the `Send` or the server-sent event backplane that classifies it, and a close error on such a chain no longer holds `Close`.

### Security

- `go.mod` — carried from the third major (v3.3.1): `github.com/rabbitmq/amqp091-go` is required at v1.14.0, the fix for [GO-2026-6700](https://pkg.go.dev/vuln/GO-2026-6700), reachable through `Provider.Open`, which dials with `amqp091.DialConfig`.
