# Changelog

All notable changes to `precision-soft/melody/integrations/outbox/v4` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Removed

- **Breaking** — `message.go`: `TableName` is removed; `DefaultTableName` is the table a store left unconfigured reads and writes, `Store.TableName()` the table one store binds.
- **Breaking** — `service_resolver.go`: `RegisterStoreService`, `RegisterRelayService` and the `ServiceRegistrar` interface they took are removed; the module is the door that registers the store and the relay.
- **Breaking** — `relay.go`: `RelayConfig.LockReleaseTimeout` is removed; the lease is released on a context detached from the run, the locker bounding its own release.

### Added

- `module.go`: `ModuleConfig.StoreBuiltAtBoot` builds `service.outbox.store` inside `Boot`, under the boot runtime, so a factory ensuring the schema does it before the first request, and `ModuleConfig.StoreBootFailure` is its boot failure mode, `BootFailureWarns` when left out; a boot mode with no `Store`, and a failure mode on a store not built at boot, are refused at registration naming the field and what it requires.
- `StoreMustFromRuntime(runtimeInstance)`, the store read through the runtime's scope under its context, for code that holds a runtime; a nil runtime is refused. `StoreMustFromResolver` stays the door of a provider.
- **Breaking** — `service_resolver.go`: `StoreMustFromContainer` and `RelayMustFromContainer` are removed, their `…FromResolver` forms taking the container as they take a scope.
- This major includes every change of the third major up to v3.2.0; that history is in the third major's changelog, and the third-major fixes released after it are listed below as carried.
- `relay.go`, `relay_config.go`: `RelayConfig.LockReleaseTimeout` bounds the lease release and `RelayConfig.ResolutionTimeout` one resolution write, each on its detached context, 5s when left out as the constants were, at least 1ms, unlimited refused.

### Changed

- **Breaking** — `relay_command.go`: `melody:outbox:relay --interval` and `--idle-backoff`, named by `RelayIntervalFlagName` and `RelayIdleBackoffFlagName`, are duration flags of the framework's `clicontract.DurationFlag`, a value that is not a go duration or not positive refused by the flag parse before the run, naming the flag, and an empty value refused where it read as left out; left out, the interval is 1s and the idle backoff the interval, as before. See the framework's `UPGRADE.md`.
- `relay.go`: the default lock name reads the namespace through the framework's `config.NamespaceFromRuntime`, so a configuration resolved as a typed nil reads `melody` as an absent one does.
- **Breaking** — `store.go`: `NewStore(database, codec, config)` takes a `StoreConfig`: `TableName`, `DefaultTableName` when left out, a plain identifier refused naming `StoreConfig.TableName`, bound in every query; `Headers`, a `messagebus.HeaderLimitsConfig` bounding one enqueue. A nil database or codec is refused naming the argument.
- **Breaking** — `store.go`, `repository.go`: `Enqueue(ctx, executor, message, options)` takes `EnqueueOptions{Headers, Transport}`, the headers judged by `messagebus.ValidateHeaders` and stored as a JSON object in the new `headers` column, the destination in the new `transport` column, both NULL when left out; `Repository.ClaimDueMessages` takes `ClaimOptions{Transport}` and claims the rows of that name alone, an empty name the rows that name none; `Pending` carries `Headers` and `Transport`; a malformed transport name is refused naming its field.
- **Breaking** — `store.go`: `EnsureSchema(runtimeInstance)` takes the runtime in place of a context, a nil runtime refused naming `outbox.Store.EnsureSchema`, and adds `headers` and `transport` to an older table as it adds `sent_at`.
- **Breaking** — `relay.go`, `relay_config.go`: `RelayConfig.TransportName` names the destination a relay drains, a relay claiming only its rows and the relay that names none only the rows that name none; the relay publishes a row's headers as a `messagebus.HeadersStamp` beside its message id, and a row whose stored headers do not decode is dead-lettered with `headers: ` before its error. See the framework's `UPGRADE.md`.
- **Breaking** — `relay.go`, `relay_config.go`: the relay's default lock name is `<namespace>:outbox:relay`, the application namespace read at each run from the runtime's configuration, `melody:outbox:relay` under the default namespace or with no configuration; a `RelayConfig.LockName` set is used verbatim. See the framework's `UPGRADE.md`.
- **Breaking** — `relay.go`: `NewRelay(repository, transport, codec, config)` takes the repository, the transport and the codec positionally, a nil one refused with the same message and its context naming `argument`; they leave `RelayConfig`.
- **Breaking** — `store.go`, `repository.go`: the table gains `sent_at`, the send time `MarkSent` records, and `PruneSent` judges `PruneSentOptions.SentBefore` against it, where it judged the enqueue time `created_at`; a sent row with no send time is never pruned. `EnsureSchema` adds the column to a table created without it, `TIMESTAMPTZ` on PostgreSQL and `DATETIME` on MySQL; a table managed by migrations is altered before the new binary is deployed, since `Enqueue` and `ClaimDueMessages` name the column, see `UPGRADE.md`.

- **Breaking** — `repository.go`, `store.go`, `lazy.go`, `relay.go`: every door of `Repository` takes the runtime it runs under first, a nil runtime, a typed nil and one carrying no context refused with "the runtime is nil or carries no context", and the contract gains `ReleaseClaims(runtime, ids, claimToken)`, an empty token refused, `RequeueDead(runtime, RequeueDeadOptions{Ids, Limit})`, more `Ids` than the limit refused, and `PruneSent(runtime, PruneSentOptions{SentBefore, Limit})`, a zero `SentBefore` refused; the relay releases the rows after the one a failed batch stopped at, that row keeping its claim until `VisibilityTimeout`, a failed release logged. See `UPGRADE.md`.
- `relay.go`: a locker refusing the relay's lock at `CreateLock` is the lease acquisition's error, `lockcontract.Locker` answering `(Lock, error)`, and one answering neither a lock nor an error is refused through `lock.CreateLock`.
- `lazy.go`: the lazy repository, whose doors take a context, resolves the store under its resolver's own runtime over that context, `runtime.WithContext(resolver.Runtime(), ctx)`, and refuses a nil context as an error.
- **Breaking** with the framework: the fourth major's runtime is read from `v4/container/contract` and built through `v4/container/runtime`, a runtime resolving through its scope only; `runtime.New` and `Runtime.Container()` are gone. See the framework's `UPGRADE.md`.
- **Breaking** — `relay.go`, `relay_config.go`, `repository.go`, `store.go`, `lazy.go`: a send the transport marks with `exception.MarkInfrastructureFailure` is judged against the next row of the batch, sent once as a probe: delivered, the failed row is charged as before; failed too or absent, the row goes back uncharged through the new `Repository.RescheduleUncharged`, its attempts unchanged and the claim's delivery attempt taken back, pending again after `RelayConfig.UnavailableBackoff` (15s, growing by `BackoffFactor` per consecutive outage pass) capped by `UnavailableBackoffMax` (1m), a value below its minimum or a backoff above its cap refused naming the field; one ERROR record when an outage starts, written by the first hand-back that reaches the store, and one INFO when a row is delivered again, where every failed send charged the row an attempt and a broker outage longer than the backoff schedule dead-lettered every pending row. A send the run's cancellation cuts hands its row back due at once with its attempts unchanged, counting no outage, and is reported as the run's error. `RescheduleUncharged` never takes the delivery count below zero. A `Repository` of the application's own implements the new door.
- **Breaking** — `lazy.go`, `relay_command.go`: `NewLazyRepository`, built during boot over the container with no `service.outbox.store` registered, fails the framework's boot, naming the line that called it, where they failed at their first use; the code is unchanged, the framework records every `container.Lazy` handle and checks it at the end of `Boot`.
- **Behavioural change** — `module.go`: `RegisterServices` refuses a `RelayCommand` configuration with no `Relay`, naming `ModuleConfig.RelayCommand`, where the configuration was read by nothing and no command was registered.
- **Breaking** — `service_resolver.go`: `StoreMustFromResolver` and `RelayMustFromResolver` take a `context.Context` first, the fourth major's resolver form; the lazy repository resolves the store under the context of the call that reaches it.
- **Breaking** — `relay.go`, `relay_config.go`: `RelayConfig`'s `LockTtl`, `VisibilityTimeout`, `InitialBackoff` and `MaxBackoff` are `bound.Duration` and `BatchSize`, `MaxAttempts` and `MaxDeliveryAttempts` `bound.Count`, resolved once at `NewRelay`, a value outside its rule panicking naming the field, a zero or an unlimited one included where a non-positive value took the default; `LockTtl` and `VisibilityTimeout` are at least 1s, the backoffs at least 1ms, the counts at least 1. `BatchSize` above 100000 is refused where it was clamped, `MaxDeliveryAttempts` at or below `MaxAttempts` is refused naming both where it was raised to twice `MaxAttempts`, an `InitialBackoff` above `MaxBackoff` is refused naming both where every delay was held at the cap, and a `BackoffFactor` below 1 is refused where it took 2, and a NaN one where it was admitted. A nil `Repository`, `Transport` or `Codec` names the field.
- **Breaking** — `store.go`: `ClaimDueMessages` refuses a limit above 100000 where it cut it to that ceiling, the answer the relay's `BatchSize` gets.
- **Breaking** — `relay_command.go`, `module.go`: `NewRelayCommand(config RelayCommandConfig)` is the one constructor of the relay command, resolving `service.outbox.relay` from the run's scope at the first batch, under the run's runtime and kind, kept for the run, a failed resolution backed off and retried and a nil yield an error; `NewRelayCommandFromResolver` and the relay argument are removed. The config's `MaxErrorBackoff` caps the doubling delay between failed batches, one minute when left out as the constant was, at least 1ms, unlimited refused; `ModuleConfig.RelayCommand` carries it to the command the module registers.
- **Breaking** — `module.go`: `ModuleConfig.Store` and `ModuleConfig.Relay` are the providers of `service.outbox.store` and `service.outbox.relay`, `func(resolver containercontract.Resolver) (*Store, error)` and `(*Relay, error)`, run at first resolution; the prebuilt fields, `StoreFactory`, `RelayFactory` and the two "set exactly one" refusals are removed, and a nil `Relay` registers no relay and no command. See `UPGRADE.md`.
- `relay.go`: the relay hands the resolved `RelayConfig.LockTtl` to the `Locker` as a `bound.Duration`, the fourth major's lock contract form.
- `relay.go`: the relay stamps the message id through `messagebus.NewEnvelope(message, []messagebuscontract.Stamp{...})`, the fourth major's envelope form.
- `relay.go` and `relay_command.go`: the log records are built through `exception.LogContext(err, exception.LogContextConfig{...})`, the fourth major's form, which takes the extra context in a struct; nothing of this module's own surface changes.
- **Breaking** — `relay.go`, `relay_config.go`, `relay_command.go`: `RelayConfig.InitialBackoff`, `MaxBackoff` and `BackoffFactor` are one `RelayConfig.Backoff bound.Backoff` (15s, 10m, 2); `RelayConfig.UnavailableBackoff` and `UnavailableBackoffMax` are one `RelayConfig.UnavailableBackoff bound.Backoff` (15s, 1m) with its own `Factor` (2), where the outage wait borrowed `BackoffFactor`; `RelayCommandConfig.MaxErrorBackoff` is `RelayCommandConfig.ErrorBackoff bound.Backoff`, its `Initial` left out the run's `--interval` capped at its `Max` (1m), so a poll interval above the cap starts the error backoff at the cap; every refusal names `<Struct>.<Field>.Initial`, `.Max` or `.Factor`, and the relay, outage and command waits are `ResolvedBackoff.Delay`, the sequences on the defaults unchanged.

### Fixed

- `relay.go`: the default lock of a relay naming a `TransportName` is `<namespace>:outbox:relay:<transport>`, so the relays of two transport names over one locker drain side by side, where both took `<namespace>:outbox:relay` and one returned having published nothing while the other drained; the relay that names none keeps `<namespace>:outbox:relay`.
- `relay.go`, `message.go`, `store.go`: a row of a table other than `DefaultTableName` publishes under the message id `melody-outbox-<table>-<id>`, `Pending.Table` carrying the table the store claimed it from, so the rows of two tables feeding one transport no longer share `melody-outbox-<id>` and a deduplicating consumer no longer drops the second; a row of the default table keeps `melody-outbox-<id>`.
- **Behavioural change** — `relay.go` — carried from the third major (v3.2.1): a failed send ends the batch. The failed row alone is charged an attempt, and the rows the batch had not reached are handed back pending with their attempts unchanged, available again when the failed row is tried again, their `last_error` naming the row whose failed send held them. Before, the batch went on and charged every claimed row an attempt on every pass, so a broker outage of about 66 minutes at the default settings dead-lettered every good message the relay claimed; a claim takes the lowest id first, so an outage now charges the first row of each claimed batch alone, pass after pass, and dead-letters one row of that batch per ~66 minutes, every poll that finds rows enqueued during the outage claiming a batch of its own. A contained send panic ends the batch the same way. A hold write that fails, or a cancellation of the run, ends the hold, the rows not handed back re-surfacing after
  `VisibilityTimeout`.
  Once the broker is back, the held rows wait out the failed row's current backoff, at most `MaxBackoff`, and a message the broker refuses holds the rows behind it for its own backoff each time it is due. When the failed send dead-letters its row, the held rows still wait the backoff that row would have had, `MaxBackoff` at the default settings.
- `relay.go` — carried from the third major (v3.2.1): a failed send writes one `outbox message send failed` ERROR record with the row's id, its type, the attempt it was charged, `MaxAttempts`, when it is tried again or that it was dead-lettered, and the transport's cause, written once the row's reschedule or dead-letter write succeeded, where a rescheduled row left no trace in the process log, `RunOnce` answering no error for it and the cause reaching only `last_error`; the batch ends at the failed send, so a pass writes at most one such record, and a contained send panic keeps its own `outbox delivery panicked` record instead.
- relay: a batch failure whose `Unwrap` chain reaches itself no longer holds the relay command that classifies it during a shutdown.

### Security

- `go.mod`: `golang.org/x/crypto` v0.52.0 and `go.opentelemetry.io/otel` v1.41.0, past the versions the advisories name. None of them reached code this module calls.
