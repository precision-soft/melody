## [v3.6.2] - 2026-10-21 - Ended-Context Cause on the Audit Close

### Fixed

- `audit/async_storage.go` — the close that abandons a save which ignored its cancellation says so as it happened when the close deadline, not the second drain grace, ended the wait: the answer reads that the deadline cut the grace short and carries `waited`, how long the save was actually given, beside the planned `grace`, where it read "after a second drain grace" and reported only the grace it never had
- `audit/async_storage.go` — `AsyncStorage.CloseWithContext` reached with a context that had already ended carries that context's error as the cause of its answer: a deadline passed before the close began is read off the answer as `context.DeadlineExceeded`, as a deadline reached during a stretch is, where the answer carried no cause; and a context its caller cancelled before the close began is answered as the caller's withdrawal with `context.Canceled` as its cause, where it read that the budget was already spent

## [v3.6.1] - 2026-10-20 - Deadline-Ended Audit Close Read as the Spent Budget

### Fixed

- `audit/async_storage.go` — `AsyncStorage.CloseWithContext` reads a deadline reached during one of its two stretches as the budget running out, never as its caller cancelling the close: reached while it waited for a save that ignored its cancellation, the close answers that it abandoned the save, the answer the stretch's own timer gives; reached during the drain, or with the drain's timer, it answers that the budget was already spent, with no grace left to observe a reaction, where a deadline landing with the drain's timer on a stalled machine reported a save that ignored a cancellation it was given no time to react to. Where a stretch overran the margin kept back before the deadline, as a loaded machine does, both were answered "cancelled by its caller", a withdrawal nobody made, measured 21 times in 30 under load with the race detector; a cancellation during a stretch is still answered as the caller's, and every answer the deadline ends carries `context.DeadlineExceeded` as its
  cause, as before

## [v3.6.0] - 2026-10-19 - Transaction-Riding Audit, Replica Retry Interval, Routed Diagnostics, Sealed Encrypted Columns and Bounded Teardown

### Added

- `audit.TransactionRider`, the question `audit.AsyncStorage` asks its delegate about a bound transaction, which `BunStorage` answers; a `Storage` decorating a `BunStorage` for metrics, tracing or retries forwards the question and rides the transaction as the bare one does, a decorator that does not answer being queued.
- `NewReadWriteSplitterWithOptions`, `ReadWriteSplitterOption` and `WithReplicaRetryInterval`: the splitter remembers an unreachable replica for a retry interval, five seconds by default, reading the primary meanwhile without dialling the replica, and journals the move once each way, a warning when reads move to the primary and an info when the replica takes them back, where every read paid the full connect timeout and the primary's reads left no record; `NewReadWriteSplitter` keeps its signature and the default.
- `ManagerRegistry.HasProviderDefinition(name)` answers whether a definition is registered under the name without opening anything, the question `db:create` of the `migrate` module asks so a misspelt `--manager` is refused where it is typed rather than at the first `db:migrate`.
- `ManagerRegistry.CloseWithContext(ctx)`, `audit.AsyncStorage.CloseWithContext(ctx)` and `audit.Recorder.CloseWithContext(ctx)`, the door the container's ordered teardown prefers: the registry's wait for opens in flight ends with the caller's deadline and counts the opens it stopped waiting for, an open that had ended never among them, and the async storage's two drain graces become halves of what the deadline leaves, a cancellation of the caller's context ending either stretch, where `WithCancel` was read once at entry; `Close()` keeps the unbounded wait and the package graces.
- `encrypt.EncryptedString.UnmarshalJSON`, `EncryptedDeterministicString.UnmarshalJSON`, `EncryptedStringFor[R].UnmarshalJSON` and `EncryptedDeterministicStringFor[R].UnmarshalJSON`, the read side of the redacting `MarshalJSON`: a plaintext string decodes as itself, a json null leaves the value untouched and the redaction placeholder is refused, where the round trip sealed `<redacted>` over the secret (see *Changed*).
- `encrypt.EncryptedString.Format`, `EncryptedDeterministicString.Format`, `EncryptedStringFor[R].Format` and `EncryptedDeterministicStringFor[R].Format` render the redaction placeholder for every verb that reaches `Format`, where `%d`, `%o`, `%b`, `%c` and `%U` reach neither `Stringer` nor `GoStringer` and printed the plaintext through the badverb form (`%!d(encrypt.EncryptedString=<plaintext>)`), the one channel `String`, `GoString`, `LogValue` and `MarshalJSON` left open — the `fmt.Formatter` redaction `StaticKeyProvider` carries; `%p` and `%w` never reach it (`fmt` prints the operand by reflection first, which `go vet` refuses in a literal format and a dynamic format slips past), nor does an unexported field rendered with `%v`/`%+v`.
- `ErrDatabaseUnreachable` and `DatabaseUnreachable(openErr)`: the class of an open failure a provider classified as transient and could not get past — the one outage `ReadWriteSplitter.Reader` absorbs — and the door a provider files it through, under the provider's exception, so `errors.Is` answers the class and `errors.As` still reaches the driver failure; the `pgsql` and `mysql` providers file the spent retry budget and the retry-less open of an unreachable host, never a refusal given by name.
- `audit.ErrAsyncStorageQueueFull` and `audit.ErrAsyncStorageClosed`, the sentinels an `AsyncStorage.Save` wraps when the buffer was full or the storage closed, so `errors.Is` tells a lost audit record from a delegate failure.
- `ManagerRegistry.SetLogger` replaces the logger a registry reports through and takes bun's diagnostic channel with it, for a registry wired before the application logger exists and built on the emergency logger; a nil or typed-nil logger is refused with `ErrLoggerIsRequired`, and a closed registry answers `ErrManagerRegistryClosed` and changes nothing.
- `ManagerRegistry.CloseMigrationDatabase(name)` ends the dedicated migration connection for one definition and forgets it, so the next `MigrationDatabase` opens a fresh one, where a boot-time migration kept a deadline-less connection for the process's life; an empty name selects the default definition, a name with no migration connection is no error, and a closed registry refuses it.
- `ResetDiagnostics` hands bun's diagnostic channel back to standard error: what a teardown calls while the routed logger is alive, and the door of a process that hosts melody.
- `audit.NewRecorderOwningStorage` and `Recorder.Close`: a recorder built by hand over an `AsyncStorage` and registered alone ends, through `Close`, the storage's drain goroutine the teardown could never reach; the default `NewRecorderWithStorage` does NOT own the storage, which the container closes itself.
- `encrypt.EncryptedColumn`, the marker interface every encrypted column type implements, the generic instantiations included, so a consumer recognises an encrypted column by the interface rather than by type identity, each instantiation being a distinct `reflect.Type`.
- `ConnectionParameters.SafeContext` is pinned by its own mirror (host, port, database and user), its negative assertion scanning every value rather than looking for `password` alone, and the same file pins that `ConnectionParams` is still an **alias**, whose turning into a defined type would leave every in-tree build green while a provider outside the tree spelling it in the `Provider` signatures stopped matching.
- **Behavioural change** for anyone reading bun's warnings on standard error: `RouteDiagnostics` sends bun's own diagnostic channel to the application's journal, the mysql and pgsql providers calling it on their first open, so a declaration mistake — an unknown struct tag option, an unknown `on_update` or `on_delete` rule, a query with arguments and no placeholders — arrives as a warning record under `bun diagnostic` with the line in the context, the shape `logging.NewStandardErrorLogger` gives `net/http`; bun's logger is one variable per process, set once to a forwarder whose destination the latest routing replaces, a binary that never opens a database leaving the setting alone. The mysql dialect writes `can't discover MySQL version` through the **standard library's** logger, out of reach unless the application takes `log.SetOutput`; the mysql readme says how.
- `ContextOpener`, the optional capability of opening under a caller's context, and `NewManagerRegistryWithContext`, which binds the registry's lazy opens to a context, so a provider implementing it refuses an open already cancelled and has its retry sleeps watch the context, a shutdown honoured at every cancellable step; a nil context reads as `context.Background()`, as `NewManagerRegistry` does. `MigrationContextOpener` is what `ContextOpener` is to `Open` for the migration open, preferred by the registry whenever a provider that implements `MigrationProvider` implements it too.
- `MigrationProvider`, the optional capability of opening a connection tuned for migrations, answered by `ManagerRegistry.MigrationDatabase`: the same database with the request-sized deadlines lifted, opened once per definition and cached beside the request pool, never inside it, and closed on Close, where a DDL statement running past them was cut mid-statement with `invalid connection`; a provider without it keeps the ordinary pool, reported as not dedicated.

### Changed

- `go.mod` — requires `github.com/precision-soft/melody/v3` at `v3.14.0`, raised from `v3.6.0`, the lowest framework version this release builds against, and declares `go 1.25.0` as the framework does, raised from `go 1.24.0`; a module that requires this release is pulled up to those versions with it
- **Behavioural change** — `encrypt/encrypt_database_command.go`: `--batch` parses in base ten through `output.DecimalIntegerConfig`, `--batch=010` reading ten and `--batch=08` eight, where the engine's inferred base read eight and refused; a base prefix is refused as syntax.
- **Behavioural change**: `encrypt.NewStaticKeyProvider` panics at construction on a key of 32 zero bytes, with the key id, as for a key of the wrong length — the key of a buffer nobody wrote, which sealed every column under a guessable key; nothing else is judged, a key being the operator's, from `crypto/rand`.
- **Behavioural change**: decoding a json document that carries the redaction placeholder into an encrypted column type is refused by name with the column type, where `MarshalJSON` wrote `<redacted>`, `encoding/json` stored it and the next `Value()` sealed it over the secret; the new `UnmarshalJSON` (see *Added*) decodes any other string as plaintext and leaves the value on a json null.
- **Behavioural change**: `audit.AsyncStorage.Save` reports an entry the queue could not take, where it answered `nil` for one dropped on a full buffer or after `Close`: it dead-letters as before, attempts every entry of the call and returns the first refusal wrapping `ErrAsyncStorageQueueFull` or `ErrAsyncStorageClosed`, naming each dropped entry under `refused` with its `index` beside its entity, id and operation, a full queue being able to split a call; a `Recorder` skips its own dead-letter record only when the refusal names the recorder's own logger as the one the storage journaled through, so a storage left on the emergency logger is still journaled by the recorder. A `Tracker` is unaffected, its saves going through the delegate synchronously.
- **Behavioural change**: `audit.Change` marshals each side by PRESENCE rather than by emptiness, where under plain `omitempty` a transition to a zero value (`active` true→false) read like the one-sided shape of an insert or a delete: a present zero renders (`"new":false`), an absent side stays out, and a `Change` built by hand keeps the old reading.
- **Behavioural change**: the `bun` requirement moves to `v1.2.17`, the dialect and driver packages in lockstep (the dialects panic at init on a version mismatch): v1.2.16 swallowed the failure of a migration read from a `.sql` file, which `integrations/bunorm/migrate` answered with `[success]` and exit 0 over an unchanged schema.
- the bulk migrator reads STORED values with the read side of the cipher's asymmetry on both `mode=encrypt` branches, so a marker-shaped value that no longer decrypts stops the run naming the key rather than being re-sealed as plaintext, the write-path leniency staying with `Encrypt`; `Migrator.MigrateEncrypt` and `MigrateReencrypt` run their own column-capacity check, where only the CLI did and the programmatic caller met silent truncation, the `EnsureColumnCapacity*` doors remaining.
- encrypt: the AES-GCM value and the deterministic nonce's sub-key are built once per key, not per call — the AEAD was forty per cent of a `Decrypt`, the path of every `Scan`, paid twice by the deterministic path and once per active key by `CiphertextCandidates`; `Decrypt`, `EncryptDeterministic` and the three-key `CiphertextCandidates` roughly halve. `KeyProvider` being public, the key bytes are compared on every read, so a provider answering new bytes under the same id is honoured at the next call.

  fallback entry states the past v3.5.0 had, the diagnostic routing entry says that the latest routing wins, and the entry narrating an intermediate list of permanent failures is removed.

### Security

- encrypt: **Behavioural change**: the column types `EncryptedString`, `EncryptedStringFor`, `EncryptedDeterministicString` and `EncryptedDeterministicStringFor` seal every application value, even one that already is a seal of the cipher, where they wrote through `Encrypt`'s pass-through of a value authenticating as its own seal: a column an application fills from a request and later shows to the same user decrypted any seal of the compartment handed to it as data — another row's, another column's or another table's. Such a value is now sealed as data and read back as the value it was; `Encrypt` keeps its pass-through for its own callers, while the `Migrator` seals through the column door and inspects nothing it re-writes, and an application that copied raw sealed bytes between columns through a column type now stores them sealed once more — copying them belongs to the `Migrator` or to SQL.
- encrypt: **Behavioural change**: over a `Cipher` implemented outside the package — a wrapper over `NewCipher` for metrics or tracing included — the column types refuse a value carrying the encryption marker with an error at `Value()`, since the wrapper's doors pass a seal through and the column would store it bare and read back the other row's secret; an application wrapping the cipher installs `NewCipher` directly or keeps the wrapper off the write path. A forwarding seam for wrappers is deferred to the next major.
- encrypt: **Behavioural change**: the `Migrator` decides on the stored value alone and seals the decrypted value as data, under the target key or the key the value carries, where a rotation (`mode=reencrypt`), a re-run of `mode=encrypt` over a deterministic column and a `mode=decrypt` run turned a seal stored as data back into a bare seal, which the column read back as the other row's secret; `mode=decrypt` stops on a row whose decrypted value is itself a seal, naming the row and leaving it sealed, since written bare it would be read as a seal by a column type that still decrypts.
- encrypt: **Behavioural change**: with a `Cipher` implemented outside the package, a rotation or a deterministic `mode=encrypt` stops on a row whose decrypted value is a seal instead of handing it to the cipher's own doors, which may pass it through.

## [v3.2.0] - 2026-07-11 - Named Cipher Compartments and Manager Registry Hardening

### Added

- `encrypt/cipher_registry.go`, `encrypt/encrypted_string_for.go`, `encrypt/deterministic_for.go` — named cipher compartments for multi-context binaries. `UseCipher` was process-global with one current write key, so two DB contexts with separate key sets could not keep separate current keys — consolidating apps meant merging key maps and losing a key compartment that existed when the binaries were separate. Now each compartment installs its own cipher with `UseCipherNamed(name, cipher)` and binds columns through the type system: a zero-size marker implementing `CipherRef` (`CipherName() string`) parameterizes the new generic column types `EncryptedStringFor[R]` / `EncryptedDeterministicStringFor[R]` — the only channel available, since `database/sql` gives `Value()`/`Scan()` no context. Compartments are truly isolated (the "crm" cipher can never decrypt a "billing" ciphertext — unlike per-column key selection over a merged provider, where either context can read the other's rows), key
  rotation inside a compartment keeps working through the key id embedded in the ciphertext, and the generic types replicate the full redaction surface (`String`/`LogValue`/`MarshalJSON`). `UseCipher` and the existing column types are unchanged — the default cipher is now simply the registry's reserved unnamed entry. Per-`Manager` cipher binding was rejected: a `driver.Valuer` has no manager context, and bun query hooks would miss raw SQL paths.
- `encrypt/module.go`, `encrypt/encrypt_database_command.go` — the bulk command module composes with compartments: `ModuleConfig.Contexts []CommandContextConfig{Name, Database, Cipher}` registers one `melody:encrypt:database:<name>` command per compartment (via the new `NewEncryptDatabaseCommandWithName`), while the legacy `{Database, Cipher}` fields keep the unsuffixed command.

### Fixed

- `manager_registry.go` — a panic inside `Provider.Open` no longer wedges every later caller. `Manager` opens outside the registry lock and coalesces concurrent callers of the same name onto one open, so when a mis-parameterised provider panicked (the pgsql/mysql providers resolve parameters with `MustGet`) the deletion of the in-flight entry and the close of its done channel were skipped, and a recovered panic left every subsequent `Manager(name)` blocked forever on the never-closed channel. The open is now wrapped so the slot is always cleared and waiters are released with an error, while the panic still propagates to the direct caller.
- `manager_registry.go` — a database opened while `Close` is running is no longer leaked. `Close` drains the manager map without an open still in flight, so an open completing afterwards memoised its `*bun.DB` into a registry nobody would drain again; `Manager` now closes the freshly opened database and returns `ErrManagerRegistryClosed` when it finds the registry closed on completion.
- `encrypt/key_provider.go` — `StaticKeyProvider` redacts its keys under `fmt`. The `%#v` and `%v` verbs walk unexported fields, so a provider that reached a debug log — or an error context formatted later — printed every AES master key as raw bytes. This is the redaction class the encrypted column types already close, applied to the material those columns are protected with.
- `encrypt/encrypted_string.go`, `encrypt/deterministic.go`, `encrypt/encrypted_string_for.go`, `encrypt/deterministic_for.go` — the encrypted column types now redact under the `%#v` verb too. `fmt` reaches for `GoStringer` there and, finding none, printed the underlying string literal, so a struct dumped with `%#v` into a log line or a test failure carried the plaintext — while `%v`, `String()`, `LogValue()` and `MarshalJSON()` all redacted correctly.
- `encrypt/encrypted_string_for.go` — a `CipherRef` whose `CipherName()` is empty is now rejected instead of resolving the default cipher. The empty name is the default cipher's reserved registry entry, so a marker that returned it silently handed a compartment-bound column the default key — exactly the cross-compartment read the marker type exists to prevent.
- `encrypt/key_provider.go` — `StaticKeyProvider` implements `fmt.Formatter`, so the numeric verbs (`%d`, `%o`, `%b`, `%c`, `%U`) can no longer bypass its redaction and print the raw AES-256 master key bytes. The `%#v`/`%v` redaction added earlier left these verbs, which walk the underlying byte slice directly, as an open channel.
- `encrypt/cipher.go` — a client-supplied marker-shaped string naming an unknown key id is sealed under the current key by `Encrypt` rather than stored verbatim, so a row can no longer be poisoned into a permanent key-not-found on a later `Scan` or re-encrypt/decrypt run. Pass-through is granted only to a value that decrypts under a key currently in the key set (a retired key stays in the set until re-encryption completes).
- `manager_registry.go` — `ManagerRegistry` no longer holds its internal lock across `Provider.Open`. A slow or unreachable database otherwise serialized `Manager`/`Database`/`Close` for every other database and stalled shutdown; concurrent openers of the same manager now coalesce onto one open, and a failed open is not cached.

### Added

- `v3/encrypt/` — transparent column encryption at rest with AES-256-GCM, designed as a drop-in over plaintext tables. `Cipher` is an interface (`NewCipher(KeyProvider)`) with a process-wide `UseCipher`; encrypted values carry a marker `<ENC>\0gcm1\0<keyId>:<base64(nonce||ciphertext)>` so reads can tell ciphertext from plaintext: `Decrypt` passes an unmarked legacy value through unchanged (existing rows read correctly and are encrypted on the next write) and `Encrypt` is idempotent on an already-marked value (double-encryption guard). `EncryptedString` (a `driver.Valuer`/`sql.Scanner`) **fails closed** — `Value`/`Scan` error if no cipher is configured rather than silently persisting plaintext — and masks its plaintext in `fmt`/`slog`/error output (`String`/`LogValue` return `<redacted>`). Searchable encryption: `EncryptDeterministic`

### Fixed

- `v3/encrypt/` — the `Encrypt*` already-encrypted pass-through no longer trusts the `<ENC>\0gcm1\0` marker shape alone: a marked value passes through only when it actually decrypts under its (known) key, so a *plaintext* that merely looks like ciphertext is sealed normally instead of being stored raw — where it poisoned every later `Scan`/`Decrypt` with a GCM authentication failure. A marked value carrying an **unknown** key id still passes through unchanged, so a value sealed under a retired key is never destroyed by double encryption, and the idempotent re-encrypt contract is preserved (genuine ciphertext still passes through). Regression coverage in `v3/encrypt/cipher_test.go`.
- `v3/audit/` — an `audit:"redact"` tag placed on an embedded (anonymous) struct field is now honored: the promoted inner fields are redacted as a group. `collectChanges` recursed into an auditable embedded struct without carrying the embed field's `redact` tag (it inspected only the embed's `bun` tag and element type), so the tag was dropped and each promoted field's plaintext was written to the audit `changes` column. The recursion now threads a force-redact flag set from the embed field's `audit:"redact"` tag, complementing the per-field redaction already applied to named fields.

The map header is now added to the cycle-detection set before its keys/values are walked, matching the existing pointer guard (the sibling self-referential **slice** case is guarded separately below).
- `v3/audit/` — `ChangeSet` now recurses into promoted (exported, anonymous) embedded structs other than `bun.BaseModel`, so an embedded struct's columns are captured in the diff instead of being silently dropped. Table names passed to `NewRegistry`/`Registry.Register` are validated against a strict SQL-identifier pattern (panic on violation) since they flow unquoted through `ModelTableExpr` into DDL/DML.
- `v3/encrypt/` — documented that deterministic encryption yields byte-identical ciphertext for equal plaintext across every deterministic column and table under the same key (cross-column/cross-table equality is observable), not just within one column.
- `v3/encrypt/` — `EncryptedString.Value` now returns the ciphertext as `[]byte` rather than `string`, so the `\x00` bytes in the `<ENC>\0gcm1\0…` marker survive persistence: bun inlines a `driver.Valuer` string into the MySQL statement text and its string formatter drops embedded NUL bytes, which silently corrupted the marker so a subsequent read no longer recognized the value as ciphertext and returned it unencrypted (encryption-at-rest was a no-op for the `EncryptedString` column type on bun + MySQL). Returning `[]byte` makes bun emit an `X'…'` binary literal that preserves every byte; `Scan` already accepts both `string` and `[]byte`, so reads are unaffected.
- `v3/encrypt/` — `EncryptedDeterministicString.Value` carried the identical NUL-drop defect and now also returns `[]byte`, and `Cipher.CiphertextCandidates` now returns `[][]byte` instead of `[]string` for the same reason: the candidates form the right-hand side of a `WHERE col IN (…)` lookup and were likewise NUL-stripped when bun inlined them as strings, which would have broken every deterministic equality lookup once the column stored intact binary ciphertext. As `[][]byte` each candidate is emitted as an `X'…'` binary literal, so the lookup matches the stored value byte-for-byte. The README lookup example is updated accordingly.
- `v3/audit/` — `ChangeSet` now also masks `EncryptedDeterministicString` columns as `<redacted>` (previously only `EncryptedString` was masked), so the low-entropy lookup PII these columns hold — e.g. an email used for searchable encryption — no longer leaks into the audit trail in cleartext. The promoted-embed walk excludes the deterministic type as well.
- `v3/audit/` — a pointer-typed encrypted column (`*EncryptedString`/`*EncryptedDeterministicString`, the natural shape for a nullable encrypted field) is now redacted the same as the value-typed form. `isRedactedField` compared the field type by exact value type only, so a pointer field did not match and — because the encrypted types at the time defined no `MarshalJSON` (one is added below) — its plaintext was serialized into the audit `changes` column (and the dead-letter log). The matcher now dereferences pointer types before comparing.
- `v3/encrypt/` — `Migrator.MigrateEncrypt` and the `melody:encrypt:database` command now honor deterministic encryption. `MigrateEncrypt` consults `TableSpec.Deterministic` (it previously always wrote random-nonce ciphertext, so bulk-encrypting an existing column mapped to `EncryptedDeterministicString` produced values that `CiphertextCandidates` equality lookups could never match — the data was present but silently unsearchable), and the command gains a `--deterministic` flag to drive it. `MigrateReencrypt` no longer takes the same-key fast-path skip when `TableSpec.Deterministic` is set: the wire format cannot distinguish a random-nonce from a deterministic ciphertext, so converting an existing random-nonce column to a searchable one under the same key id now actually rewrites the rows instead of skipping them. Deterministic re-encryption is idempotent (stable ciphertext), so rows already stored in deterministic form are left unchanged.
- `v3/encrypt/` + `v3/audit/` — `EncryptedString` and `EncryptedDeterministicString` now define a redacting `MarshalJSON` (returning `<redacted>`, consistent with their `String`/`LogValue` masking). `ChangeSet`'s `isRedactedField` only inspects a column's own top-level type, so an encrypted value nested inside a **named** (non-embedded) struct field, a slice, a map, or an array was emitted whole and its plaintext was serialized into the audit `changes` column. Redacting at the JSON layer closes the leak at any nesting depth, complementing the field-level matcher above; database storage is unaffected because the encrypted form is produced by `Value` (a `driver.Valuer`), not by JSON.
- `v3/audit/` — a plain `audit:"redact"`-tagged column nested inside a **named** (non-embedded) struct, slice, array, map, or pointer-to-struct field is now redacted too. `ChangeSet` captures such a composite field whole and `isRedactedField` inspected only the column's own top-level tag/type, so a `redact` tag one level down had no effect and its plaintext was serialized into the `changes` column (encrypted types were already safe via their `MarshalJSON`, but a plain `redact` tag has no serialization guard). The matcher now scans the field's type tree and redacts the whole containing field when any member carries `redact`.
- `v3/encrypt/` — `Migrator.MigrateReencrypt` in **randomized** mode (`TableSpec.Deterministic = false`) now rewrites a value that is deterministically encrypted under the target key instead of skipping it. The same-key fast-path skip could not tell a deterministic ciphertext from a random-nonce one (the wire format is identical), so re-encrypting a searchable column to random nonces under the same key id silently left it deterministic — and still equality-searchable. The transform now re-derives the deterministic ciphertext to detect this case and rewrites it with a random nonce, while still skipping a genuinely random-nonce value to avoid pointless churn.
- `v3/audit/` — `AsyncStorage.WithLogger` no longer races the background drain goroutine. The goroutine starts in the constructor, so attaching a logger via the builder while a failing save called `deadLetter` was an unsynchronised read/write of the `logger` field; it is now guarded by a dedicated mutex (separate from the queue mutex to avoid lock nesting in the `Save` → `deadLetter` path).
- `v3/audit/` — a `audit:"redact"`-tagged member reached through an `interface{}`/`any` column is now redacted too. `ChangeSet` walks a field's **static** type tree to find a nested `redact` tag, but an interface field hides its concrete type, so a redact-tagged struct assigned into an `any` column was serialized whole and leaked its plaintext into the `changes` column (encrypted types stay safe via their `MarshalJSON`, but a plain `redact` tag has no serialization guard). The matcher now also inspects the **dynamic** type of the captured value, complementing the static walk that already covers concretely-typed composite fields.
- `v3/audit/` — redaction detection now also inspects **map keys**, not only map values. A `map[encrypt.EncryptedString]V` (or a map keyed by any redact-tagged type) leaked its key plaintext into the `changes` column because `encoding/json` serializes a string-kind map key directly from its underlying value, bypassing the key type's `MarshalJSON`. Both the static type walk and the dynamic value walk now follow the map key as well as the value, so the whole containing field is redacted when a sensitive type or `redact` tag appears in either position.
- `v3/audit/` — the dynamic-type redaction above now descends through **nested** interface values, not just an interface used as the column itself. The previous check ran a static type walk on `reflect.TypeOf(value)`, which still could not see a `redact`-tagged struct carried by an `any` field one level deeper (`struct{ Inner any }`) or held as an interface value inside a map/slice (`map[string]any`), so such plaintext still leaked into the `changes` column. Redaction detection now walks the captured **value**, following interface, pointer, slice/array element, and map value boundaries to their concrete types, so a `redact` tag (or an encrypted column type) is honored at any depth regardless of interface indirection.
- `v3/audit/` — the value walk above no longer skips a `redact`-tagged (or encrypted) value reached through a **second sibling of the same struct type** whose sensitive content is only reachable via an `interface{}`/`any` field. The walk deduplicated visited struct **types** to break cycles, so once one instance of a type surfaced no redact marker (its interface field happened to hold a non-sensitive value) a later same-typed sibling — whose interface field did hold a redact-tagged struct — was short-circuited without inspecting its fields, leaking the plaintext into the `changes` column. Cycle detection now tracks visited **pointers** rather than types, so each distinct value of a repeated type is inspected on its own while genuine pointer cycles still terminate.
- `v3/audit/` — the redact-tag value scan no longer overflows the stack on a self-referential **slice** reached through an interface element (`d := []any{nil}; d[0] = d`). The map case recorded its header in the cycle set but the slice case did not — and a slice can self-reference through an `any` element with no pointer node for the deref loop to catch — so such a slice recursed forever and crashed the process. The `reflect.Slice` case now records the slice header before walking its elements, mirroring the map guard (`reflect.Array`, which cannot self-reference, keeps the plain walk).
- `v3/audit/` — a bun many-to-many relation field (`bun:"m2m:join_table,…"`) is now skipped in the diff like other relations. `auditFieldName` skipped only `rel:`-prefixed tags, so a loaded `m2m:` relation slice was treated as a column and serialized into the `changes` column — audit-table bloat plus another entity's rows recorded under this entity's audit row, bypassing its per-entity `IgnoredFields`. The `m2m:` prefix is now skipped too.
- `v3/audit/` — `Tracker.Update` now reads the before-image with `SELECT … FOR UPDATE` (it already runs inside the audited transaction). The plain select read a snapshot under MySQL's default isolation, so two concurrent audited updates on the same row could both record `before = A` (`A→B` and `A→C`) and the audit chain no longer reconstructed the data history; the row lock serializes audited writers per row.
- `v3/encrypt/` — `Migrator` bulk encryption no longer silently reverts a concurrent application write. Each row's `UPDATE … SET col = encrypt(old)` was guarded only by `WHERE pk = ?`, so an application write that landed between the migrator's read and write was overwritten with the stale pre-image — a lost update on a feature designed for online adoption. The update is now additionally guarded on the value read for each column (`AND col = ?`), so a row that changed under the migrator matches zero rows and is re-encrypted on the next run instead of being clobbered.
- `v3/encrypt/` — `Migrator` bulk encryption no longer skips rows whose primary key is zero or negative. The keyset pager seeded the cursor with the empty string and always filtered `WHERE pk > ?`, which MySQL coerces to `pk > 0` on an integer key — so `id <= 0` rows (and a string key equal to `''`) were never visited while the command reported success. The first page is now unfiltered and only subsequent pages apply the keyset predicate.
