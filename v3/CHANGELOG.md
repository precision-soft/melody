# Changelog

All notable changes to `precision-soft/melody/v3` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- tooling: `.dev/validate/documentation.sh` checks the package documents against the code of every major, and now runs in the staged mode as well as the full one; it reads both bullet characters the documents use, every symbol a list entry names rather than only the first, methods as well as top-level declarations, the members of grouped `const`/`var` blocks, and packages at any depth, so a symbol documented for one major and shipped here can no longer go undocumented here

- security: `JwtConfig.RevocationEpochSkew` widens a revocation boundary by the worst clock skew between the node that mints and the node that revokes, and covers the imprecision of `iat` itself. `iat` is a whole-second numeric date, and nothing in the token says whether its issuer truncated or rounded up, so the instant a token claims can sit up to a second either side of when it was really minted: a token minted just before a boundary can read as minted after it. The allowance is where that is paid for, rather than in a hidden default — guessing the issuer's rounding would refuse tokens legitimately minted after a revocation. It defaults to zero; set it to at least a second on the json web token path, plus whatever the fleet's clock skew is
- security: a revocation stops being an enumeration. `security/contract.RevocationEpochStore` declares `RevokeBefore(userIdentifier, deviceIdentifier, instant)` and `RevocationEpoch(...)`, and `EpochRevocableTokenStore` composes it with `RevocableTokenStore`; both stores melody ships satisfy it. `DeleteByUser` walks an index with `SSCAN`, which does not promise to return a member added while the walk is in progress, so a token issued to a user after the walk passed the bucket it lands in survived the revocation — the window an account compromise is most likely to be exploited in. A boundary is one write instead: every later lookup refuses a token stamped before it, so a token issued during the revocation is refused by the same comparison as one issued an hour earlier, without anything having to find it first. A boundary can be published for a user or for one device of a user, and the one applied is the later of the two, so a user-wide revocation cannot be undone by a device-scoped one.
  `DeleteByUser` keeps its place as cleanup, and its documentation now says so rather than promising a guarantee it cannot give. **Breaking** is not needed: the epoch methods live on a new interface rather than on `RevocableTokenStore`, so a store written against an earlier release still compiles
- security: `security/contract.Claims` carries `IssuedAt` and `DeviceIdentifier`. The issue instant is what a revocation boundary is compared against and is stamped by the store on every write, ignoring any value the caller passed — claims read back through `Lookup` and put again would otherwise carry the original instant forward, so a token refreshed after a revocation would be born already refused. **Behavioural change**: a token written by an earlier release carries no issue instant, and the zero instant precedes every boundary, so such a token is refused as soon as a boundary exists for its user. Nothing else changes for it, and the cost falls only on the accounts somebody actually revoked
- security: `NewJwtTokenValidatorWithRevocationEpoch` makes a JSON web token revocable, which it has never been: the validator already parsed and verified `iat` and then discarded it, because `Claims` had nowhere to put it, so a signed and unexpired token could not be withdrawn by anything. It now carries the instant, reads a device from the claim named by `JwtConfig.DeviceClaim` when one is configured, and refuses a token issued before the boundary published for its subject. The wiring is opt-in because it makes verification stateful — one store read per request, no cache, and every token on that firewall refused while the store cannot answer; a deployment that cannot pay that keeps `NewJwtTokenValidator` and gives up revocation. The constructor forces `RejectFutureIssuedAt` on regardless of the configuration, since a token stamped ahead of the verifying process's clock would otherwise sit after every boundary ever published and outlive every revocation, silently

- example: the development stack serves all three example applications at once, each under a name that says which it is — `v1-example.`, `v2-example.` and `example.melody.localhost.precision-soft.com`. They are the same image with a different example directory, so nothing about the supervision is per-major, and none of them publishes a host port: they are reached through the load balancer, which keeps the per-developer host-port map out of it entirely. An end-to-end section tells them apart where a status code cannot — all three answer the same routes, and v1 and v2 are the same application on different majors — by writing through each vhost and reading which catalogue table the row landed in
- example: the example application is a working nomenclature rather than a set of routes that exist to be driven. Products, categories, currencies and users are kept through bunorm when the environment configured a database and in memory when it did not, so the application still boots on a machine with no containers; the listing is served from redis and dropped when a product changes; every write leaves a journal entry naming whoever made it; the write endpoints sit behind a per-address budget while the reads stay open; and the catalogue reading is refreshed on a schedule instead of being computed inside the request that finds a cold cache. The routes that only demonstrated a backend — `/integration/cache/`, `/integration/database/`, `/integration/ratelimit/` — are gone, and what they proved is now proven against the nomenclature itself, half of it read out of band by the end-to-end harness straight from redis and mysql
- example: every redis key and every table the example writes carries its major. The three example applications share one redis and one mysql in development, the cache holds gob-encoded entities whose wire format is keyed on the fully qualified type name — which carries the major — and the rate-limit counter is asserted on exactly by the end-to-end harness. Both example applications had been writing under the same prefix, so with the two of them running at once one would read entries it cannot decode and spend the other's budget; the comment above the constants had said so while the code did the opposite
- example: the schema is owned by one migration set in `v3/.example/migration/` — six mysql migrations, one per table: the four catalogue tables, the journal, and the two-factor enrollment table neither frozen major carries. Each repository used to create the table it read, and the enrollment table was created inline by the composition root, so the schema was spelled once per reader and nothing could roll it back, inspect it or report what had been applied. Two doors now run the same set: `migration.EnsureMigrated`, called at boot and again by every repository constructor before it seeds, and the `db:*` command family (`db:init`, `db:migrate`, `db:rollback`, `db:status`, `db:unlock`, `db:create`) the `bunorm/migrate` module registers. The set is applied under bun's migration lock with a bounded retry that names `db:unlock` when it gives up, and every statement is tolerant, because several processes of the example reach an empty volume at once. The framework's own tables are not in it: the outbox store and the audit registry each open their schema through the module that owns it
- example: the packages melody:wiring:generate scans expose exactly one constructor per service — the one that picks the implementation the environment can support. The concrete implementations are unexported so the generator neither registers them beside the chooser, which the container refuses as a duplicate type registration, nor reports them as skipped; the database handle they choose on lives outside the scanned packages, because a constructor asking for a `*bun.DB` by type could only have been generated for an application that has one
- config: `MELODY_STATIC_EXCLUDED_PATHS` (`kernel.static.excluded_paths`) names the path prefixes the built-in file server declines without touching the disk, comma separated. A declined request continues down the rest of the middleware chain, which is how an application serves part of the url space behind its own middleware — authentication on a directory, a stricter policy, a file server of its own. An entry is compared against the raw request path exactly as `security.NewPathPrefixMatcher` reads one, so a prefix written for a firewall rule and one written here select the same requests. An empty entry, or one that does not start with a slash, fails the boot. **Breaking**: the accessor is added to `config/contract.HttpConfiguration`, which breaks an out-of-tree implementation of that interface
- http: `SimpleRateLimitWithResolver`, `IpRateLimitWithResolver` and `UserRateLimitWithResolver` take the client-ip resolver the convenience helpers could not reach. The three original helpers build their configuration internally and return only the middleware, so `SetClientIpResolver` — the remedy the documentation prescribes for a deployment behind a reverse proxy — was unreachable through them, and `IpRateLimit(n)` therefore gave every client one shared budget behind any proxy. The original three are unchanged and remain correct where the direct peer is the client
- http: `static.FileServerConfig.SetAllowedDotPrefixList` names the dot-prefixed first path elements the file server may retrieve. The default allows `.well-known` alone, so an ACME http-01 challenge, `security.txt` and `assetlinks.json` published under the public directory stay retrievable while `.env`, `.git` and `.htpasswd` do not. The allowance never reaches past the first element, so `.well-known/.env` is refused exactly like `/.env`, and an empty list refuses every dot-prefixed path
- http: `RegenerateRequestSession` rotates the session id of a request and republishes the rotated session in one call, which is the whole session-fixation defence a login handler needs; write the authenticated identity to the session it returns. `session.Manager.RegenerateSession` remains the storage-level primitive: it mints a fresh id, carries the values over, removes the entry the previous id pointed at, and latches the session passed in out of use, so a caller that does not publish the rotated one logs the client out cleanly instead of leaving it presenting a deleted id. The latch matters because `Session.Set` lifts the cleared flag: a caller that rotated and then kept writing to the original object would otherwise have the response path re-create the just-deleted id and re-issue it as the cookie, silently undoing the rotation and letting a pre-login, attacker-plantable id carry the authenticated identity. A rotated-away session can no longer be resurrected. **Breaking**: the
  added contract method breaks an out-of-tree implementation of `session/contract.Manager`
- config: `MELODY_HTTP_SESSION_TTL` (`kernel.http.session_ttl`) sets how long a stored session stays valid, reaching the session manager through `Configuration.Http().SessionTtl()`. The default is unchanged at `0`, which stores sessions with no expiry; a negative value fails the boot. A deployment that leaves it at `0` should know the default in-memory store then grows without bound — an http application running on both the framework-supplied storage and a ttl of zero is told so once at boot
- http: `SessionCookiePolicy.Secure` takes a `SessionCookieSecurePolicy`. The default `SessionCookieSecureFromScheme` derives the attribute from the resolved scheme as before, `SessionCookieSecureAlways` forces it on for a deployment whose proxy terminates TLS but is not trusted for `X-Forwarded-Proto`, and `SessionCookieSecureNever` is the explicit opt-out — the only value that can weaken the cookie, so it is discouraged — previously such a deployment emitted every session cookie without `Secure` and had no way to override it

- cache: `Manager.GetCounter` reads a key written by `Increment` or `Decrement`. Those operations are backend-native so a distributed backend keeps them atomic, which means they store the count as decimal text rather than through the serializer — `Get` handed that raw payload to a deserializer that does not expect it, and with any serializer other than the default the two were mutually unreadable in both directions. The contract is now stated on `Increment` as well
- application: two boot warnings name a resource melody supplied that nothing will ever reclaim, so the deployment learns it from a log line rather than from a memory graph. One reports that the framework-supplied in-memory cache backend carries no item ceiling, so a key cached without a ttl is kept until the process exits. The other reports the framework-supplied in-memory session storage paired with a session ttl of zero: melody mints a session for every request that arrives without a session cookie, so one write on a public path turns every such request into a permanent entry, and an unauthenticated caller decides how many arrive. Either half alone is silent — a storage the application registered is the operator's to prune, and a lifetime the deployment set reclaims on its own. Both are raised from the http path only: a command builds its map, runs, and takes it away with it
- config: a dollar in an `.env` value opens a reference only where godotenv says it does — upper case, digits and underscore. Admitting lower case and the dot turned literals that had always been read as data into references to keys no file defines, and an unresolvable reference fails the boot: `DB_PASSWORD=pa$sword` became a lookup of a key named `sword`, and `PRICE=$1.50` a lookup of `1.50`, in applications whose configuration had not changed
- http: a middleware reference is satisfiable when the registrations sharing the referenced name cover the referrer between them. Each registration was weighed alone, so the ordinary way of writing an environment-specific middleware — an `auth` for development beside an `auth` for production, both under the one name the pipeline orders against — was refused in development AND in production for a configuration that boots correctly in both. The environment is not free-form (`config.validateEnvironment` admits `dev` and `prod` and refuses to boot on anything else), so a name registered for both is registered everywhere
- http: the reference-gating check weighs only what the group being built assembles. It was handed every definition the builder holds, so building the `web` group reported an unsatisfiable reference between two definitions confined to `api` — a pair `web` never assembles, over a gating no request to it could reach. The check still fires for the group that does carry the pair
- application: the comment on `MiddlewarePriorityStatic` describes where the static file server actually sits. It said a priority above the default keeps the server innermost; the constant is below the default and the server is outermost, which is what makes a request for a file that exists skip the rate limiter, the compressor and the access log
- http: `PrefersHtml` is covered again for an html type that arrives on its own in mixed case. The entry was rewritten to carry a second type, which reaches the parser differently — one takes the whole header as the type, the other has to split it first — and the single-type case was left uncovered everywhere
- openapi: a field the validator rejects for every value is advertised as `not: {}` rather than as an object-level contradiction. `minProperties: 1` beside `maxProperties: 0` reads as impossible and is — for an object; JSON Schema draft-04 §5.4.1 and §5.4.2, the dialect the document declares, apply both to object instances only and ignore them otherwise. Once a named collection is promoted to a component, the same pair beside its `$ref` excluded nothing and `["a"]` satisfied a conjunction the server refuses, while the inline path for the same verdict emitted `minItems`/`maxItems` and did bind — so the two paths contradicted each other. The tests asserted on the keywords rather than on the exclusion, which is why none of this was visible
- bunorm: the encrypted-width measurement no longer allocates the widest row in the table. It sealed a plaintext of `MAX(LENGTH(col))` bytes to measure the result — some 320 MB resident for a 64 MiB row, and `LONGTEXT` reaches 4 GiB, so measuring cost more memory than the batched migration it was measuring for and an out-of-memory kill is not recoverable. Raw-standard base64 encodes every three input bytes as exactly four characters, so the width is now a probe of at most two bytes plus arithmetic; the marker, key id, nonce, tag and alphabet are still read off a real seal rather than assumed
- amqp: a re-publish the broker refuses returns the delivery to the queue when no dead-letter queue is configured, instead of refusing it outright. With a dead-letter exchange bound, refusing without requeue routes the message there — kept, visible, recoverable. Without one the same refusal discards it, so the transport turned at-least-once into at-most-once under exactly the conditions that produce a refused re-publish: a `max-length` policy with `overflow=reject-publish`, an unroutable return, a queue that filled. The requeued delivery carries the counts it arrived with, which is the accounting given up to keep the message
- container: a service the container owns stays one instance for the whole process even when it is resolved through a request scope. A provider builds from the container alone now; the scope layers over the container for the code running inside a request and no longer reaches underneath into the container's own wiring. The kernel installs a request logger into every scope under the name the container registers, so a provider that did nothing request-specific beyond asking for a logger was assembled from a scope entry, kept per request, and closed when that request ended — the bunorm providers read the logger while opening, so the `*bun.DB` pool was closed at the end of the request that first resolved it, taking it away from every other one. A provider that genuinely needs something only a request carries is now told the service does not exist, at the point the mistake is made, instead of quietly becoming a per-request object a request ending destroys
- debug: the error-context walk stops at a depth bound instead of descending until the goroutine stack is gone. The cycle guard answers a context that holds itself and says nothing about one that is merely very deep, so a deep enough acyclic context — a producer-supplied map, which nothing validates — ended the process with `fatal error: stack overflow` while rendering a debug page: not a panic, so no recover in the command layer turns it into a reported failure. Measured with the stack capped at 16 MiB it took some five hundred thousand levels, which the production cap of one gigabyte scales up rather than removes. The bound is the same one `internal/copy.go` puts on the same shape of walk, far above anything a real error context reaches; a subtree past it renders as `<depth limit>`, told apart from `<cycle>` because the two say different things

- container: a scope is a registrar in its own right, layered over the container it came from. `ScopeManager.RegisterScoped` — reached through the container, which is a scope manager — declares a service whose lifetime is one scope — one http request, one message delivery, one cron tick — built lazily on the first resolution through a scope, held for as long as that scope lives, and closed when it closes; `container.RegisterScoped[T]`, `MustRegisterScoped[T]`, `RegisterScopedType[T]` and `MustRegisterScopedType[T]` are the typed front doors, and `Scope.RegisterScoped` adds one to a single live scope. The root container never sees a scoped service and two scopes never share one: each holds its own creation guard, so neither waits on the other's build. A scoped service reads both levels — the scope's overrides and the container's singletons — while a container provider stays request-agnostic exactly as before, which is the direction that had to stay closed. Until now the only way to put
  anything request-specific in front of userland was the override the framework installs for its own logger and request context, so an application had no way to declare a request-lifetime service at all. The declaration sits on `ScopeManager` rather than beside the container's own registrations, because a scope does not exist until a request arrives: the services a scope owns have to be declared by whatever will be making the scopes. **Breaking**: `container/contract.ScopeManager` and `container/contract.Scope` gain `RegisterScoped` and `MustRegisterScoped`, which breaks an out-of-tree implementation of either — including an implementation of `Container`, which embeds `ScopeManager`
- container: `Replacing()` admits a registration whose name — or whose registered type — the other lifetime already claims. Without it the collision is refused where it is made, in both directions and whichever order the two registrations arrive in, because a name that answers with a process singleton outside a scope and with a per-request service inside one is an ambiguity whose symptom appears one lifetime away from its cause. It admits substitution, not decoration: a scoped provider that resolves the name it replaces re-enters itself and is reported as the circular dependency it is
- container: `ClosedWithScope()` hands an installed override to the scope's teardown, through the new `OverrideInstanceWithOptions` and `OverrideProtectedInstanceWithOptions`. The default is unchanged and stays the right one — an override belongs to whoever installed it and outlives the scope, which is what lets the http kernel report a scope-close failure through the request logger it installed — so the option is for the caller that built the value for one scope and holds no other reference to it. The four `OverrideService` signatures are untouched
- container: a scope closes what it built in dependency order, dependents before their dependencies, falling back to the descending node key for anything the graph says nothing about and reporting a cycle the way the container's own teardown reports one. The previous order was the node name alone, which was defensible while the only scope-built values were incidental and is a coin flip now that a scoped repository holding a scoped transaction is the ordinary shape
- container: a collection gathered on a scope holds the scope's registrations as well as the container's, and one gathered by a container provider holds only the container's. `AllImplementing` on a scope previously delegated straight through, so a scope-registered handler was silently absent from every collection — a handler nothing dispatches to, with no error anywhere to say a member was missing
- application: `ScopedServiceModule` is the module hook for request-lifetime services, with `RegisterScopedServices(registrar ScopedServiceRegistrar)` running at boot beside `RegisterServices`. It is a separate interface, so no existing module changes. `ScopedServiceRegistrar` and `ServiceRegistrar` deliberately share no method with each other's container counterpart: a container provider handed to the scoped hook, or a scoped provider handed to `RegisterServices`, is a compile error at the call site rather than a service quietly rebuilt and closed once per request. A name claimed at both lifetimes joins the aggregated boot collision report
- wiring: `//melody:scoped` on a constructor emits it into a second generated function, `<function>Scoped(registrar containercontract.ScopedRegistrar)`, through `MustRegisterScoped`/`MustRegisterScopedType`. The two registrars arrive at two different module hooks and neither satisfies the other, so two functions is the only shape that fits both; the function is emitted only when something carries the directive, and a project that declares nothing scoped regenerates a byte-identical file. `melody:wiring:generate` takes `--scoped-function` to name it

- exception: `Logged` answers an error that reports itself already logged, and is what a writer returns after filing its record. An error whose chain carries an `AlreadyLogged` implementer is marked in place and handed back unchanged, so its identity — and every `errors.Is` and `errors.As` its readers perform on it — survives; an error whose chain carries none is wrapped in a marked melody error keeping it as its cause, because `errors.New`, `fmt.Errorf` and every runtime error have nowhere for the mark to live and the next reader would otherwise file the same failure a second time. The wrap cannot change how a status is resolved: it happens exactly when no `HttpException` is in the chain, which is exactly when the status was already going to be the generic one
- exception: `IsAlreadyLogged` reads the already-logged mark at the depth `MarkLogged` writes it. It is the single reader: reading the mark off a concrete `*Error` instead misses a marked `HttpException` and anything wrapping a marked error, which are then rendered a second time
- logging: `NewStandardErrorLogger` adapts a melody logger to the `*log.Logger` the standard library asks for, so a component that can only speak to one — net/http's `Server.ErrorLog`, bun's diagnostic channel — reaches the application's journal instead of printing unstructured text to stderr, where it is invisible to a deployment whose journal is a json file. Each line the standard logger emits becomes one warning record with the line in the context, so the message stays the one groupable string an operator can query on; a nil logger leaves the destination inert

- cli: `--format=json-pretty` renders the same envelope indented for a person reading it by hand. It exists because json is the machine format and a machine reads a stream: one document per line, so a consumer can follow a long-running command live with a line reader and hand each line to a parser whole
- cli: `output.IsJsonFormat` answers for both json spellings, and every place that used to compare against `FormatJson` asks through it — the two differ in whitespace alone, so a site that recognised one and not the other would colour a banner into a document, or print a table where a document was asked for
- container: `IsClosed` reports whether a `Close` already began tearing the container down. A repeated `Close` returns the first teardown's memoized error, so a caller that closes defensively could not tell a failure it had just caused from one somebody else had already discovered and reported; asking before closing is what keeps one failure from being presented as two incidents
- application: `ProcessContext` — `ServiceProcessContext`, `NewProcessContext`, `ProcessContextMustFromResolver`, `ProcessContextFromResolver` — is the console counterpart of the http request context: the generated process id every log record of the run is correlated under, and the moment the run started.
- logging: `NewProcessLogger` is the console sibling of `NewRequestLogger`, and the cli entry point now decorates with it.
- logging: `RunShieldedStep` runs one step under the exit handler's own budget and answers whether it finished, so the normal return of `Run` tears down under the same shield the panic path has had since the exit-step budget was installed
- logging: `Closed()` on the json logger reports whether `Close` really closed the underlying writer, and `NewRequestLogger`'s decorator forwards it to the logger it wraps — the question the process-boundary exit handler asks before trusting a logger with the final record, because a file-backed logger a teardown already closed silently drops every write

### Changed

- example: the connection is declared in a `bunorm.ManagerRegistry` instead of opened directly. The registry validates the definition as it is built and is the one door the `db:*` commands resolve, so the operator running a migration and the repository resolving at first request reach one pool rather than two onto the same database; the `*bun.DB` the rest of the application holds is the registry's default manager, published under a name of its own, and closing the registry is what closes the pool. The retry configuration and the TLS opt-out travel in the provider definition. The credential keeps the marking `RegisterParameters` already gives it — this major names `MYSQL_PASSWORD` itself, so the registry is not asked to say it a second time
- example: each major's example application holds its schema in a database of its own rather than the one all three shared. The bunorm/migrate command family builds its migrator on bun's default bookkeeping tables and bun matches an applied migration by NAME, so three migration sets in one database would share one `bun_migrations` and the first set to land would answer for the others — a later major's `db:migrate` would report success having created nothing. The development mysql is still one container; the databases are created by an init script on a fresh volume and idempotently by the e2e harness on one that already exists

- example: the request-scoped service is the nomenclature's journal accumulator rather than a route that reports on itself. The event listener that follows a write records into it, and a middleware writes what it holds once the handler chain has returned — before the response is sent, so a caller that reads the journal on receipt of its 201 is not racing the write, and a journal write that fails fails the request instead of becoming a log line. The scope's own teardown remains the safety net for a request that never reached the middleware. Every entry now carries the request that caused it, and a request that changed several records costs one round trip rather than one per change. `/scoped/trail/demo` is gone: what it claimed about itself is now the journal row a real write leaves behind, which is a claim a response cannot fabricate
- example: every catalogue and directory write is recorded through `bunorm/audit` on the tables the application actually uses, so who changed which field, from what to what, is answerable after the fact for the products and the accounts rather than for a table kept for the purpose. The actor is the account the request authenticated as; the password column is recorded as changed with its value masked, because a trail that kept credentials is worse than no trail. `/database/audit/demo` and its `melody_example_products` table are gone, and so are `/database/demo` and `melody_example_secrets` — transparent encryption at rest is already carried by the two-factor enrollment, whose shared secret must be stored reversibly and is read back to verify every code
- example: a change to the nomenclature is announced on the websocket to every open page, emitted by the same listener that invalidates the cache and writes the journal entry, and the product list carries a bell that counts what arrived and reloads on click. The counter a ticker used to broadcast, the page built to watch it and `/websocket/demo` are gone: the socket now carries the application's own changes, and an end-to-end section proves two live clients are both told about one write
- example: the two-factor enrollment table carries the major, like every other table the application writes: `melody_example_v3_two_factor`. Three example applications share one database in development, and it was the one table whose name did not say which of them owned it. The audit trail's own transaction table keeps the integration's fixed `melody_audit_transaction` name, which is not per-major — only v3 records an audit trail today, so nothing collides, but two majors recording one would share it
- example: the routes and commands are named for what they do. `/platform/demo` is `/platform/check`, a readiness probe over the lock and the storage backend; `/messagebus/demo` is `/messagebus/dispatch`; `/encrypt/demo` is `/encrypt/roundtrip`; `/redis/token/demo` is `/redis/token/revocation`; `/storage/demo` is `/storage/object`; `example:grant:demo` is `example:grant:role`, `example:exclusive:demo` is `example:exclusive:tick` and `messagebus:demo` is `messagebus:dispatch`. `/cache/demo` is gone — it wrote a key and read it back while the real cache is the product listing, invalidated on every write and already read out of band by the harness

- logging: `LogOnRecover` only logs. It terminated the process when the recovered value carried an exit code, skipping every remaining deferred call, which is the one place in the framework where a library helper could end a program that had not asked to end. `LogOnRecoverAndExit` is the honestly named helper for that, and the two call sites that want it use it
- config: `Resolve()` reports an error once the application is serving. Resolution rewrites the parameter store, and by then every service holds values copied out of it, so a later pass cannot reconfigure anything that is running — it only rewrites the store under readers that expect it settled. Building a configuration by hand and resolving it before serving is unaffected
- config: a positive session ttl below one second fails the boot. Such a value does not describe a short session but a broken one: the file-backed store purges a lapsed entry on the same write that stores it, so a lifetime near the cost of that write returns success having persisted nothing, and one second is the finest unit an HTTP date can express in any case. Zero keeps its meaning of no expiry
- httpclient: the client sets `MaxIdleConnsPerHost` on its transport, exposed as `TransportConfig.MaxIdleConnsPerHost` and defaulting to `MaxIdleConns` (100), following an override of it unless pinned explicitly. It was never set, so `net/http` fell back to `DefaultMaxIdleConnsPerHost` (2) and the configured `MaxIdleConns: 100` was inert: since a `BaseUrl` means one client per upstream, a burst of 200 concurrent requests dialled 200 sockets, retained 2 and closed 198, each holding a `TIME_WAIT` entry for the 60-second MSL until the ephemeral port range was exhausted and every request failed with `connect: cannot assign requested address`, reported as `"request failed"` and indistinguishable from the upstream being down. **Behavioural change**: connection reuse against a single host now scales with `MaxIdleConns`; a caller who relied on the old two-connection ceiling must set `MaxIdleConnsPerHost` explicitly

- validation: a nil pointer embed is validated as "nothing was supplied" rather than "nothing to validate", so the constraints on its promoted fields run against their zero values exactly as a value embed's already did. A payload that mentioned no field of a `*T` embed previously skipped every constraint the embed promotes — naming any sibling field made `encoding/json` allocate the embed and re-arm them — so a body of `{"status":"open"}` on a request whose `*Audit` embed declares `ActorId` as `notBlank` passed validation and then dereferenced nil in the handler. **Behavioural change**: requests that relied on omitting the embed entirely are now rejected with the constraint errors the tags declare. A promoted field shadowed by an outer field of the same json name stays unvalidated, so the dominance rules are unchanged
- validation: exceeding the nesting-depth cap is reported as a validation error (`nestingDepthExceeded`) only when the truncated subtree could actually carry a `validate` tag, so nesting past the cap can no longer bypass validation while free-form tag-free client json is accepted up to the cap as before. An interface-typed member counts as possibly tag-bearing, its dynamic type being unknowable from the type alone: the walk descends into one and enforces the tags it finds, so clearing it statically let a payload nest past the cap and bypass them. **Behavioural change**: tag-free json reached through an interface — a `map[string]any` metadata field among it — is reported as `nestingDepthExceeded` past the cap rather than accepted at any depth. Past the cap the walk previously returned an empty error list, which `Validate` converted to `nil`, so nesting a payload one level deeper than the cap bypassed every constraint in it. The reachability check follows pointers, slices, arrays and map
  elements and is memoized per type; the cap value is unchanged. A member the payload sent as null or empty — a nil pointer or interface, a slice or map holding no element — is no longer reported at the cut: the walk returns no errors for it at any depth, so the error named a member that was never walked
- http: `JsonHandler` rejects a literal `null` request body with `400` when its request type is instantiated as a pointer. The four-byte body decoded without error and left the value nil, the validator took its nil-pointer early return and reported every constraint satisfied, and the handler then dereferenced nil. A value instantiation and a `{}` body were never affected, and a caller-supplied error responder still shapes the response. **Behavioural change**: that request is now a client error instead of a `500`

- http: a route pattern whose optional parameter is not its final segment is refused at registration instead of being accepted and half-served. An omitted optional is dropped wherever it sits in the pattern, while a match only ever ends early at the tail, so `/blog/:locale?/posts` let `UrlGenerator.GeneratePath` mint `/blog/posts` — a path the router matched with nothing and answered `404`; the canonical locale-prefix shape `/:locale?/blog` was broken the same way whenever the parameter carried no default, while a trailing optional worked correctly all along. A mid-pattern optional that carries a default is still accepted, because the default is always substituted and the segment is therefore never dropped. **Behavioural change**: an application registering a mid-pattern optional with no default now panics at the definition site with `optional route parameter must be the last pattern segment unless it has a default` instead of booting and emitting dead links — give the parameter a
  default, move it to the end, or register the long and short patterns as two routes

- cli: in json mode a command's standard output is the rendered document and nothing else — the ansi start/finish banner that `cli.Register` wraps around every registered command is suppressed, and `--format=json` implies `--no-color`. Nothing is lost: `meta` already reports the command, its arguments, the start time and the duration, and `error` reports the final status. **Behavioural change**: `jq` and `json.Unmarshal` now consume `debug:*` output directly instead of failing on the first byte; a consumer that scraped the banner off stdout must read `meta` instead
- cli: a command whose envelope reports an error exits non-zero. `output.Render` returns an exit-coded error after writing the envelope, so `debug:container <name>` fails when the service cannot be resolved instead of printing `[success]` and exiting `0` — a deployment gate such as `app debug:container app.repository.order || exit 1` now catches a broken container. A registered service that errors or panics while being constructed is reported as `debug.buildFailed` rather than `debug.notFound`, so the operator is not sent after a registration that is in fact present. **Behavioural change**: a command that reported an error in its payload while exiting `0` now exits `1`
- cli: `--format` and `--order` reject an unrecognised value instead of silently substituting the default. `--format=JSON`, `--format=yaml` and `--order=ascending` now fail during flag parsing with a message naming the accepted values and a non-zero exit, matching how `--limit=abc` already behaved, instead of quietly printing the human table. Omitting either flag still defaults to `table` and `asc`. **Behavioural change**: a script passing an unsupported value now fails instead of receiving the table

- http: the response path saves and advertises the session published on the request under `RequestAttributeSession` at the moment the response is written, rather than the one the kernel captured before routing. **Behavioural change**: replacing that attribute in a handler now takes effect

- cli: `--order=desc` reverses the listing in `debug:router`, `debug:events`, `debug:parameters`, `debug:middleware` and `debug:container`, applied before `--limit`/`--offset` so a descending window returns the end of the list rather than the beginning; `--order=asc` remains the default. **Behavioural change**: the flag was accepted and ignored before, so an invocation that passed it now gets different output
- cli: the `--fields` and `--sort` flags are withdrawn. No printer ever read them and no command ever sorted on a supplied key, so they are removed from the flag set, from `output.Option` and from the `meta.flags` block of the json envelope rather than left advertising a projection the document never received; `output.SplitFields` goes with them. **Behavioural change**: passing either flag now fails as an unknown flag instead of being silently ignored. **Breaking**: `output.Option` no longer has the `Fields` and `SortKey` fields, so a command that constructs that struct as a literal no longer compiles, and `output.SplitFields` is gone

- rate limit: the default key extractor now keys on the client IP alone instead of `ip:path`. `SimpleRateLimit(n)` is therefore a true per-IP budget of `n` requests per minute rather than `n` per IP per path — a client that varied the path could previously never trip the limit. **Behavioural change**: an application relying on the old per-path budgets must set a path-aware `KeyExtractor` explicitly. Both limiters also bound how many distinct keys they track (`SetMaxKeys`, default 1,000,000): once the map is full and an idle-entry prune frees nothing, a request under an unseen key is denied rather than growing the map without bound. The reclaim walk runs at most once per window, so a full limiter cannot be made to pay a whole-map scan for every request under an unseen key
- security: an access control rule whose attribute list normalizes to empty is refused at construction instead of being accepted. Such a rule still matched its path, so it granted every authenticated principal and shadowed any longer-prefixed rule that would have denied — a silent privilege downgrade from a variadic call with no attribute, or from a role that a configuration value resolved to empty. Blank attributes inside a non-empty list are still trimmed
- http: `TokenBucketLimiter` is now `FixedWindowLimiter`, with the old type name and both constructors kept as deprecated aliases so existing code is unaffected. The limiter restores the whole allowance at the window edge rather than proportionally to elapsed time, so it is a fixed-window counter and an instant straddling that edge admits up to twice the rate; the name now says so. `SlidingWindowLimiter`, which `IpRateLimit` and `UserRateLimit` already use, holds the rate over every trailing window
- security: `totp.OtpauthURI` is now `totp.OtpauthUri`, with the old spelling kept as a deprecated alias so existing code is unaffected
- http: the request attributes the kernel owns are reserved under the framework's own underscore prefix (`RequestAttributeSession` is `_session`, `RequestAttributeScheme` is `_scheme`) and are published after the route attributes, so a route attribute can no longer replace the session object or the resolved scheme. Every other framework attribute already carried that prefix. **Behavioural change**: code reading these attributes through the exported constants is unaffected; code that hardcoded the literal `"session"` must move to `RequestAttributeSession`

- cli: `--format=json` writes one document on one line, terminated by a newline, instead of an indented block. **Behavioural change**: the document is unchanged and `jq` reads either, but a consumer that counted lines or read the output as a single indented block sees the new shape; `--format=json-pretty` is the indented one from now on. Indenting by default made every document many lines, which every line-framed consumer — a log collector's json stage, a `while read line`, a `grep '\"failed\": true'` — receives as fragments that each fail to parse
- cli: text of server or client origin reaching the terminal is escaped rather than obeyed. The start and finish banners embed the command's own error, which routinely echoes downstream values, and the table cells carry whatever the command was reporting: an embedded carriage return or escape sequence could repaint the status line as another verdict, or forge lines in a captured log
- httpclient: the response body cap bounds `RequestStream` too, the inherited default of ten mebibytes included — the cap was completely inert on the streaming path: a caller who asked for ten bytes was handed everything the server sent, and a caller who never named a cap streamed unbounded behind a bounded contract. **Behavioural change**: a stream that legitimately carries more than the default names its own cap through `WithMaxResponseBodyBytes`; the body past the cap is refused with the cap, the method and the sanitized url in the record

### Removed

- cli: the dead unexported error presenter is gone — an error-printing path with sorted context and a bounded cause chain that nothing has called since the envelope renderer became the one presentation, drifting beside the live path it duplicated

### Fixed

- exception: `MarkLogged` marks the nearest `AlreadyLogged` implementer in the chain rather than only the value it is handed, and answers a typed nil unchanged instead of attempting to mark it. A record filed against a wrapped melody error left the mark unwritten before, so the reader at the same depth found nothing and the same failure was rendered a second time
- documentation: fifty-six exported doors this major has always carried are listed at last, added beside the same repair on the two published majors so a reader of any of the three finds the same surface. The access control merge strategies were given as the three string literals and never as the exported constants a caller is meant to pass; the session-fixation section taught the manual two-step rotation without naming `http.RegenerateRequestSession`, which does both; and the rest are doors of the same kind — the deferred-resolution handle and the container's four registration sentinels, the process-identity family and the signal context every `Run` example is handed out of thin air, the config resolver a provider actually comes through, the setters of the cache remember option, the session cookie constant, the interface a userland constraint has to implement, the cause-chain builders, four http contracts declared beside two siblings that were listed, both cookie helpers, the file
  server path every request actually takes, and the deprecated cors doors that were half listed. Where this major's code differs, the entry says what this major does rather than what the published ones do: `config.IntWithDefault` answers the default for a value that does not parse, where they refuse it
- example: the shared icons every page links — `favicon.ico`, `assets/favicon.svg`, `assets/logo.png`, `assets/apple-touch-icon.png` — are produced by the same `npm run build` that produces the frontend bundle, so the one command a fresh clone needs for the browser interface delivers everything a browser asks for. They used to be produced only by a hand-written copy loop inside the development container's entrypoint, so anyone who did not run the Docker stack got a 404 for all four while the packaging matrix promised a binary requiring "nothing else" at runtime. They still exist in exactly one place in the tree, `<root>/.assets`, and are git-ignored under every example, so no second copy can go stale: `assets/sync-icons.mjs` owns the mapping from source name to served name and is what copies them, run as the `prebuild` step of the bundle and by the entrypoint for each major. The README also names that build step for the first time — `melody_static_embedded` freezes `public/` into the
  binary at compile time, so a binary built before it carries neither bundle nor icons and cannot gain them afterwards
- example: the comment in `.env` no longer claims that an already-set process or host environment variable overrides the value beside it. melody reads configuration only from the `.env` files and writes a warning naming each process variable it ignored, so the pattern the comment taught — commit `.env` with development values and inject the secrets through a `env:` entry in an orchestrator manifest — started the application against the values in the file with the injected secret reaching nothing. The comment now names the real override, `.env.local` or `.env.<MELODY_ENV>`, and says that a key is unset in the file rather than out of the environment
- security: `InMemoryTokenStore` no longer drops the members of `Claims` it was not written to know about. The clone named the fields it carried, so every field added to `Claims` afterwards vanished through `Put` and `Lookup` with no compile error to say so, while the redis store round-tripped through JSON and carried them — the two stores would have disagreed about exactly the members a revocation is decided on. The clone now starts from the value and replaces only what would otherwise alias the caller
- container: `HasType` canonicalises the type it is asked about, so it can no longer answer "no" for a service `GetByType` resolves happily. Registrations are filed under the canonical type — a provider returning `*T` is indexed under `*T` — and every resolution canonicalises before it looks, but the two `HasType` implementations did not: asking with the value type reported the service absent, and a caller that guards a resolution with `HasType` took the branch for a service that is registered. The scope answered the same way for an installed override, which is filed under the canonical type of the value.
- container: a provider that panics no longer leaves the resolution around it blind to its scope. Scope visibility was restored inline after the provider call, so a panic unwound through the guard's recovery and skipped the restore, and every service resolved afterwards on that resolution saw a suspended scope. Nothing observed it while no userland service could be scope-owned; it is load-bearing now that one can
- http: a scope-close failure is reported through the emergency logger when the request never got a logger of its own, instead of being dropped. The report is written after the scope has closed, which is safe only because the request logger is an installed override and a scope leaves overrides alone — so the one path that had no override to report through said nothing at all about a failure that must never go unreported
- openapi: a validation tag on a field whose type is published as a component reference is described from what that component actually is, so a `notEmpty` on a promoted collection advertises the same floor an inline one would instead of being published as impossible to satisfy. Only a type reached through a reference is affected, and only where the validator agrees: a tag the validator rejects for that shape is still advertised as unsatisfiable, and a fixed-length array keeps its own reading, since a short payload is zero-filled rather than refused
- container: a request scope closes the services it built. Only what the scope created is closed — an override placed into it from outside and a singleton that came from the root container are left alone, because the scope did not build them and does not own their lifetime
- internal: the defensive copy isolates pointers, structs and arrays, so a consumer that only reads a copied value can no longer mutate the original through it. A token's attributes reached the token's own authorization data and the caller's claims that way, and a session payload was shared process-wide across concurrent requests on one identifier while the storage lock protected only the map around it. Maps and slices were already isolated; the depth bound and cycle handling are unchanged. Data decoded from json is unaffected and allocates exactly as before. **Behavioural change**: a pointer stored and read back is no longer the same pointer
- debug: an error context that refers to itself is rendered with the loop marked instead of exhausting the stack. Redaction deliberately runs before serialization, so it walked the raw context ahead of the cycle detection `encoding/json` would have applied, and a stack overflow is a fatal error no recovery catches. The walk marks where a loop closes and keeps the surrounding keys; a container two sibling keys happen to share is not a loop and is still rendered
- application: a panic inside an http shutdown hook is logged and the drain continues, instead of being able to terminate the process. The hook recovery reached a helper that exits when the recovered value asks for an exit code, so a hook could end the process in the middle of the shutdown it was registered to participate in
- openapi: a type that reaches itself through a named collection — `type Metadata map[string]Metadata`, `type Nodes []Nodes`, or a mutual pair — is described through a component reference instead of exhausting the stack. A cycle that never passed through a struct met neither the visited set nor the component placeholder that break struct cycles, and a stack overflow is a fatal error no recovery layer can catch: because the specification is generated per request, the first client to fetch it killed the process and every restart killed it again. Only a type that previously could not be described becomes a reference, so a document that already generated is unchanged. The walk is additionally bounded, and a position that reaches the bound is described as unconstrained rather than abandoning the document
- openapi: a pointer that refers to its own type no longer live-locks the walk. Six places stripped pointers in an unbounded loop and now share one bounded dereference, where a chain that outlasts the bound is left as a pointer and each caller reads that as "not the kind I asked about". The schema walk itself keeps a bound of its own rather than sharing this one, because it has somewhere to put the answer: a chain that outlasts it is published as an undescribed nullable position instead of being declined
- lock: a renewal that never answers can no longer leave two instances believing they hold the lease. Leadership was derived from whether the last renewal returned an error, and the renewal itself ran without a deadline, so a store that stopped answering left the incumbent claiming a lease that had already lapsed while a second instance acquired it. A renewal is now bounded by a deadline of its own and leadership is true only while the lease the store actually granted is still in the future
- lock: **Behavioural change** — `RunExclusive` decides demotion from the lease clock rather than from the outcome of one renewal. The deadline on a renewal bounds the call so a wedged store cannot park it forever; it is no longer a verdict on the lock. A renewal that answers slowly still renewed — the budget was a quarter of the ttl, so a call that succeeded at forty percent of it cancelled work that was never in danger — and a single dropped renewal is now survived by the one behind it, which is the whole reason the cadence is half the ttl. Demotion follows once the lease last written is within half a cadence of lapsing. The per-call budget is also clamped to the cadence after the minimum-interval floor rather than before it: below two milliseconds both were floored independently and the budget came out LARGER than the cadence, so every attempt overlapped its successor. `LeaderGate` follows the same lease clock, with a `MaxConsecutiveRefreshFailures` threshold (three by default,
  configurable, negative to disable) for the one case the lease clock cannot see: a gate whose cadence is far denser than its lease would otherwise run leader work for the whole lease against a store that has gone. Leaving on the FIRST failed renewal turned a store failover into a cancelled term, a re-election and leader work restarted from the beginning, for a lock no other instance could have taken — the cadence is half the lease precisely so a lost renewal is survivable. Renewals that land clear the count, so scattered losses never accumulate. At the default cadence the threshold is unreachable and the lease decides, which is why the existing demotion tests are unchanged
- lock: `IsLeader` stops claiming a lease the moment it is lost, rather than when the elected hook finishes unwinding. A hook that ignores its cancelled context kept the claim alive indefinitely, so the two signals the documentation tells you to combine disagreed
- http: a handler that returns no response reaches the `kernel.response` event like every other outcome. The empty `204` was synthesized on a separate exit path that skipped the dispatch, so a listener never saw it: a cross-origin request answered that way carried no `Access-Control-Allow-Origin` and was blocked by the browser, and the access log recorded status `0`. The response is normalised before the dispatch, so there is one exit path
- container: a service whose creation read an entry out of a request scope is kept in that scope and dies with it, instead of being stored in the root container. The first request to build such a service froze its overrides — the logger carrying that request's identifier, the request context — into a process-wide singleton every later request then received. A creation that reads nothing from the scope is still a singleton, and a store that would put a scope-resolved instance in the root container is refused with the service and the entries it read
- container: a service that cannot be created reports its own failure. A provider returning an error alongside a nil value had that error replaced with the generic report and demoted to the cause, so a missing registration was announced as a provider returning nothing. The generic report is kept only for a provider that returns neither a value nor an error
- config: reading a parameter no longer races the resolution that rewrites it. Guarding the incidental write left the primary one — the resolution pass over every parameter — unguarded, and a consumer holding the parameter reads its value without the configuration lock
- config: a `${...}` reference in an `.env` file resolves against every file the environment loaded, and an undefined, self- or mutually-referencing one fails the boot. The underlying loader expands each file on its own, so a reference to a key defined in a sibling file silently produced an empty string — a credential assembled that way degraded to a blank rather than refusing to start, which is the opposite of what `%env()%` does with the same mistake. A `\$` still writes a plain dollar and a single-quoted value is still literal
- http: the compression middleware emits `Vary: Accept-Encoding` on every path, including the one taken when the response already carries a `Content-Encoding` and the excluded-path and excluded-content-type paths. A publicly cacheable pre-encoded response was stored under the url alone and served to a client that had asked for a different encoding
- http: a middleware may only reference, through `before` or `after`, a middleware enabled in at least every environment it is itself enabled in. A reference to an environment-gated middleware was dropped wherever that middleware was filtered out, turning into a missing reference that failed the pipeline build and panicked the boot — so a pipeline that started in development failed to start in production. The rule weighs the declared environment sets, so the mistake fails identically in every environment instead of only where it breaks; the group a build is asked for is left to the selection, since several groups are built in one process and a reference unsatisfiable in another group says nothing about this one
- http: `NewForwardedClientIpResolver` reads a bracketed IPv6 literal that carries no port, so a trusted edge emitting `[2001:db8::1]` no longer collapses every IPv6 client onto the proxy's own rate-limit budget while IPv4 clients keep theirs. The trusted-proxy check reads the same four authority forms
- http: the compression middleware bounds the read it uses to decide whether a body reaches the compression threshold. A body reader answering zero bytes with no error pinned a request goroutine at full processor use indefinitely; the read fails the request after the same number of consecutive empty reads `bufio` tolerates
- http: the static file server no longer trims whitespace off the path it resolves, so `/%20internal/secret.json` no longer retrieves `internal/secret.json`. Access control matches on the raw request path, so the trim let a padded spelling reach a file a path-prefix rule protects — the same aliasing the router already refuses, and it also made the two build modes answer the padded spelling differently
- http: the static file server refuses a path that is not already canonical instead of serving the file `path.Clean` folds it onto. `/open/../internal/secret.json` and `//internal/secret.json` reached files that a path-prefix access-control rule, matching on the raw path, never saw. The spellings that fold onto the root still serve the index file
- http: the static file server answers `GET` and `HEAD` only. Every other method received the full file body, so an `OPTIONS` preflight for a path that resolved to a real file was answered with the file instead of the cors headers, and every asset was a `POST` endpoint answering `200`
- http: the static file server ignores `If-Modified-Since` when the request also carries `If-None-Match`, as RFC 9110 requires. A non-matching entity tag combined with an unchanged modification time answered `304`, so any deploy that preserves timestamps while changing content left revalidating caches serving the old bytes indefinitely
- http: the static file server accepts all three HTTP date formats for `If-Modified-Since` (RFC 9110 requires accepting the obsolete RFC 850 and asctime forms, not only IMF-fixdate)
- http: the static file server records a refused resolution on the streaming path. `ServeReader` is the only path any request takes — `Serve` has no caller outside its own tests — and it discarded the logger, so a traversal attempt, a symlink escape and an invalid path were all indistinguishable from an ordinary miss. A resolution that simply found no such file is recorded at debug level, along with the successful ones: the static server is consulted for every request, so anything louder would file one record per request that is not a static asset. A refused resolution — a path that is not canonical, a dot-prefixed element, a path the filesystem rejects — is still recorded at warning
- http: a route whose only segment is a trailing optional parameter is served at the root again. `/` is the one path whose trailing slash cannot be trimmed away, so it splits into two empty segments and the empty-segment guard refused the optional — while `UrlGenerator` mints exactly `/` for that shape and the OpenAPI document advertises it, so the framework answered a url it had produced itself with a `404`. The optional is treated as omitted and left unbound, as it is everywhere else
- http: a `RouteGroup` no longer writes its name prefix and its merged requirements and defaults back into the caller's `RouteOptions`. One options value reused across two grouped registrations accumulated the prefix, so the second route registered under a name nothing could generate, and the first group's requirements leaked into a later registration through a different group. **Behavioural change**: reusing one options value for two routes in the same group now raises the documented duplicate-name panic instead of silently registering the second under a doubled prefix
- http: a route declared with an empty method no longer contributes an empty token to the `Allow` header of a `405` response; an empty element is not a valid method token (RFC 9110)
- validation: a field promoted through stacked embed levels below a diamond is validated again. The dominance walk counted how many paths from the root reached a type instead of how many times one level reaches it, so an ancestor diamond cascaded its multiplicity onto every type below it and annihilated a name `encoding/json` does populate, silently skipping every constraint declared on that field. The count now increments once per embed occurrence, exactly as `encoding/json`'s own field walk counts it
- openapi: the schema mirror publishes a property promoted through stacked embed levels below a diamond, matching the validation walk it mirrors — the same multiplicity cascade dropped the property from the document while the walk dropped its constraints, so the specification and the enforcement agreed with each other and disagreed with `encoding/json`
- lock: a `LeaderGate` starts renewing its lease before `OnElected` runs, and the hook receives a runtime whose context is cancelled when the lease is lost. Nothing renewed the lease while the hook ran, so a hook slower than the ttl let the lease lapse: another replica acquired, both reported leadership, and the incumbent never demoted because demotion only follows a failed renewal — which could not happen while the hook held the campaign loop. **Behavioural change**: `OnElected` is handed a term-scoped runtime rather than the run runtime, so leader-only work that respects its context now stops when the lease is lost instead of running alongside the new holder
- messagebus: `melody:messagebus:consume` separates the shutdown signal from the handler lifetime — the signal stops the pull of new deliveries, while in-flight handlers and their `Ack`/`Nack` keep a live context for the whole `WithShutdownGrace` window. One shared context meant a signal cancelled the running handler immediately, so the grace protected nothing that respects its context, and the acknowledgement ran on the cancelled context too: any transport that honours the runtime context on publish failed the `Ack` of a message whose side effects had already committed, so the broker redelivered it on every deploy, while a failed `Nack` dropped the `RedeliveryStamp` increment and `MaxRetries` never converged. **Behavioural change**: a handler that respects its context is no longer cancelled at the signal; it is cancelled when the grace expires
- http: equal-priority middlewares now run in the order the application registered them. The pipeline resolved ties on the definition's generated name, which carries the registration counter as decimal text, so `middleware.10` sorted ahead of `middleware.2` and every factory-provided middleware sorted ahead of every directly registered one — a cors middleware registered before an authentication factory ended up inside it, and a preflight was answered `401` with no `Access-Control-Allow-Origin`. Explicit `before`/`after` edges and priorities decide the order as before. **Behavioural change**: any application registering two or more middlewares at the same priority gets the nesting it asked for, which for some is a different pipeline than before
- validation: the parsed validate tag and the constraint a parameterized rule resolves to are memoized instead of being rebuilt for every value the validator reaches. A `regex` tag recompiled its pattern once per element, so a body of about 80,000 elements performed 80,000 `regexp.Compile` calls — measured at roughly 3.1 seconds of CPU before the handler ran, now about 37 milliseconds. The parse cache is keyed on the tag string and the constraint cache on the rule name and its parameters, both length-prefixed so no two distinct rules can share a key; the constraint cache is per-validator, so custom constraints registered under the same name in different validators stay separate. Tag strings come from struct tags, so neither cache can be grown by a request. **Behavioural change**: a parameterized constraint is now configured once and the same instance is reused for every value it validates, so a custom `ParameterizedConstraint` whose `WithParams` result carried per-value state, or was
  not safe for concurrent use, must be made immutable
- openapi: a struct that promotes an embedded `time.Time`'s codec is advertised as the `date-time` string `encoding/json` actually writes, instead of an object of properties that never reach the wire. The advertisement follows Go's promotion rules rather than mere reachability: the codec at the shallowest embedding depth wins, embeds tied at that depth promote nothing, and a non-struct embed competes like any other — so a depth-1 marshaler embed writing an object keeps its object schema even when a `time.Time` sits below it, where reachability alone would have promised a string for an object body. The recognition stays limited to `time.Time`, the one embed whose wire form is derivable from its type. Where reflection cannot settle which type won — a codec with a pointer receiver behind a pointer embed, a codec reached through an embed cycle — the object schema stands rather than a guess. Still advertised as objects, unchanged: a promoted `MarshalText` fallback, a user `json.Marshaler`
  embed, and an embedded marshaler interface; and a `MarshalJSON` declared on the enclosing type over a `time.Time` embed still reads as the promoted one, `reflect.Method` carrying no declaring type
- openapi: an instantiated generic gets a component key strict validators accept and a `$ref` that resolves. Go reports the type arguments as part of the type name (`Page[github.com/acme/app/api.User]`), whose brackets fall outside the `^[a-zA-Z0-9.\-_]+$` key grammar for every instantiation, and whose import-path slashes split the `$ref` json pointer into four tokens where one was meant, so the reference resolved to nothing. Import paths are dropped and the remaining punctuation folded to a single underscore, giving a key derived only from the type and therefore stable across runs; two instantiations that fold alike are separated by the existing numeric suffix
- openapi: a route with a trailing optional parameter is documented as both of the paths it serves. The router answers `/users` and `/users/42` for `/users/:id?`, but the document carried only `/users/{id}`, silently omitting a path the server answers. OpenAPI 3.0 forbids `required: false` on `in: path`, so the two shapes are emitted as two path items sharing the described operation — summary, tags, request body and responses — with the shortened form carrying no path parameter and a distinct operation id (`<id>.without.<parameter>`, since operation ids must be unique). A route explicitly registered at the shortened path keeps its own operation, whichever order the two are registered in

A key defined in the .env artifacts always wins over the fallback, so an environment that needs the real endpoint sets it and every other one boots on the default instead of having to declare a key it does not use. The processor is opt-in: a plain `%env(KEY)%` still fails resolution when the key is undefined, so a parameter holding a credential refuses to boot rather than degrading to an empty string. The fallback is resolved through the parameter branch, inheriting its recursion, its circular-reference guard and its undefined-key reporting.
- `config/configuration_resolve.go` — a fragment shaped like an environment placeholder that the strict pattern rejects is now reported instead of surviving as literal text. `%env(default:KEY)%` — the default processor written with one colon instead of two — matched nothing and reached the consuming service as the uninterpreted string `%env(default:KEY)%`; resolution now fails and names the offending placeholder. The error context carries the placeholder text when it is spelled in key-grammar characters — it then names an environment key, never a value — and `%env(<redacted>)%` otherwise, since arbitrary pasted text in that position may be a credential.
- `wiring/` — a new package that renders container registrations from the source. `wiring.NewBindSet()` declares which packages to scan and how the scalar arguments of the constructors found there are filled; `melody:wiring:generate` walks those directories with `go/parser`, discovers every `NewX` constructor and writes a Go file registering each one — dependencies resolved from the container by type, scalars read from the configuration parameter they are bound to. Go cannot enumerate the types of a package at run time, and a package no one imports is not in the binary at all, so the scan that Symfony performs when it compiles its container is done here at build time; the generated file is ordinary source, which means an unfilled dependency is a compile error rather than a boot-time surprise. An argument name is bound on the constructor itself with a `//melody:bind name=parameter` directive, on the scanned package, or across every package, in that order of precedence, and
  `//melody:ignore` skips a constructor. Generation fails when no bind covers a scalar argument, and — when run through the command, which executes inside the application — when a bind points at a parameter the running configuration does not declare. A constructor the generator cannot wire (generic, variadic, returning more than a value and an error, returning only an error or `any`) is reported with its location and the reason rather than dropped silently, as is every declared bind that matched no argument — a `//melody:bind` directive that touched nothing included — and the full set of constructors each cross-package bind reaches; `--strict` turns the two losses — the skipped constructors and the untouched binds — into a failure. A file the default build excludes (`//go:build ignore`, the unsatisfied half of a tag pair, a foreign GOOS suffix) contributes nothing, matching the binary the wiring is generated for, and a qualifier the last path segment does not spell (`melody/v3`,
  `yaml.v3`, `go-redis`) resolves through the conventional package-name fallbacks. The emitted providers hold up at the edges: a non-pointer constructor returns a declared zero value on its error paths, a conversion narrower than the accessor's type is range-guarded into an error naming the parameter (through int64 where the bound overflows a 32-bit int), generated locals are renamed away from the closure parameters, the helpers and the import aliases so a constructor argument named after its package qualifier still compiles, and only the imports the emitted bodies use are written, the framework's own aliases reserved first so a scanned dependency on `melody/v3/config` cannot collide with them. A constructor returning a bare scalar is skipped as no service, `time.Duration` is recognized by its resolved import path rather than its spelled qualifier, a package-name guess two imports both produce — or one that lands on a base name two unnamed imports already contest — is added for
  neither, a file with a dot import leaves its unqualified types unrenderable rather than misattributed, and the generated file opens with the line-comment marker Go tooling recognizes. `//melody:service SomeConstant` additionally registers a service under the name its package already exports, referencing the constant rather than copying its value, so the name-based lookups a package exposes keep resolving once its registration moves to the generator.
- `container/resolver_implementing.go`, `container/contract/type_lister.go`, `container/register_option.go` — `container.AllImplementing[T](resolver)` resolves every registered service satisfying an interface: every type registration whose type implements it — one registered under the interface type itself included — and every instance of a type registered non-strictly under several names, which is the multi-instance pattern a by-type resolution would refuse as ambiguous. A component that must act on all of a kind — dispatching to every message handler, scheduling every cron task — collects them here instead of being handed a list assembled by hand, which is the list that goes stale when a service is added. The services resolve by their registered names through the resolver handed in, so a collection gathered on a request scope yields the scope's overrides; the service whose provider is doing the collecting — and only it — is excluded instead of failing the collection, so the composite
  dispatcher that is itself one of the handlers it dispatches to collects the others, the way a tagged iterator excludes its referencing service; a service deeper on the same resolution path stays in and fails as the circular dependency it is, since excluding it would freeze a collection whose content depends on boot order. A collection on a closed scope refuses the way the scope's own Get refuses, a negative priority sorts after every service that declared none, and a type-level match whose stored instance cannot satisfy the interface — a value provider behind a canonical pointer registration — aborts with a hint naming that cause. The order never changes between runs: descending `container.WithCollectionPriority` — a registration option for the services whose dispatch position matters — then type and name. A provider that fails aborts the collection rather than yielding a partial set. The enumeration is exposed through `contract.TypeLister` (`TypesImplementing` and
  `ReferencesImplementing`, the latter yielding one `contract.ServiceReference` per registered name), kept apart from `Resolver` so a resolver written outside the framework keeps working without it; the container, a request scope and the resolver a provider receives all implement it, and a closed scope enumerates nothing, mirroring `Has`.
- `application/application_container.go`, `application/contract/service_module.go` — `Application` is now a container registrar (`Register`, `MustRegister`), and `ServiceRegistrar` embeds `contract.Registrar`. A module registering services could previously only do so by name, which put the container's own typed helpers — `container.MustRegisterType` and anything generated on top of it — out of reach inside `RegisterServices`. A duplicate registration is still absorbed into the aggregated boot report whichever entry point produced it.
- `config/configuration.go`, `config/parameter.go`, `debug/command_parameter.go` — a parameter may be declared as holding a credential, through `RegisterSecretParameter` on the module registrar for one the application declares, or `MarkParameterSecret` for one melody registered automatically from the .env artifacts. `debug:parameters` then renders it as `********` — or `(empty)` when it carries no value, which is what an operator runs the command to find out — and reports the marking in a new `secret` column; the length is withheld along with the value, since on a short credential it narrows the search meaningfully. The marking travels with the value: a parameter whose template reads a secret becomes one itself — through a `%parameter%` reference and through `%env(KEY)%` alike, since the environment key is registered as a parameter under its own name and marking it is how a credential read that way is declared — so a dsn assembled from a declared password no longer prints in full
  beside the password that is redacted. The value reaching the services is untouched — this governs display, not storage. `MarkParameterSecret` leaves an absent name alone rather than failing the boot, since an environment key is legitimately undefined in some environments; the marking is retried before the configuration resolves — so it still propagates into the parameters whose templates read the secret — and once more at the end of the boot, where what still matches nothing is warned about, so a misspelled name is a visible signal instead of an unredacted credential. `Parameter.IsSecret` reads an atomic, since a marking may land while a consumer that already holds the parameter asks for it.
- `config/parameter.go`, `config/contract/parameter.go` — `Parameter.Duration()` and `Parameter.Float()` complete the accessor set alongside `Bool()` and `Int()`, converting from the native type or from the string an environment value always arrives as. Both report an unset parameter as a conversion error rather than yielding a zero value, and both identify a failure by environment key alone, keeping an inline credential out of the exception cause-context chain.

### Changed

- `config/contract/parameter.go`, `config/contract/configuration.go`, `application/contract/parameter_module.go`, `application/contract/service_module.go` — four contracts gained methods, which is a breaking change for a type implementing one outside the framework: `Parameter` gained `IsSecret`, `Float` and `Duration`; `Configuration` gained `RegisterRuntimeSecret` and `MarkSecret`; `ParameterRegistrar` gained `RegisterSecretParameter` and `MarkParameterSecret`; and `ServiceRegistrar` now embeds `container/contract.Registrar`. ### Fixed

- `container/container_close.go` — `Close` runs the teardown exactly once and a concurrent or repeated call blocks until it finishes and returns the same error, instead of a second caller reading the not-yet-assigned close error and reporting a premature success while services are still being torn down.
- `container/resolver_context.go`, `container/container_close.go`, `container/utility.go` — the resolution and shutdown keys are unique per type identity, not the type's `String()` which two same-named types from different packages share. A service resolving another such type by type no longer fails the boot with a spurious cycle, their creation guards no longer alias onto one entry, and the close-order graph no longer collapses them; the key carries the named type's import path, which a package's own type names cannot collide within. The type registration's auto-derived service name is import-path-qualified for the same reason, so two same-named types can both be registered by type.
- `config/configuration.go` — a parameter registered through `RegisterRuntime`/`RegisterRuntimeSecret` after the boot resolution is resolved against the configuration on registration, so a `%env(...)%` or `%parameter%` template registered late no longer reaches the consuming service verbatim; a pre-resolve registration is still resolved in the boot batch.
- `config/configuration_resolve.go` — `Resolve` holds the write lock the runtime accessors read under, closing the fatal "concurrent map iteration and map write" a post-boot `RegisterRuntime` racing it would otherwise trip.
- `application/application.go` — the cli exit code survives a wrapped exit error: `Run` walks the cause chain with `errors.As` instead of asserting the top type, so a command that returns an exit code together with a shutdown-close failure exits with that code rather than panicking.
- `validation/validator.go` — the validator validates exactly the fields a payload can populate, resolved with encoding/json's dominance rules, so the validator, the openapi mirror and encoding/json say the same thing across the whole class of unreachable fields. A field carrying `json:"-"` is skipped (a field literally named `-` is spelled `json:"-,"` and stays validated); a promoted embedded field shadowed by a shallower field with the same json name is skipped — its tag ran against a permanent zero value and rejected every request while the mirror rightly documented the winner alone; a name claimed ambiguously at equal depth is dropped entirely, as encoding/json drops it; an explicitly json-named field beats an untagged twin at equal depth; a diamond embed annihilates; and the exported fields promoted through an unexported embed are now validated, since a payload does populate them — a payload that omitted such a field satisfied the endpoint before and is rejected now, the one
  validator change in the stricter direction. The struct walk mirrors the openapi mirror's flattening (`openapi/schema.go` `collectStructFields`/`dominantEmbeddedField`, kept in lockstep), a validate tag declared on an exported promoted embed still runs against the embed value — its promoted fields are payload-populated, so the constraint is satisfiable — stacked diamond embeds are counted with the same cap-at-two encoding/json uses, and a nil pointer embed keeps its promoted names in the dominance while yielding nothing to validate.
- `security/hmac_token_source.go` — the replay-guard key encodes the key id's length. Key ids carry no charset restriction, so with a plain colon join the guard key of key id `a` with nonce `b:<n>` was identical to that of key id `a:b` with nonce `<n>`, letting one tenant pre-burn another key's nonces and force rejection of its legitimate requests. On a fleet sharing a persistent guard, an instance running the previous key format does not see nonces the new format records (and the reverse), so an envelope captured mid-rollout is replayable once within its expiry window — roll the fleet before the change carries production traffic.
- `openapi/schema.go` — a pointer string field carrying a `min` length is no longer advertised as required. The validator dereferences nothing when the property is omitted and accepts the payload, so the spec demanded a field the server does not: the required computation now leaves pointer fields to the pointer-bound rule that models them, exactly as `greaterThan`/`lessThan` already did.
- `application/boot_collision.go` — the boot-collision report names the user's registration call site again. The origin was read a fixed number of stack frames above the recording, a count the registrar delegation added for the generated wiring silently shifted, so every duplicate service was reported as registered at the framework's own delegation line; the origin is now the first frame outside the framework's registration plumbing, whichever path — name-based, typed or generated — recorded the duplicate.
- `config/configuration_resolve.go`, `config/configuration_validate.go` — template resolution is a positional left-to-right scan, the way Symfony resolves its parameters, replacing the escape-then-regex fixed-point passes. Each percent is decided in place — the `%%` escape for one literal percent, an `%env(...)%` placeholder, a `%parameter%` reference (a single-character name included, matching what the default processor's fallback accepts), or data, which is what a lone percent now is — and a referenced value is resolved recursively and spliced in as pure data, never rescanned. This fixes the values that were previously unwritable: an environment value holding a literal percent (`pa%%ss%%word` read through `%env(APP_PASSWORD)%`) and a dsn reading a password parameter whose value holds one both failed the boot with an `undefined parameter key` for `ss`, since the doubled-percent escape ran only on the entry template and substitution handed the injected text back to the pattern scan.
  Adjacent references (`%a%%b%`) resolve instead of the escape pre-pass swallowing the touching percents, and a self-reference — direct or through any chain of parameters and environment keys — is a circular-reference error at resolve time instead of surviving as literal text. A literal `%env(` stays data unless a well-formed placeholder closes it right there — the scan never reaches past a percent for a distant `)%`, which used to let the closer of a different placeholder turn the literal into a boot failure — while a misspelled placeholder that does close (`%env(FOO-BAR)%`) is still reported. The project directory is read as data wherever a template references it, a filesystem path with a percent in it being data by definition, and the kernel log-path validation no longer pattern-matches the resolved path, which after this scan can only carry a percent as data. Anything placeholder-shaped the scan cannot resolve is an error on the spot, so the after-the-fact unresolved-placeholder
  validation, which had to guess whether a percent was an escaped literal or a failure, is gone with nothing left to check.

## [v3.11.0] - 2026-07-17 - Lazy Service Resolution, SMTP Session Deadlines, Signal-Context Force-Exit and Runtime-Flag Scoping

### Added

- `container/lazy.go` — `container.Lazy[T](resolver, serviceName)` and `container.LazyByType[T](resolver)` return a `LazyService[T]` handle that defers resolving a service until its first `Get()` and memoizes success — a failed resolution is returned (or panics, for `Get()`) without being memoized and is retried on the next call, mirroring the container resolver, so a transient outage at first use does not poison the handle. A component assembled during the boot phase — a cli command, an http middleware — can hold a service whose provider is registered but not yet safe to resolve at that phase, without hand-rolling a `sync.Once` proxy for each one. `Resolve()` is the non-panicking variant.

A locker that cannot be resolved is reported through the contract — `CreateLock` returns a lock whose `Acquire`/`Release`/`Refresh` carry the resolution error — so `LeaderGate` and `RunExclusive` treat the outage as a retryable acquire failure and a later `CreateLock` retries the resolution.

The payload is written in fixed-size chunks with the deadline re-armed before each one, so the timeout bounds per-chunk progress rather than total transfer time: a large message on a slow-but-alive link completes regardless of its size, while a stalled peer still fails within one `Timeout`. Zero falls back to `DialTimeout`, then to the package default.
- `mailer/smtp_transport.go` — `SmtpConfig.DataTerminationTimeout` bounds the server's acknowledgment of the message-ending dot separately from the per-step `Timeout`. That one reply routinely runs the relay's content inspection and spam scoring (rfc 5321 allows it up to ten minutes), so capping it at the per-step ceiling turned a scanning relay into an error after the message may already have been queued — inviting a retry and a duplicate delivery. Zero derives four times the resolved per-step `Timeout`, raised to at least two minutes.

An app whose parameters all have defaults still boots without a `.env` — the hint is added only on an actual resolution failure. The detection behind the hint counts only a regular file — a directory named `.env` is not an environment file — and a stat error that cannot prove absence (a permission failure) suppresses the hint instead of misdirecting the operator; the `go run`

### Changed

- `application/boot_collision.go`, `application/application.go`, `application/application_container.go`, `application/application_cli.go`, `container/errors.go` — duplicate registrations now surface as ONE aggregated report at boot instead of one panic per run. Previously a consolidation that introduced several collisions (duplicate service ids, duplicate service types under the strict default, duplicate parameters, module configurations or cli command names) sent the developer around the fix-one-reboot-hit-the-next loop; the `Application.Register*` surface now records each duplicate (first registration wins for the remainder of the boot) and `Boot()` panics once, after the cli phase, listing every collision with the file:line of the registration that caused it. The container's raw `Register`/`MustRegister` and `Configuration.RegisterRuntime` keep their fail-fast behavior for direct callers, and any non-duplicate registration failure still panics immediately; the duplicate branches in
  `container.Register` now carry `errors.Is`-able causes (`container.ErrServiceIdAlreadyRegistered`, `container.ErrServiceTypeAlreadyRegistered`) with unchanged messages.
- `application/environment_warning.go`, `application/application.go` — boot now warns for every process environment variable whose name matches a known configuration parameter: melody deliberately reads configuration only from the `.env` artifacts (the application stays a black box), so such a variable is inert — the report's real-world case being an `APP_ROLE: web` set in docker-compose that consumers assumed was read while every container silently ran the outbox dispatcher. The known set is exactly the resolved parameter names, so `PATH`/`HOME` can never match; a variable whose value equals the resolved parameter value is skipped (platforms often mirror `.env` values); values are never logged. Log-only — behavior does not change.
- `config/configuration.go`, `application/application.go` — the misplaced-binary foot-gun is now diagnosable: melody derives the project directory from the executable location (the working directory only under `go run`), so `go run .` finds the `.env` artifacts but the same app built to `/tmp/app` and run from the same directory does not — and previously failed much later with an unsuggestive "undefined environment key". Boot now warns when zero environment keys were loaded (naming the searched `projectDirectory` and explaining the derivation), and the resolve failure carries `projectDirectory` in its error context. Log/diagnostic only — the lookup semantics are unchanged and documented in `CONFIG.md`.
- `security/totp/totp.go` — `Verify`/`VerifyAt` now strip whitespace anywhere in the submitted code before comparison (`"123 456"`, padded copy/paste, tabs and the non-breaking space mobile keyboards produce), mirroring the secret normalization that already handled spaces/dashes/padding/case. Whitespace can never be part of an all-digit code, so the tolerance is unambiguous; the comparison stays constant-time and dashes are untouched (they belong to recovery codes).
- `lock/run_exclusive.go`, `lock/leader_gate.go` — the session-probe path (non-positive ttl) now renews for twice the probe interval instead of the interval itself. A session locker ignores the ttl handed to `Refresh`, but a *lease* locker rewrites the lease to `now+ttl`: renewing for exactly the probe cadence made every probe race the expiry it had just written, so roughly every other probe found the lease gone — cancelling `fn` mid-run with "lost the lock lease", and, worse, genuinely letting the lease lapse so a second instance could acquire and run alongside the first. The positive-ttl path (refresh at `ttl/2`) always had this margin; session mode now matches it.
- `lock/run_exclusive.go` — a refresh in flight when the caller's context is cancelled is read as shutdown, not as a lost lease. A SIGTERM cancels the very runtime the refresh loop calls the backend with, so the in-flight `Refresh` fails with that cancellation; the shutdown check consulted only the `fn`-finished channel, so every graceful stop of a long-running exclusive command returned "exclusive run lost the lock lease while running" — an error a cron fleet reads as a failed run.
- `lock/run_exclusive.go` — a refresh already in flight when `fn` returns no longer wedges the call. `close(refreshDone)` cannot interrupt a `Refresh` blocked on an unresponsive backend, and the child-context `cancel()` was deferred until *after* `waitGroup.Wait()` — so a network partition during the last moments of a cron command hung the process forever, holding an unreleased lock. The cancel now runs before the wait, and a refresh that fails because of that cancel is read as shutdown rather than reported as a lost lease.
- `lock/run_exclusive.go`, `lock/leader_gate.go` — the derived refresh cadence is floored (`resolveRefreshSchedule`), so a ttl small enough to make `ttl/2` round to zero can no longer reach `time.NewTicker(0)`, whose panic on a background goroutine no `recover` can reach and which took the process down while holding the lock.
- `security/totp_second_factor_authenticator.go` — the two-factor replay guard keys on the normalized code (`totp.NormalizeCode`) rather than the raw header value. Because `Verify` treats `"123 456"` and `"123456"` as the same code, a guard keyed on the raw value would have recorded them as two distinct nonces, letting a captured code be replayed within its validity window by re-spacing it. Caught before release: both the whitespace tolerance and this key live in the same unreleased change.

### Fixed

- `openapi/schema.go` — the schema mirror's character-class scanner no longer treats `[.` and `[=` as POSIX collating and equivalence elements. RE2 supports only `[: :]` and reads a `[` inside a character class as a literal, so a valid tag such as `regex=[a,b[.c]` was mis-scanned as an unbalanced class: the rule split at the in-class comma and the field was advertised as accepting only the empty string, diverging from the validator (which scans only `[: :]`) and from `regexp.Compile`.
- `http/router_utility.go` — `isRequestFromTrustedProxy` unmaps an IPv4-mapped IPv6 CIDR in the trusted-proxy list before matching, mirroring `http/middleware/client_ip.go`. A mapped-form entry such as `::ffff:10.0.0.0/104` matched nothing against an unmapped IPv4 peer, so scheme detection distrusted a proxy the rate-limiter trusted, ignored `X-Forwarded-Proto` and dropped `Secure` from cookies set over a genuinely HTTPS request.
- `openapi/schema.go` — the schema mirror no longer treats `pattern` as an alias for `regex`. The validator registers no constraint by that name and fails the field closed for every value, while the generated spec advertised a satisfiable regex-constrained string: a contract the api rejects outright. Like any other rule this mirror does not model — a caller's custom constraint among them — `pattern` is now simply left out of the schema.
- `lock/leader_gate.go` — a graceful shutdown no longer fires `OnCampaignError`. Stopping cancels the very context the backend is called with, so the campaign in flight fails with that cancellation; reporting it handed every clean stop an error indistinguishable from a store outage.
- `http/middleware/pipeline/builder.go` — two definitions sharing a name no longer report a cycle. The Kahn traversal emits every duplicate a node carries, so counting the emitted definitions against the name-keyed node map found a mismatch for the very duplicates `allowDuplicates` exists to permit: `Build` returned "middleware pipeline has a cycle" and the application panicked on it. The sentinel now counts the nodes it drained.
- `http/router_utility.go` — `X-Forwarded-Proto` is read as the list it is. A chain of proxies appends rather than replaces, so the header arrives as `https, http`; returning it whole produced a scheme equal to neither `http` nor `https`, and every session cookie the response set silently lost its `Secure` attribute. The client-facing (leftmost) entry is now used.
- `config/environment_source.go` — a quoted `.env` value that spans lines survives preprocessing. The comment stripper tracked quote state per physical line, so from the second line on it believed it was outside quotes: a `#` in the value opened a comment and a blank line was dropped, silently truncating the value godotenv would then parse. A leading UTF-8 byte order mark is stripped too — `U+FEFF` is not whitespace, so nothing trimmed it and godotenv rejected the first key of every file an editor saved that way.
- `http/accept.go` — `PrefersHtml` honours the `Accept` header's quality values. It compared substring positions, so `text/html;q=0, application/json` — a client explicitly refusing HTML — was served HTML, as was any client that merely mentioned `text/html` first while ranking JSON higher.
- `http/middleware/client_ip.go` — IPv4-mapped IPv6 addresses are unmapped before use. A proxy writing the same client as `::ffff:1.2.3.4` keyed a different rate limit bucket than `1.2.3.4`, and an IPv4 CIDR in the trusted proxy list never matched a 4-in-6 peer.
- `application/cli.go` — stripping the runtime flags no longer eats the command's own next argument. `parseRuntimeFlagFromArguments` refuses to read a token starting with `-` as the value of a bare `--role`/`--mode`, but the stripper consumed it unconditionally, so `command --role --verbose` reached the command without `--verbose`.
- `openapi/schema.go` — the generator's bracket-balance mirror accepts a `]` that closes no character class, as the validator now does. RE2 reads such a `]` as a literal, so a rule like `regex(pattern=^a]b$)` passed validation while the generator's syntax guard read the tag as malformed and advertised the field as unsatisfiable (`minLength: 1, maxLength: 0`) — a spec that rejects every value the api accepts. The two helpers are documented as an exact mirror; they are one again.
- `http/kernel.go` — the panic-recovery path now closes the response it discards. When a panic unwinds while a file-backed response (a `FileResponse` or a static `ServeReader`) is already assigned but not yet written — a session backend blowing up inside `writeResponse`, before `WriteToHttpResponseWriter` registers the body's deferred `Close` — the recover handler replaced it with an error response and dropped the only reference to the open file. One descriptor leaked per such request.
- `http/router_utility.go` — a requirement declared on a catch-all wildcard (`/files/*path`) is now enforced when matching. The catch-all branch assigned the joined remainder to the parameter without ever consulting the compiled regex, while the single-segment wildcard and named-parameter branches enforced theirs — a whitelist that silently failed open.
- `http/url_generator.go` — a requirement declared on a catch-all wildcard (`/files/*path...`) is now enforced when generating, as it already is when matching. The catch-all branch emitted the value unchecked while the single-segment branch validated its own, so `GeneratePath` minted urls this very router answers with a 404 — and a traversal like `../../etc/passwd` passed the one whitelist meant to catch it.
- `http/static/utility.go` — the static file server opens the path it validated. It resolved symlinks with `filepath.EvalSymlinks`, confirmed the result stayed under the base directory, and then opened the *unresolved* path, re-following every symlink component at open time: an attacker who swapped a component between the check and the open was served a file from outside the base directory.
- `httpclient/http_client.go` — the redirect policy no longer reads the client's header map from the request goroutine while `SetHeader` writes it. `net/http` runs `CheckRedirect` on whichever goroutine is performing the request, and the policy iterated the very map `SetHeader` mutates under the client mutex: a concurrent setter during an in-flight redirect crashed the process with a fatal, unrecoverable `concurrent map iteration and map write`. The policy is now a method that takes the read lock.
- `httpclient/http_client.go` — credential headers attached to a single request with `WithHeader`/`WithHeaders` are stripped on a cross-origin redirect too. Only the client-wide headers were in the stripped set, so a per-request `X-Api-Key` was still handed to whatever host the first server pointed at — the same leak the policy exists to prevent. The caller's header names now travel to the policy on the request context.
- `httpclient/http_client.go` — `isSameOrigin` compares the *effective* port and folds host case, so `https://host` and `https://HOST:443` are one origin. A redirect that merely spelled out the default port, or changed the host's letter case, was read as leaving the origin and had its credentials stripped, breaking ordinary same-host flows.
- `httpclient/http_client.go` — the client installs a redirect policy that strips every credential it attaches once a redirect leaves the original origin (a different scheme or host). `net/http` strips only `Authorization`, `WWW-Authenticate` and `Cookie`, and only across domains, so a client configured with an api-key header (`X-Api-Key`, `X-Internal-Token`, …) handed that secret to whatever host the first server pointed it at. The ten-redirect cap is preserved.
- `httpclient/http_client.go` — `WithMaxResponseBodyBytes(math.MaxInt)` no longer returns an empty body. `int64(maxResponseBodyBytes)+1` wrapped negative, so `io.LimitReader` read nothing and reported no error; the bound now saturates.
- `httpclient/http_client.go` — `RequestStream` no longer runs under the client's whole-request `Timeout`, which bounds the body read as well and force-closed any stream that outlived it. The header phase stays bounded by the transport (dial, TLS handshake, response header); an explicit per-request timeout is still honored.
- `session/file_storage.go` — expired sessions are swept before every snapshot write. They were removed only when a `Load` happened to name that exact id, so they accumulated forever in memory and on disk — and since every `Save` rewrites the whole snapshot, the write cost grew with everything that had ever expired.
- `config/configuration.go`, `config/configuration_resolve.go`, `config/configuration_validate.go` — a value that escapes a literal percent with `%%` no longer fails boot. After resolution it legitimately reads `%NAME%`, which the post-resolution scan reported as an unresolved placeholder; parameters that used the escape are now exempt from that check.
- `validation/validation_rule.go` — a `]` outside a character class is treated as the literal RE2 reads it as, instead of failing the whole validation tag. A regex constraint containing one made its field emit an invalid-rule-syntax error on every request, regardless of input.
- `http/middleware/pipeline/builder.go` — `allowDuplicates` survives ordering. `selectDefinitions` kept both same-named definitions, then `orderDefinitions` rebuilt them into a map keyed by name and the second silently overwrote the first, so only one ever reached the built pipeline.
- `debug/command_container.go` — `debug:container` no longer panics on a large `--limit`. `startIndex + option.Limit` overflowed `int` and wrapped negative, producing an out-of-range slice bound.
- `debug/command_container.go` — the stack/trace redaction runs before the context is marshalled, so it also covers the two fallback paths. When `json.Marshal` or `json.Unmarshal` failed, the raw context was printed with `%v` — leaking exactly the trace and stack entries the sanitizer exists to strip.
- `exception/utility.go` — `BuildCauseContextChain` emits one entry per link in the cause chain. It read each level with `errors.As` (a deep search that jumps to the nearest `*Error`) while advancing the cursor a single level with `errors.Unwrap`, so a plain wrapper in front of an `*Error` repeated that error's context once per intervening level.
- `cli/output/table_builder.go` — `AddBlock` returns a builder that holds its owner and index rather than a pointer into the `Blocks` slice. A later `AddBlock` reallocated the backing array, so rows added through an earlier builder were written into memory nobody read and vanished from the table.
- `clock/frozen_clock.go` — `frozenTicker.Stop()` no longer closes the channel it handed out. `time.Ticker` (and so `systemTicker`) leaves its channel open forever, so a consumer selecting on a stopped ticker's channel busy-spun on the zero value from the closed one — the same `Ticker` interface with opposite semantics.
- `internal/parse.go` — `bag.Int` range-checks a `float64` before converting. Values outside the `int64` range converted to the indefinite value (`-9223372036854775808`) with no error at all.
- `internal/parse.go` — `bag.Float64` accepts an `int64`, matching `bag.Int` and `bag.Duration`, which already did.
- `mailer/smtp_transport.go` — the SMTP dial bounds the tcp connect, the TLS handshake and the server's opening greeting (new `SmtpConfig.DialTimeout`, defaulting to 30s). `smtp.NewClient` reads the 220 greeting synchronously with no deadline, so a server that accepted the connection and then said nothing pinned the sending goroutine and its socket indefinitely.
- `http/router.go` — a route parameter requirement is now wrapped in a non-capturing group before it is anchored (`^(?:...)$`). Alternation binds looser than the anchors, so a requirement like `en|de|fr` compiled to `^en|de|fr$` — which the regexp engine reads as `(^en)|(de)|(fr$)` — and matched `aden`, `frfr` and anything ending in `fr`. A requirement meant as a whitelist therefore failed **open**, both when matching an inbound path segment and when validating a value in `UrlGenerator.GeneratePath`, handing the handler a parameter it had been told was already validated. Note for consumers of the route manifest: the normalized requirement it publishes is now `^(?:\d+)$` where it was `^\d+$` — the same language, in Go and in JavaScript `RegExp` alike.
- `http/middleware/compression.go` — a negative `MinSize` is now normalized along with zero. Only `0` was replaced by the 1024-byte default, so a negative value reached `make([]byte, peekSize)` and panicked on every request routed through the middleware.
- `http/server_sent_event_hub.go` — the per-subscriber dropped-event counter is an `atomic.Uint64` instead of a bare `uint64`. A 64-bit atomic on a bare field requires 64-bit alignment; the field sat at offset 12 on a 32-bit build (`string` 8 + `chan` 4), so the first dropped event on a slow consumer panicked with "unaligned 64-bit atomic operation" on GOARCH=386/arm/mips. The hub-level counters moved with it.
- `exception/utility.go` — `BuildCauseChain` / `BuildCauseContextChain` clamp the capacity they preallocate. A caller passing a very large `maxDepth` made `make` request that many entries up front, so the allocation panicked with `makeslice: cap out of range` (or ballooned memory) before a single cause was walked; the walk still honors `maxDepth`, it just no longer trusts it as an allocation size.
- `cli/output/table_printer.go` — the table printer measures, pads and wraps every cell by rune count rather than byte length. A multibyte value (a diacritic, any non-ASCII text) counted each UTF-8 byte as a column, so wrapping sliced through a rune into an invalid sequence and padding over-counted its width, throwing every column after it out of alignment.
- `http/accept.go` — `PrefersHtml` takes an `Accept` entry's quality from the most specific range that matches it (RFC 7231 §5.3.2). A wildcard range with a higher `q` (`text/*` or `*/*`) previously outranked an exact `text/html`, so a client that spelled out `text/html;q=0` to refuse HTML was served HTML anyway.
- `http/router_utility.go` — scheme detection unmaps an IPv4-mapped IPv6 peer (`::ffff:a.b.c.d`) before testing it against the trusted-proxy list, so a reverse proxy that presents itself in 4-in-6 form is trusted and its `X-Forwarded-Proto` honoured. Without the unmapping the peer matched no trusted entry, the header was ignored, and every session cookie set behind such a proxy silently lost its `Secure` attribute — the same unmapping the client-IP resolver already does.
- `http/profiling_kernel.go` — the profiling listener emits the `http.request.profile` event whenever a request carries a request context, instead of skipping a request whose `Attributes()` is nil. A nil attribute bag is a normal state, not an absent context, so those requests silently went unprofiled.
- `http/middleware/client_ip.go` — `NewForwardedClientIpResolver` strips a `host:port` suffix from the untrusted `X-Forwarded-For` hop it returns. Proxies such as IIS/ARR and Azure Application Gateway append the client's source port, so the resolver read `1.2.3.4:52122` as unparseable and fell back to the trusted proxy's own address, collapsing every client onto one per-IP rate-limit bucket.
- `http/middleware/client_ip.go` — a trusted-proxy entry written in IPv4-mapped IPv6 form (an exact `::ffff:10.0.0.5`, or a `::ffff:.../104` prefix) again matches its unmapped host. The comparison unmaps both sides, so a dual-stack front proxy configured this way resumes hop-skipping instead of being treated as untrusted.
- `http/middleware/rate_limit.go` — the `TokenBucket` and `SlidingWindow` limiters clamp a non-positive window and a non-positive rate/limit. A missing or zero window otherwise disabled rate limiting entirely — a silent fail- **open** — and a negative rate denied every request; both now fall back to a sane floor.
- `http/middleware/rate_limit.go` — the default bucket key normalizes the request path exactly as the router does (trailing slashes trimmed), so `/login`, `/login/` and `/login//` share one bucket. Previously each trailing-slash variant keyed its own bucket, handing a caller a fresh allowance per spelling of the same route.
- `application/application_http.go` — `Application.OnHttpShutdown` panics when called after boot, matching the other registrars. A hook registered too late was previously accepted and then silently dropped, never reaching the http server.
- `application/application_http.go` — a panicking http shutdown hook is recovered and logged instead of crashing the process mid-shutdown. The panic otherwise skipped the graceful drain and container cleanup that run after the hooks.
- `application/application_http.go` — graceful http shutdown waits for the registered shutdown hooks to finish, bounded by the shutdown timeout, before the process exits. Websocket and Server-Sent Events handlers that a hook releases were otherwise cut off mid-flight when the process raced ahead of them.
- `httpclient/stream_response.go` — `StreamResponse.Body` and `Close` are mutex-guarded. A watchdog goroutine aborting an indefinite stream while the consumer read it raced the body field, and a `Close` that nilled it could leave the reader dereferencing a nil body; access is now serialized.
- `http/middleware/compression.go` — the gzip middleware ties its compression pipe to the request context and releases it when the request unwinds. A middleware sitting outside compression that panicked after the handler returned skipped the pipe's normal close, leaking the writer goroutine and the original response body's file descriptor on every such request.
- `security/hmac_token_source.go` — the HMAC internal-auth replay guard namespaces caller-chosen envelope nonces as `hmac:<keyId>:<nonce>`. When one shared `NonceGuard` backs several components, a raw nonce could collide with the TOTP two-factor guard's key space or another key id's nonces, letting a holder of any valid HMAC key pre-consume a victim's nonce and lock them out of two-factor; the namespacing isolates each.
- `debug/command_container.go` — `debug:container` truncates and wraps error/context cells on rune boundaries, so multibyte UTF-8 is no longer sliced mid-character and the table and JSON output stay valid UTF-8.
- `config/environment_source.go` — the dotenv preprocessor now follows godotenv's escaped-quote and value-start quoting rules. A backslash-escaped quote inside a quoted value no longer ends the quote early, so an interior `#` is not mistaken for a comment and the value is not truncated; and a stray quote or apostrophe in an *unquoted* value no longer flips cross-line quote state, which had dropped the comment-prefixed lines of a later quoted multiline value.
- `application/cli.go` — runtime `--role`/`--mode` parsing and stripping stop at a bare `--` end-of-options terminator, passing every token after it to the command verbatim. Previously the scan ran past `--` and could consume a following token as a runtime flag, panicking on an invalid value or stealing the command's own argument.
- `application/cli.go` — an explicitly present but empty `--role` (an `--role=` expanded from an unset env var, or a bare `--role` that cannot consume a dash-leading next token) now fails closed like any other invalid role instead of falling back to the most permissive `all`, which had silently widened the process.
- `httpclient/http_client.go` — concurrent `Post`/`Put`/`Patch` calls that share one caller-supplied options slice no longer race or swap bodies. `append`-ing the JSON body option to a slice with spare capacity wrote into shared backing storage, so two in-flight requests could hand each other's body to the wrong destination; the capacity is clamped before the append so each call gets its own array.
- `httpclient/http_client.go` — a negative configured timeout falls back to the 30-second default. A negative value reached `http.Client.Timeout` as-is, which `net/http` treats as no deadline at all, so a misconfiguration silently produced an unbounded client.
- `httpclient/http_client.go` — the credential-stripping redirect policy also removes the auto-generated `Referer` header on a cross-origin redirect. `net/http` derives the `Referer` from the previous request URL, so a secret carried in that URL's query string leaked to the redirect target even as the header credentials were being stripped.
- `http/url_generator.go` — URL generation rejects a slash inside a single-segment `:param` value instead of percent-encoding it. An emitted `%2F` decoded back to `/` at the server, so the generated path matched a different route or 404'd rather than round-tripping to the route it named.
- `http/url_generator.go` — a catch-all parameter's requirement is tested against the collapsed remainder actually emitted (non-empty segments joined by `/`), not the raw value. A value with interior double slashes the router accepts was otherwise refused by generation, which checked the requirement against a form the router never sees.
- `http/url_generator.go` — URL generation stops at a `*name...` catch-all and no longer appends trailing literal pattern segments, matching registration and routing, which treat the catch-all as terminal. Appending them minted URLs this very router answered with a 404.
- `cache/remember_in_flight.go`, `cache/remember.go` — a `Remember` single-flight late joiner no longer inherits a spurious `context canceled` error. The waiter-count decrement and the decision to cancel the shared call raced when the last waiter of a cancelable call timed out just as another joined; both now happen under the shard mutex, so the call is cancelled only when truly no waiter remains.
- `lock/in_memory.go` — the in-memory locker's counter uses an alignment-safe atomic, so it no longer panics with `unaligned 64-bit atomic operation` on 32-bit builds (`GOARCH=386/arm/mips`). A bare 64-bit atomic field needs 64-bit alignment the compiler does not guarantee on those platforms, so `CreateLock` — and every `RunExclusive`/`ExclusiveCommand`/`LeaderGate` campaign over it — crashed on first use.
- `lock/run_exclusive.go` — `RunExclusive` treats an acquisition aborted by a cancelled runtime context as a clean skip, not a store error. A graceful stop landing between a cron tick and its acquire otherwise returned an error and exited non-zero, which a cron fleet reads as a failed run.
- `lock/leader_gate.go` — the outage backoff cap holds at `max(one minute, RetryInterval)`, so a `LeaderGate` never retries a failed campaign faster than its configured `RetryInterval`. The cap previously clamped a longer `RetryInterval` down to one minute, campaigning more aggressively than asked.
- `lock/leader_gate.go` — `NewLeaderGateWithOptions` clamps a `RefreshInterval` override longer than half the lease ttl down to `ttl/2`. A longer interval let the lease expire before the first renewal, opening a window in which a second instance could win the lock and run alongside the incumbent.
- `validation/validation_rule.go` — the tag scanner recognizes a POSIX named character class, so a comma inside one (`regex=[[:alpha:],]`) no longer splits the tag. Such a pattern previously parsed as a truncated, invalid rule that rejected every value; it now compiles and validates as written.
- `config/configuration_resolve.go`, `config/configuration_validate.go` — placeholder resolution reports a circular reference instead of hanging. A self-referential or mutually-referential value (`APP_A=x%env(APP_A)%`) drove the resolver into unbounded recursion at boot; the cycle is now detected and surfaced as an error.
- `config/configuration_resolve.go`, `config/configuration_validate.go` — a placeholder-resolution boot error reports only the parameter name and the offending placeholder key, never the raw parameter value. The value can carry inline DSN credentials, which the previous message printed straight into the boot log.
- `container/resolver_context.go` — resolving a not-yet-created service by name or type snapshots the provider under the container lock. It previously read the provider registry with the lock released, so a concurrent registration racing the read could abort the whole process with Go's fatal `concurrent map read and map write`.
- `openapi/schema.go` — the generator no longer emits string `pattern`/`minLength`/`maxLength` facets on a `[]byte` (`format: byte`) field. The runtime validator ignores string constraints on such a field, so advertising them over-constrained a base64 payload the server in fact accepts.
- `openapi/schema.go` — numeric-bound parsing uses the same integer width as the validator, so a `min`/`max`/`greaterThan`/`lessThan` bound that overflows a 32-bit int fails closed in the generated spec exactly as the validator rejects it, instead of wrapping to a satisfiable facet the server would still refuse.
- `openapi/schema.go` — the generator marks a field `required` when the validator rejects the Go zero value (`min>=1` on a string, a non-pointer `greaterThan` bound `>=0` or `lessThan` bound `<=0`). A client that conformed to the spec and omitted such a property was otherwise rejected with a 400 the spec gave no warning of.
- `openapi/schema.go` — the generator's regex character-class scanner recognizes POSIX named classes (`[:alpha:]` and friends), so a `validate` tag such as `regex=[[:alpha:],]` is no longer mis-split at the in-class comma and the real pattern is advertised. Mirrors the validation-rule scanner fix.
- `http/cors/service.go` — a scheme-qualified wildcard allowed-origin (`<scheme>://*.suffix`, for example `https://*.example.com`) is recognized as a wildcard and matches an `Origin` only when the scheme is identical and the host is a subdomain of the suffix. Such patterns were previously not treated as wildcards and matched nothing; scheme-less patterns keep their existing scheme-agnostic host matching.
- `validation/validator.go` — `validate` tags on nested struct fields, slice/array elements, map values and embedded structs are now enforced rather than silently ignored, so the runtime matches the constraints the OpenAPI schema mirror already advertises for nested components. A nested violation fails the whole validation with a path naming the offending field (`items[0].sku`, `bill.sku`). The descent is depth-bounded and cycle-guarded so a self-referential payload terminates, and nil pointers/interfaces and unexported fields are skipped, so a previously-valid flat payload is unaffected.

## [v3.9.0] - 2026-07-06 - Cross-App Security, Route Manifest, Consumer Hardening and the Observability Seam

### Added

- `security/contract/actor.go`, `security/actor.go` — originating-actor propagation on the security token. A resolved `Token` can now carry an optional `Actor` (the upstream principal that started an action — a user, api-client or system — distinct from the authenticated transport principal carrying the request), readable through the new optional `ActorAware` interface (`OnBehalfOf() (Actor, bool)`). The core `contract.Token` interface is deliberately **not** widened — consumers type-assert `ActorAware` (helper `security.ActorFromToken`), so every existing `Token` implementation keeps compiling and an absent actor behaves exactly as before. `AuthenticatedToken` gains `NewAuthenticatedTokenWithActor` and reads an `OriginatingActor` from `Claims` (new serializable `contract.ActorData` carrier, since the `Actor` interface does not round-trip through JSON); the `security.Token` wrapper delegates `OnBehalfOf` to the wrapped token. This replaces per-product synthetic-principal hacks (e.g.
  minting a fake `wms-service` SSO identity with hard-coded roles) that caused role drift, letting service B authorize and audit as the originating actor X without X re-authenticating. An actor can additionally carry the admin acting behind it (optional `ActorImpersonating` interface, serialized through `ActorData.Impersonator`), which the impersonation work below uses to propagate an accountable impersonator across services.
- `security/hmac_token_source.go`, `security/hmac_signer.go`, `security/hmac_envelope.go`, `security/hmac_secret_provider.go`, `security/hmac_app_registry.go` — HMAC-signed internal-auth token source for service-to-service calls, promoting the per-product hand-rolled internal-header schemes into one shared melody implementation. The canonical transport is a single signed envelope (a JWT-like `header.payload.signature` triple over `crypto/hmac` SHA-256, reusing the existing `signHmacSha256`/`hmac.Equal` helpers): the payload binds the calling app name, the request method, path and query string, an issued/expiry window, a single-use nonce, a SHA-256 hash of the request body, and an optional embedded originating `Actor` (the F1 carrier). Putting every authorization-relevant field inside the one signed blob removes the separate-header canonicalization footguns and makes both the query string and the body tamper-evident. `NewHmacTokenSource(HmacTokenSourceConfig{...})` verifies an incoming
  envelope and resolves to an `AuthenticatedToken` whose principal is the calling service (roles from a configurable `HmacAppRegistry`) and whose `OnBehalfOf()` is the propagated actor; it fails closed to an anonymous token on any signature, endpoint, expiry, body-hash, unknown-app or replay failure (it reads and restores the request body for the downstream handler, and only after the signature has already verified, so an unauthenticated caller can never make the server buffer a body). `NewHmacEnvelopeSigner(HmacEnvelopeSignerConfig{...})` is the matching client-side helper both products use to produce the header. Secret rotation is seamless through `HmacSecretProvider` (`NewStaticHmacSecretProvider`) keeping several key ids resolvable at once — roll a new current key while the previous stays accepted, then drop it. Each key id is bound to exactly one application (provider entries are `HmacKey{App, Secret}`): the verifier refuses an envelope whose key id is not issued to the app it
  claims, so a holder of one valid secret cannot claim a higher-privileged app (and forge its actor) — a secret is only ever as privileged as the single app its key id is issued to. Because the key id is attacker-visible, `NewStaticHmacSecretProvider` also rejects the same secret bytes registered under key ids belonging to different apps, and the signer fails fast at construction if its current key id is not bound to the app it signs for. Replay protection is pluggable through the new `security/contract.NonceGuard`: `security/memory_nonce_guard.go` provides an in-process `MemoryNonceGuard` (single-instance/dev) and `integrations/rueidis` adds a shared Redis-backed guard for multi-instance deployments. Two verifier knobs harden replay handling: `MaxFutureExpiry` bounds how far ahead an envelope's expiry may sit — the nonce guard remembers a nonce until its envelope expires, so an unbounded expiry would let a holder of a valid secret pin unbounded memory in an in-process guard; zero
  keeps the horizon unbounded for callers that deliberately mint long-lived envelopes. `VerifyBodyBeforeNonce` selects whether the body hash is checked before the nonce is consumed, overridable per request through the `HmacVerifyBodyBeforeNonceAttribute` route attribute or `SetHmacVerifyBodyBeforeNonce(request, ...)`: body-first rejects a mutated-body replay *without* burning the nonce (closing an on-path denial where a captured header replayed with a tampered body burns a legitimate request's nonce), while nonce-first (the default) bounds body buffering from a captured envelope. Register the source with the existing `security/config.Builder.AddStatelessFirewall(...)`.
- `security/impersonation_token_source.go`, `security/impersonation_token.go`, `security/contract/impersonation.go` — switch-user / impersonation built on the actor primitive. `NewImpersonationTokenSource(ImpersonationTokenSourceConfig{Inner, Users, ...})` is a decorator over any primary token source: when the configured switch header (default `X-Switch-User`) names a target user, the resolved principal is authenticated, and it holds the switch role (default `contract.RoleAllowedToSwitch`), the application-supplied `contract.ImpersonatedUserResolver` resolves the target and the result is an `ImpersonationToken` whose visible principal is the impersonated user while the original admin stays readable through the new optional `Impersonating` interface (`Impersonator()`, helper `security.ImpersonatorFromToken`) so both identities can be audited. A precondition that means no impersonation was authorized in the first place — no switch header, an anonymous principal, or a principal without
  the switch role — leaves the caller's own token untouched and is logged. A precondition that fails *after* authorization (a switch-role holder whose target is unresolvable, or an impersonated user that is unknown/unauthenticated) instead fails closed to an anonymous token: the request was meant to run narrowed to the target, so continuing with the caller's own (broader) roles would execute it with privileges the operator believed were constrained to the impersonated user. A `RoleMode` selects whose roles the token authorizes with — `RoleModeImpersonated` (the default) takes on the target's roles for their full context, `RoleModeImpersonator` keeps the admin's own rights while acting in the target's context — set on the source config or directly via `NewImpersonationTokenWithRoleMode`. The token's `OnBehalfOf` originating actor now names the impersonated user while carrying the accountable admin (and the admin's roles) as an `ActorImpersonating` impersonator, so an impersonation
  started in one service stays auditable and the impersonator's roles propagate the whole flow and across services — the impersonator round-trips through the new optional `ActorData.Impersonator` carrier in the HMAC envelope (and `Claims`). As with the actor work, the core `Token` interface is not widened.
- `http/route_manifest.go`, `http/command_route_manifest.go`, `http/route.go` — frontend route manifest export so the frontend generates URLs by route name instead of hardcoding paths (the melody equivalent of a JS routing bundle). A route opts in by carrying `RouteAttributeExpose` (helper `http.ExposedRouteAttributes(zone)`) in its options attributes, optionally tagged with a `RouteAttributeZone` (`RouteZonePublic`/`Internal`/`Frontend`/`Client`). `BuildRouteManifest(router.RouteDefinitions())` projects the exposed, named routes into a stable `RouteManifest` DTO (name → pattern, methods, requirements, defaults, zone) — internal attributes and handlers are never exported, and entries are sorted by name for deterministic output. The new `melody:routes:manifest` CLI command (`NewRouteManifestCommand`) writes it to `--out` or stdout, with an optional `--zone` filter, and is auto-registered by the framework (see below). A small TypeScript helper (`v3/.example/assets/melody-routes.ts`,
  `RouteGenerator`) ships with the example — bundled into its frontend and available to vendor — loading the manifest and building paths from a route name plus params, matching the server's segment-anchored placeholder grammar (required `:param`, optional `:param?`, single `*wildcard` and catch-all `*name...`) so generated URLs agree with the Go URL generator; usage example in `v3/.example/assets/routes-usage.ts`.
- `application/application_cli.go`, `openapi/service_resolver.go`, `openapi/generate_command.go`, `messagebus/service_resolver.go`, `messagebus/consume_command.go` — the framework now auto-registers its core CLI commands the same way it registers the debug commands, so an application no longer wires them by hand. `melody:routes:manifest` is always available (it only needs the router); `melody:openapi:generate` and `melody:messagebus:consume` are exposed only when their feature is configured — detected by the presence of the backing service in the container (`ServiceOpenApiRegistry`, `ServiceTransports`) — so an application that does not use them sees no dead command. The two commands gain container-first constructors (`NewGenerateCommandFromContainer`, `NewConsumeCommandFromContainer`) that resolve their dependencies at run time; the explicit constructors are unchanged. New service keys let an application register those dependencies: `openapi.ServiceOpenApiInfo`,
  `messagebus.ServiceTransports` (with `RegisterTransports`), an optional `messagebus.ServiceConsumeBus` for a consumer bus distinct from the dispatch bus, and an optional `messagebus.ServiceRetryPolicy`.
- `messagebus/stamp.go` — `MessageIdStamp` and the `MessageId(envelope)` accessor: a generic, producer-assigned message id a transport can carry (for example as the AMQP message id) so a consumer can deduplicate redeliveries from an at-least-once producer such as the outbox relay. Mirrors the existing `RedeliveryStamp`/`DeadLetterAttemptStamp` accessor shape; transports opt in to serializing it.
- `security/totp/totp.go` — TOTP two-factor authentication (RFC 6238) implemented on the standard library only (`crypto/hmac`+`crypto/sha1`, `encoding/base32`), with no new dependency: `GenerateSecret`, `Verify`/`VerifyAt` (accepting a configurable step skew, constant-time comparison), `GenerateCodeAt`, `OtpauthURI` (the enrollment QR payload) and `GenerateRecoveryCodes`. Verified against the RFC 6238 known-answer vector.
- `security/totp_second_factor_authenticator.go`, `security/two_factor_pending_token.go`, `security/contract/two_factor.go` — second-factor integration that slots into the existing `AuthenticatorManager` without changing its first-match flow. `NewTotpSecondFactorAuthenticator(...)` decorates any primary `Authenticator`: once the primary credential is accepted and the application-supplied `contract.TwoFactorEnrollmentStore` reports the user has a TOTP secret, a valid code header (default `X-2FA-Code`) is additionally required; absent or invalid, the result is a non-authenticated `TwoFactorPendingToken` (readable through the new optional `TwoFactorPending` interface, helper `security.PendingUserFromToken`) so the application prompts for a code rather than treating the request as anonymous. An accepted code is bound to single use within its validity window through a replay guard (in-process by default, mirroring the HMAC source; supply a shared `NonceGuard` for multi-instance
  deployments). A single-use recovery code can be redeemed as an alternative to a TOTP code: when the application's enrollment store also implements the optional `contract.TwoFactorRecoveryStore` (`RedeemRecoveryCode`), a code supplied on the recovery header (default `X-2FA-Recovery-Code`, deliberately distinct from the TOTP header so the two never collide) is accepted and atomically consumed by the store, so each recovery code authenticates at most once; a store that does not implement the interface simply leaves recovery unavailable and TOTP verification unaffected. `v3/.example/twofactor/store.go` demonstrates persisting the secret and recovery codes encrypted at rest via bunorm `EncryptedString`, implementing the enrollment store (failing closed on a real lookup error rather than mistaking it for "not enrolled") and redeeming a recovery code atomically inside a transaction (load `FOR UPDATE`, constant-time match, consume, re-encrypt the remaining set).

- `application/contract/http_handler_decorator_module.go`, `application/application_http.go` — outermost observability seam: `Application.RegisterHttpHandlerDecorator` (and the optional `HttpHandlerDecoratorModule` module hook) wrap the fully built `nethttp.Handler` the http kernel produces, so a decorator observes every request — including 401/403 short-circuits produced by `kernel.request` listeners, listener-written responses and the panic-recovery path — none of which ever reach the middlewares (middlewares wrap only the routed handler). The first registered decorator is the outermost. The opentelemetry integration ships a ready-made decorator for it.
- `messagebus/consume_command.go` — scope-per-message consumption, mirroring the http kernel's scope-per-request idiom: each delivery now gets its own container scope carrying a message-scoped logger whose `messageId` context key is the envelope's `MessageIdStamp` value. Scope-based ambient state written by one handler (a security context, a logger override) previously landed in the single shared CLI scope and leaked into every other in-flight message when consuming concurrently; it is now isolated per delivery, and every log line of a delivery is correlatable by message id.
- `validation/contract/constraint.go` — new optional `ParameterizedConstraint` interface (`WithParams(params) (Constraint, error)`) so custom registered constraints can consume tag parameters. The five parameterized built-ins (`min`, `max`, `regex`, `greaterThan`, `lessThan`) now implement it, and `Validator.createConstraintWithParams` delegates through the interface instead of a hard-coded switch, opening the extension point without changing any built-in behavior.
- `event/contract/event_dispatcher.go`, `event/event_dispatcher.go`, `security/access_control_listener.go` — `RequiredListenerRegistrar`: an optional event-dispatcher capability to mark a listener *required*. When a listener stops event propagation before a required listener behind it (lower priority) has run, `Dispatch`/`DispatchName` now return an error so the http kernel fails closed (its existing `kernel.request` error path) instead of proceeding as if that listener had run — closing a foot-gun where a custom `kernel.request` listener that stops propagation without producing a response could silently skip the access-control listener and reach the handler unauthenticated. The security firewall marks its access-control listener required automatically, so any application using it is protected with no code change. A listener that deliberately short-circuits past required listeners opts out via `MarkListenerMaySkipRequiredListeners`. Both marks default off and the first listener error
  already aborted dispatch, so an unmarked dispatch is byte-for-byte backward-compatible. Documented in `.documentation/package/EVENT.md` and `SECURITY.md`, and demonstrated by a required listener in the example (`.example/config/event.go`). Added in lockstep across `v1`/`v2`/`v3`.

### Changed

- `version/version.go` — the ldflags-overridable `buildVersion` default is raised to `v3.9.0`; keeping it in step with the released tag is now a standing release-procedure step (builds without `-ldflags` previously reported a stale default).
- `container/scope.go` — resolving from a closed scope through the error-returning methods (`Get`, `GetByType`, `OverrideProtectedInstance`) now returns the `scope is closed` error instead of panicking, aligning them with the package's Must/non-Must convention (`lookupInstanceByName`/`lookupInstanceByType` already returned the same error for the same state, and the container itself returns a clean `container is closed` error). The `Must*` variants keep panicking. This matters for handler-spawned goroutines that outlive the request: the kernel closes the request scope when `ServeHttp` returns, and a panic in such a goroutine is covered by no recover — process death instead of a handleable error. Background work should still prefer `Container()` over a request-scoped `Scope()`. Aligned in lockstep with `v1`/`v2`.
- `security/memory_nonce_guard.go` — the expired-entry sweep is amortized (runs at most once per second) instead of on every `Remember`, so a high volume of distinct nonces no longer pays an `O(n)` sweep per call; correctness is unchanged (an expired entry is ignored by the per-nonce expiry check regardless of the sweep).

### Fixed

- `http/kernel.go` — the kernel now also fails closed when the `kernel.controller` event dispatch aborts with an error and no listener produced a response, mirroring the existing `kernel.request` fail-closed path: the dispatcher stops at the first failing listener, so a listener marked required through `RequiredListenerRegistrar` sitting behind a failing higher-priority `kernel.controller` listener never ran, yet the kernel logged the error and proceeded to the handler — a silent fail-open one lifecycle event past the `kernel.request` gate the primitive already closed. It now synthesizes a 500 instead. Fixed in lockstep across `v1`/`v2`/`v3`.
- `openapi/schema.go` — a negative `max` bound on a **nullable** string field (for example a `*string` carrying `validate:"max(value=-1)"`) is no longer advertised as fully unsatisfiable. `MaxLength.Validate` rejects every non-null value but passes a nil pointer (it dereferences to absent), so the validator still accepts null; the mirror now contradicts only the non-null value space (`applyEmptyValueSpace`) and preserves the `nullable` advertisement — matching the integer/number/boolean branch — instead of clearing `Nullable` and advertising a null the validator in fact accepts.
- `http/request.go` — the request wrapper now preserves the raw body of an `application/x-www-form-urlencoded` request across its automatic form parse. `NewRequest` auto-runs `ParseForm` for form content types, and `ParseForm` *consumes* a urlencoded body; the wrapper now buffers the body and restores `Body`/`GetBody` around that parse so a later reader still sees the true bytes. Without this the new HMAC internal-auth source — which reads the body *after* the auto-parse to verify the envelope's signed body hash — saw an empty body and therefore verified every form-encoded request against the hash of an empty body, silently accepting a tampered form body (the envelope's documented body-tamper-evidence was void for that one content type; JSON and other content types were already correct, and multipart bodies are deliberately left streamed so large-upload disk spooling is preserved). Found via live end-to-end testing of the internal-auth firewall. Fixed in lockstep with `v1`/`v2`.
- `openapi/schema.go` — closed two advertise-vs-enforce gaps in the OpenAPI generator against the validator's behavior: (1) a malformed or empty `min`/`max` value on a non-string field — integer, number, boolean, array, object or a `$ref` struct — is now advertised as unsatisfiable (null included), matching the validator which fails the rule closed and rejects every value before it is examined; previously only the string shape was handled, so a non-string field with e.g. `min=abc` was advertised satisfiable while the server rejected all input. A valid-but-restrictive bound (a negative `max`, a too-large `min`) is left to the per-kind handling, which preserves a nullable field's null since the constraint still accepts a nil pointer. When several length rules apply to one field the tighter ceiling wins (a later `max` no longer raises a lower `maxLength` set by an uncompilable-regex rule), and symmetrically a value-less `min` is now raise-only so it cannot lower a higher `minLength` floor
  an earlier rule already set (advertising the effective floor the validator enforces). (2) a `regex`/`pattern` whose value fails to compile is no longer emitted verbatim (an uncompilable pattern is invalid in the spec); the validator accepts the empty string and null for such a pattern and rejects only non-empty values, so the field is advertised with `maxLength: 0` (only the empty string) and its nullability preserved.
- `mailer/smtp_transport.go` — the plain/STARTTLS dial path now builds the SMTP client with the configured `Host` (raw `net.Dial` + `smtp.NewClient(conn, host)`) instead of `smtp.Dial(address)`, which derived the client server name from the address host. `startTls` already uses `Host` for the TLS SNI and `PlainAuth` is constructed with `Host`, so whenever `Host` differed from the address host (dialing by IP, through a tunnel, or a CNAME) `smtp.PlainAuth.Start` rejected the mismatch with "wrong host name" and authentication could never succeed. The implicit-TLS branch was already correct; the two paths now agree. The zero-value `SmtpConfig{Address}` path (Host derived from Address) was unaffected.
- `security/hmac_token_source.go` — the internal-auth envelope now signs and verifies the request query string (previously only method and path were bound), closing an asymmetry where an on-path attacker could tamper with query parameters of a captured, not-yet-consumed envelope even though the body was already tamper-evident.
- `security/hmac_token_source.go` — the nonce replay guard now rejects an envelope whose remaining acceptance window has lapsed to a non-positive ttl, instead of admitting it without recording the nonce (the guard does not store a non-positive ttl, which left an envelope at the very edge of the window replayable). The recorded window is now exactly as wide as the accepted one.
- `security/totp/totp.go` — recovery codes are now the documented `xxxxx-xxxxx` (six random bytes → ten base32 characters, 48 bits of entropy) rather than the `xxxxx-xxx` (eight characters, 40 bits) the five-byte draw produced.
- `.example/assets/melody-routes.ts` — the frontend `RouteGenerator` now matches the server's segment-anchored placeholder grammar (optional `:param?`, single `*wildcard`, catch-all `*name...`, and only treating a leading `:`/`*` as a placeholder), so routes using those forms generate correct URLs instead of emitting literal markers or throwing.
- `security/totp_second_factor_authenticator.go` — the second-factor replay-guard validity window is now computed overflow-safe and saturates to the maximum duration instead of wrapping. A pathological `Totp.Period`/`Skew` could overflow `time.Duration` to a non-positive value; because a `NonceGuard` does not record a non-positive ttl, the accepted code was then never remembered and replay protection was silently disabled. The window now stays strictly positive for any configuration. It is additionally derived through the new `totp.Config.Resolve` so it mirrors exactly the skew `Verify` accepts — in particular the `maxSkew` clamp: a misconfigured large skew previously remembered an accepted code for far longer than it stayed verifiable (an unbounded skew pinned the nonce entry in an in-process guard effectively forever), whereas the window is now capped to the clamped acceptance span.
- `security/impersonation_token.go` — `ImpersonationToken.Roles()`, `Scope()` and `Attributes()` now return defensive copies, matching the `security.Token` wrapper. Previously they handed back the impersonated token's underlying slice/map, so a caller could mutate the token's roles, scope or attributes in place.
- `security/in_memory_token_store.go` — the token store's claim clone now deep-copies the originating actor's nested `Impersonator` subtree (new recursive `cloneActorData` helper) instead of copying it as a raw pointer. The store's isolation guarantee (a caller mutating a stored or returned claim must not corrupt the other) already deep-copied the actor's own `Roles`/`Attributes`, but the actor-propagation work added `ActorData.Impersonator *ActorData`, which the shallow struct copy left aliased: a `Lookup` caller (or a caller mutating its claims after `Put`) could rewrite the stored impersonator's roles/attributes, and two concurrent `Lookup`s (only an `RLock` is held) shared the same `*ActorData`. The clone now recurses the entire impersonator chain.

- `messagebus/consume_command.go` — a panicking message handler is now recovered and converted into a dispatch error (new `dispatchSafely`, mirroring the recover-to-error contract the http kernel gives handlers), so it flows into the existing retry/redelivery/failure-transport pipeline. Previously no `recover()` existed anywhere on the consume path: a handler panic killed the worker goroutine and the process, the AMQP delivery stayed unacked and was broker-redelivered with an unchanged redelivery count, so `RetryPolicy.MaxRetries` never tripped and one poison message crash-looped every consumer replica indefinitely.
- `messagebus/consume_command.go` — the consumer worker goroutine now runs each delivery behind a panic barrier (`consumeRecovered`), so a panic raised *outside* the handler dispatch — in per-message scope setup, the transport `Ack`/`Nack`, or scope teardown — is logged and the worker survives, instead of the goroutine dying and silently shrinking the worker pool until the consumer stalls with no error surfaced. A handler panic is already converted into the retry pipeline by `dispatchSafely` (above); this backstops the rest of the per-message path (the in-flight delivery is left unacked and redelivered).
- `security/hmac_token_source.go` — internal-auth endpoint verification now guards a nil request `URL` before dereferencing its `Path`/`RawQuery`, failing closed with an error instead of panicking. Unreachable through the normal server path (a server-originated `*http.Request` always carries a non-nil `URL`) but reachable by an internal caller constructing a synthetic request.
- `security/totp/totp.go` — the verification step skew is now clamped to a small maximum (mirroring the existing 6–8 digit clamp). The verify loop runs `2*Skew+1` HMAC-SHA1 computations, so an unbounded misconfigured `Skew` turned every verification into heavy CPU work — and a skew near the `uint` maximum would additionally overflow the `int64` loop bound; a few steps already cover realistic clock drift.
- `security/hmac_envelope.go`, `security/hmac_signer.go`, `security/hmac_token_source.go` — the internal-auth envelope can now be bound to its intended callee service. `HmacEnvelopeSignerConfig.Audience` signs a target-service name into the envelope and `HmacTokenSourceConfig.ServiceIdentity` makes the verifier reject any envelope whose signed audience does not match, closing an on-path cross-service replay where a shared caller's captured header — valid method/path/body/nonce, and a nonce still fresh at a second service's independent guard — could be redirected to a different service that also trusts that caller and serves the same endpoint. Opt-in and backward compatible: a verifier with no `ServiceIdentity` does not check the audience, so envelopes minted before callers set one keep verifying; once set, callers must sign with a matching `Audience`.
- `security/impersonation_token_source.go` — the switch-user gate can now expand the admin's roles through the role hierarchy before checking the switch role (new optional `ImpersonationTokenSourceConfig.RoleHierarchy`), matching how the access-decision path authorizes: an admin granted the switch role transitively (via a role that implies it) is allowed to switch instead of being denied. Optional and backward compatible — a nil hierarchy checks the raw token roles as before.
- `security/totp_second_factor_authenticator.go` — documented on the config that failed-attempt throttling and lockout are the application's responsibility and must front this authenticator: the `ReplayGuard` blocks reuse of an accepted code but does not rate-limit a stream of distinct wrong guesses, so without an external rate limiter/lockout the 6-digit second factor is open to online brute-force once the primary credential is known.
- `validation/constraint_min_length.go`, `validation/constraint_max_length.go` — the min/max length constraints now count Unicode code points (runes) instead of UTF-8 bytes, matching the error text ("characters") and the OpenAPI `minLength`/`maxLength` facets (which are code-point based). Previously a multibyte value passed a byte-based minimum with fewer characters than required (a fail-open for a minimum-length check) and a code-point-valid value could be rejected server-side though the spec advertised it valid. Fixed in lockstep across `v1`/`v2`/`v3`.
- `http/kernel.go` — the kernel now fails closed when the `kernel.request` event dispatch aborts with an error and no listener produced a response: it synthesizes a 500 instead of proceeding to the handler. The dispatcher stops at the first failing listener (now documented on `event/contract.EventDispatcher`), so the listeners behind it — including the access-control listener at priority 20 — never ran, and continuing to the handler treated a partially-processed request as authorized (fail-open). A response set by an earlier listener (e.g. a 401 denial) still wins. Fixed in lockstep with `v1`/`v2`.
- `http/kernel.go` — the four response-finalization blocks now share one dispatch-error logging policy: the controller-event and handler-response blocks logged the `EventKernelResponse` dispatch error inline without the `AlreadyLogged` suppression the other two blocks apply through `logEventDispatchError`, so the same listener failure was logged twice on those paths (the dispatcher already logs `event listener error` once and marks the wrapper). The not-found-handler error fallback also gains the `PrefersHtml` HTML branch the other two error fallbacks already had. Fixed in lockstep with `v1`/`v2`.
- `http/router_utility.go` — `writeResponse` no longer panics on session persistence or response-write failures. It runs inside the kernel's already-consumed panic-recovery defer, where a `SaveSession`/`DeleteSession` panic escaped `ServeHttp` entirely: a session-backend outage degraded to connection resets instead of responses (happy path: first `SaveSession` panic → recovered 500 → `writeResponse` re-entry → second panic escapes to `net/http`). Session failures now log once and send the response without the session cookie (the session is intentionally not marked persisted); a response-write failure logs instead of panicking, since the headers may already be committed and no better response is possible. Fixed in lockstep with `v1`/`v2`.
- `http/router_utility.go` — logout now always expires the browser session cookie even when the session-backend delete fails. On the cleared-session path the `Max-Age: -1` clearing cookie was emitted only when `DeleteSession` succeeded, so a session-store outage during logout returned a normal response while the client kept a still-valid cookie pointing at a still-live server-side session — a fail-open logout. Clearing the cookie is independent of and strictly safer than the backend delete (it can only end a session, never resurrect an unpersisted one), so it is now sent regardless (the session is still not marked persisted); the save path, where suppressing the cookie on a failed `SaveSession` is correct, is unchanged. Fixed in lockstep with `v1`/`v2`.
- `validation/validator.go` — tag parameters on a constraint that cannot consume them now fail the rule closed (`invalid validation rule parameter`) instead of being silently discarded. Previously `createConstraintWithParams` returned the registered singleton for every non-built-in rule, so a custom constraint registered via `RegisterConstraint` and tagged `between(min=1,max=5)` validated with whatever the singleton was constructed with — no error, wrong validation. `openapi/schema.go` mirrors the new fail-closed case: parameters on a non-parameterizable built-in (`email`, `alpha`, `numeric`, `alphanumeric`, `notBlank`, `notEmpty`) advertise the field as unsatisfiable, keeping the advertise/enforce contract.
- `validation/constraint_greater_than.go`, `constraint_less_than.go`, `constraint_min_length.go`, `constraint_max_length.go`, `constraint_regex.go` — the built-in parameterized constraints now also fail the rule closed when a parenthesized tag carries parameters without the key they consume (`value`, or `pattern`/`value` for `regex`), instead of silently falling back to their registered default bound. A mistyped key such as `greaterThan(min=18)` validated as `> 0`, `min(len=8)` as `minLength 1`, and — worst — `regex(re=^\d{4}$)` fell back to the match-all `.*` default, leaving the field effectively unvalidated; each now returns `invalid validation rule parameter`. The shorthand form (`greaterThan=18`) is unaffected — the parser maps it to the `value` key — and a bare value-less constraint (`min`) still resolves to its default. This extends the fail-closed parameterized-constraint contract above from custom constraints to the built-ins themselves; `openapi/schema.go` mirrors it (
  `tagHasUnconsumedParameterizedParams` advertises such a field unsatisfiable) so the spec and validator stay in agreement. Fixed in lockstep across `v1`/`v2`/`v3` (the openapi mirror is `v3`-only).

Fixed in lockstep with `v1`/`v2`.
- `openapi/schema.go` — a `validate` tag whose parenthesized parameter lacks `=` (a stray-paren typo such as `min(5)`, `notEmpty(foo)` or `email(x)`) is now advertised as unsatisfiable, matching the validator. The runtime `parseValidationTag` rejects such a tag with a value-independent `invalid validation tag syntax` error before any value is examined, so the field accepts no value (null included); the generator's more lenient `splitRule` silently dropped the malformed pair and emitted a satisfiable schema, so the documented endpoint could never be satisfied while the spec claimed it could. Completes the fail-closed advertise/enforce mirror alongside the
  malformed-numeric-bound and uncompilable-regex cases.
- `security/in_memory_token_store.go` — the recursive originating-actor clone (`cloneActorData`) is now depth-bounded (`maxActorImpersonationDepth`, mirroring `internal.maxCopyDepth`). Because `ActorData.Impersonator` is an exported pointer field, an in-process caller can build a cyclic impersonator chain (`actor.Impersonator = actor`) and `Put`/`Lookup` it, driving the clone into unbounded recursion until the goroutine stack overflows — a fatal error no deferred `recover()` can catch, taking down the whole process. The clone now stops following the chain at the bound (dropping the truncated link rather than aliasing it), so a pathological or cyclic chain terminates cleanly while every realistically-shallow chain stays fully deep-copied. Defense-in-depth: a JSON-decoded actor is already bounded and acyclic.

Because `ActorData.Impersonator` (and an `Actor`'s `Impersonator()`) are reachable through the exported field, an in-process caller can build a cyclic or pathologically deep chain; without the bound, rebuilding one (`NewActorFromData`, on the HMAC decode path) or serializing one (`ActorToData`, on the sign path) recursed until the goroutine stack overflowed — a fatal error no `recover()` can catch. A JSON-decoded actor is additionally capped by `encoding/json`'s nesting limit.

### Added

- `messagebus/` — transport-agnostic asynchronous message bus. Messages are wrapped in `Envelope`s carrying `Stamp`s (`BusNameStamp`, `SentStamp`, `ReceivedStamp`, `HandledStamp`); a configurable middleware stack via `NewManager(name, ...Middleware)` with `NewSendMessageMiddleware(routingByType)` (routes typed messages to a transport) and `NewHandleMessageMiddleware(locator)` (dispatches to handlers — a message with no registered handler is logged as a warning so the loss is observable, and `NewHandleMessageMiddlewareWithOptions(locator, HandleOptions{RequireHandler: true})` turns that into an error so a forgotten registration fails loudly instead of being acked and discarded); typed handler registration through `NewHandlerLocator` plus generic `RegisterHandler[T]`; an in-process `NewInMemoryTransport(bufferSize)`; and a long-running `melody:messagebus:consume` command via `NewConsumeCommand(bus, transports)`. The consumer owns the retry policy:
  `NewConsumeCommandWithRetry(bus, transports, RetryPolicy{MaxRetries, BaseDelay, FailureTransport})` requeues a failing message with an incremented `RedeliveryStamp` (and an optional backoff `DelayStamp` for delay-aware transports) up to `MaxRetries`, then routes the exhausted message to a dead-letter `FailureTransport` if configured — and if that `FailureTransport.Send` itself fails the message is requeued on the source rather than acked-and-lost — or otherwise nacks it without requeue so a transport-native dead-letter (e.g. the AMQP DLX) can claim it rather than dropping it silently; `NewConsumeCommand` defaults to three retries. The `messagebus/contract.Transport` interface (`Send`/`Receive`/`Ack`/`Nack`/`Close`) lets durable backends plug in (see the `amqp` integration); `Close` releases a transport's consumption resources and is idempotent. Transport lifecycle is owned by the application, not the consume command (see the `### Changed` note below) — `Close` is called by the
  application during shutdown, not by the consumer.
- `security/` — stateless bearer-token authentication for APIs. `NewBearerTokenSource(validator)` extracts an `Authorization: Bearer <token>` header and delegates to a pluggable `securitycontract.TokenValidator`. Two validators ship: `NewJwtTokenValidator(JwtConfig)` (dependency-free HS256 verification with constant-time signature comparison, a required `exp` claim by default — opt out with `JwtConfig{AllowWithoutExpiry: true}` so a missing `exp` never silently yields a non-expiring token — plus `nbf`/`iat` checks with configurable leeway and optional `iss`/`aud` enforcement, mapping the subject and roles claims to `Claims`; out-of-range or non-finite `NumericDate` claims are rejected as malformed instead of saturating on the int64 conversion) and `NewOpaqueTokenValidator(store)` backed by a `securitycontract.TokenStore` (`NewInMemoryTokenStore` ships for tests/dev) for revocable tokens — the in-memory store adds `DeleteByUser` (sign-out-everywhere) and `PurgeExpired` (janitor cleanup)
  on top of per-token `Delete`. `NewJsonEntryPoint()` (401, with a `WWW-Authenticate: Bearer` challenge header per RFC 7235) and `NewJsonAccessDeniedHandler()` (403) return JSON instead of redirecting, for pure-API firewalls; `security/config.FirewallOverrideConfiguration` gains `WithEntryPoint`/`WithAccessDeniedHandler` so a single API firewall can answer with JSON while the global web firewall keeps redirecting. The `security` service resolver also exposes `FirewallManagerFromResolver`/`FirewallManagerMustFromResolver` to match the other modules. For applications that resolve roles after the token is validated, `Claims` carries generic `Scope`/`Attributes` maps (the JWT validator can populate `Scope` from a configurable `JwtConfig.ScopeClaim`), and `NewBearerTokenSourceWithEnricher(validator, enricher)` runs a generic `securitycontract.TokenEnricher` after signature validation to turn that scope into the final roles/attributes (e.g. via a database lookup) — tenant- or
  product-specific resolution lives in the application's enricher, the library stays generic; an enrichment failure falls back to an anonymous token. `Claims` carries explicit `json` tags because a persisted token store (the `integrations/rueidis` Redis store) serializes it as JSON and its Lua index reads the `UserIdentifier` key back — the tags pin that wire contract so a later field rename cannot silently break the per-user token index.
- `translation/` — i18n message catalogs. `NewManager(defaultLocale, fallbackLocales, ...Catalog)` resolves a message id by domain/locale with fallback-chain lookup; `NewMapCatalog(locale)` for in-code messages and `NewJsonDirectoryLoader(directory)` to load `<domain>.<locale>.json` files; an ICU-subset message formatter supporting `{placeholder}`, `plural`, and `select` blocks with per-locale plural rules (recursion depth-guarded against pathological catalog strings); a plural argument that is missing or non-numeric resolves the `other` branch with an empty `#` rather than being treated as the number zero.
- `openapi/` — OpenAPI 3.0.3 generation from route metadata. `NewRegistry()` plus `Describe(routeName, Descriptor)` associates request/response Go types with routes; the generator reflects struct types into JSON Schema (honoring `json` and `validate` tags, with cycle detection) and emits a `Document`; `NewGenerateCommand(info, registry)` writes the spec to stdout or a file. Named struct types are emitted once into `components/schemas` and referenced by `$ref` (deduplicating types reused across operations); pointer fields are marked `nullable`; the fields of an untagged embedded struct are promoted into the parent as encoding/json does; `min`/`max` emit `minLength`/`maxLength` on string fields only — matching what the framework validator actually enforces (`min`/`max` are string-length checks) so the generated spec never advertises a numeric or collection bound the server does not enforce — while `greaterThan`/`lessThan` emit an exclusive `minimum`/`maximum`; and the `Document`/`Schema`
  types now carry `servers`/`security`/`tags`/`externalDocs` and `description`/`maximum`/`exclusiveMaximum`. `service_resolver.go` registers the registry as a first-class container service (`ServiceOpenApiRegistry`, `RegistryMustFromContainer`/`RegistryMustFromResolver`) so the module wires like the others, and `SpecHandler(info, registry)` serves the document as JSON from a live route (e.g. `GET /openapi.json`) by reusing `Generate` against the running router — every instance behind a load balancer serves the same spec from its identical route table.
- `lock/` — distributed/named lock abstraction. `lock/contract.Locker`/`Lock` (`Acquire`/`Release`/`Refresh`); a dependency-free `NewInMemoryLocker(clock)` with token-owned, TTL-aware, reentrant locks. Durable backends implement the same contract — Redis (`integrations/rueidis/v3`, TTL auto-expiry) and MySQL `GET_LOCK` (`integrations/bunorm/mysql/v3`); note that MySQL advisory locks are connection-lifetime and do not auto-expire, so their `ttl` is documented as not honored as an expiry (the lock releases on `Release` or connection drop).
- `mailer/` — pluggable email sending. `mailer/contract` (`Mailer`, `Transport`, `Message`, `Address`, `Attachment`); `NewManager(transport)` validates sender and recipients; `NewSmtpTransport(SmtpConfig)` (stdlib `net/smtp`) and `NewInMemoryTransport()` for tests. The SMTP transport opportunistically STARTTLSes, and `SmtpConfig` adds `RequireTls` (fail closed unless the connection is encrypted, closing the silent-downgrade hole), `RequireAuth` (fail closed when a username is configured but the server does not advertise the AUTH extension, rather than delivering unauthenticated), `ImplicitTls` (dial straight into TLS, the smtps/465 convention) and a `TlsConfig` override. `RenderMessage` builds RFC 5322 / MIME messages: quoted-printable bodies (kept within the SMTP 998-character line limit), `multipart/alternative` for text+HTML, `multipart/mixed` with base64-encoded attachments, CRLF-stripped headers/addresses, reserved-header filtering so callers cannot override the structural
  headers, and RFC 2047 encoded-words for non-ASCII subjects and display names (RFC 2231 for non-ASCII attachment filenames) so international text survives transport.
- `storage/` — object-storage abstraction. `storage/contract.Storage` (`Put`/`Get`/`Delete`/`Exists`/`PresignedUrl`); a `NewLocalStorage(baseDirectory)` filesystem backend that confines every key operation to the base directory via `os.Root` — each path component is checked against symlink escape as the operation runs (not validated up-front and used later), so neither a leaf symlink nor a symlink planted at an intermediate directory component can redirect a read or write outside the base. The base directory is created lazily on first write, and objects are written with restrictive `0o640`/`0o750` permissions. An S3-compatible backend ships in `integrations/awss3/v3`.
- `http/server_sent_event.go`, `http/server_sent_event_hub.go` — Server-Sent Events. `NewServerSentEventWriter(w)` streams `text/event-stream` (sets the headers and flushes after every `Send`); `NewServerSentEventHub()` is a topic-keyed fan-out (`Subscribe`/`Unsubscribe`/`Broadcast`) with **at-most-once** delivery — a full subscriber buffer drops the event, and `DroppedEventCount()` exposes the cumulative loss as a metric. `Shutdown()` drains and closes every subscriber channel so in-flight handler loops exit during a graceful server stop, and `ServerSentEventWriter.Ping()` writes a keepalive comment that a handler can drive from a ticker to hold idle connections open through intermediary proxies. `ServerSentEventSubscriber.DroppedCount()` exposes the per-subscriber dropped-event count so a handler can detect and close a persistently slow subscriber. For load-balanced deployments the hub takes an optional `ServerSentEventBackplane` (`SetBackplane`): `Broadcast` then fans out to local
  subscribers via `DeliverLocal` **and** replicates to the other instances through the backplane, which calls `DeliverLocal` for events other instances publish — so a client connected to any instance receives every broadcast. A nil backplane keeps the original local-only behaviour; `BackplaneFailures()` counts replications that could not be published. Concrete backplanes ship in `integrations/rueidis` (Redis pub/sub) and `integrations/amqp` (fanout). The same hub backs the WebSocket integration, so both transports fan out across instances.
- `security/` — `AuthenticatedToken` now carries the enriched claims beyond roles: `NewAuthenticatedTokenFromClaims` populates `Scope()` and `Attributes()` (both returning defensive copies) so a `TokenEnricher` can attach tenant/attribute data that attribute-based access control reads downstream — previously only roles survived enrichment and the rest was silently dropped.
- `messagebus/` — the `melody:messagebus:consume` command gains a `--concurrency` flag (N worker goroutines reading the transport concurrently; per-transport Ack/Nack stay serialized) and a bounded graceful-drain window configurable via `ConsumeCommand.WithShutdownGrace(d)`: after an interrupt the consumer waits up to the grace period (default 30s) for in-flight handlers to finish, then stops waiting so a wedged, non-context-aware handler cannot block shutdown indefinitely.
- `mailer/` — `RenderMessage` now emits a unique RFC 5322 `Message-ID` header (random local part + the sender's domain) unless the caller already supplied one in `Headers`.
- `messagebus/` — generic routing builder `NewRouting()` + `RouteType[T](routing, name, transport)` (and `NewSendMessageMiddlewareFromRouting`) so a dispatch bus is wired without hand-writing the `map[reflect.Type]TransportRouting` literal and `reflect.TypeOf` keys; the existing map-based `NewSendMessageMiddleware` is unchanged.
- `http/` — `JsonHandler[Req](handle, ...options)` wraps a handler that needs a JSON body: it decodes the body into `Req`, runs the container validator, and on failure returns an error (or a caller-supplied shape via `WithJsonHandlerErrorResponder`), so per-handler decode/validate boilerplate collapses to the typed `handle` function.
- `openapi/` — `DescribeTyped[Req, Resp](registry, routeName, status, ...options)` describes a route's request/response from Go types via `WithSummary`/`WithDescription`/`WithTags`/`WithResponse[T]`, removing the `Descriptor{RequestType: TypeOf[…](), Responses: map[int]reflect.Type{…}}` literal; the existing `Describe` is unchanged (still used for no-body or multi-response routes).
- `container/` — documented that type registration is on by default, so any registered service is resolvable by its contract type via `MustFromResolverByType[T]` — a single-implementation service needs no string-name constant or per-type accessor (named registration remains for coexisting multi-implementation contracts, which are strict).
- `validation/` — `lessThan` constraint (`NewLessThan(max)`, the `LessThan` type, and the `ConstraintLessThan` registration). A field tagged `validate:"lessThan(value=N)"` (or the shorthand `validate:"lessThan=N"`) now enforces an exclusive upper bound on numeric fields, mirroring the existing `greaterThan` lower-bound constraint and the exclusive `maximum`/`exclusiveMaximum` the `openapi` generator already emits for it.
- `httpclient/transport_config.go` — `TransportConfig` (`DialTimeout`, `KeepAlive`, `MaxIdleConns`, `IdleConnTimeout`, `TlsHandshakeTimeout`, `ExpectContinueTimeout`, `ResponseHeaderTimeout`) with `DefaultTransportConfig()` exposes the previously-hardcoded `net/http.Transport` tuning of the HTTP client. Set it via the new fluent `HttpClientConfig.WithTransport(*TransportConfig)`; zero fields inherit the defaults, and a client built without it keeps the previous behaviour unchanged (backwards compatible).
- `application/` — the HTTP graceful-shutdown grace period (previously a hardcoded `5s`) is now overridable: a `Configuration` that also implements the optional `HttpShutdownConfiguration` (`GetShutdownTimeout() time.Duration`) sets it, mirroring the existing `HttpTimeoutConfiguration` mechanism; a zero or absent value keeps the 5s default (backwards compatible).
- `messagebus/` — `RetryPolicy` gains optional `MaxDelay` (the exponential-backoff cap, previously a hardcoded 1h) and `FailureRequeueDelay` (the fallback requeue delay when no `BaseDelay` is set, previously a hardcoded 5s); zero keeps the previous defaults, so existing `RetryPolicy` values are unaffected (backwards compatible).
- `application/` — `Application.RegisterModuleProvider(provider)` plus activation of the (previously dormant) `application/contract.ModuleProvider` inside `RegisterModule`: a module that also implements `ModuleProvider` now contributes its child modules in the same call, so an integration or application can register a whole group of capability-modules at once. Every Melody v3 integration now ships a self-registering module exposed through its `NewModule(ModuleConfig{...})`, wired with a single `app.RegisterModule(...)` call instead of hand-calling the individual `Register*` helpers (see each integration's CHANGELOG); `HttpMiddlewareModule` joins the public module contracts (`Module`, `ModuleProvider`, `ParameterModule`, `ServiceModule`, `HttpModule`, `CliModule`, `EventModule`, `ConfigModule`). Existing single-module registration is unchanged.

### Changed

- the `v3` module now requires **Go 1.25** (raised from 1.22). The `storage` local backend uses `os.Root` (Go 1.24) and `os.Root.MkdirAll` (Go 1.25) to confine filesystem operations to the base directory without a check-then-use window (see `### Fixed`). The `v3` integration modules and the example already build on Go 1.24+/1.25, and Go's toolchain auto-download fetches a matching toolchain for consumers transparently (unless `GOTOOLCHAIN=local`).
- `security/` — `JwtConfig` gains `RejectFutureIssuedAt` (default `false`). A future `iat` is no longer rejected by default (RFC 7519 treats `iat` as informational, and the previous strict check false-rejected tokens from issuers whose clocks ran ahead of the verifier's leeway); set the flag to restore strict rejection. The contract adds a `RevocableTokenStore` interface (`TokenStore` plus `Put`/`PutWithTtl`/`Delete`/`DeleteByUser`/`PurgeExpired`) so a custom revocable store can be swapped in through the interface rather than only the concrete `InMemoryTokenStore`.
- `messagebus/` — the consumer no longer calls `Close` on the transport it was handed; transport lifecycle is owned by the application (the process exit releases AMQP connections), so a transport shared between the dispatcher and the consumer is no longer disabled when the consume command returns. The in-memory transport now honors a `DelayStamp` on requeue (delayed re-push instead of an immediate hot retry). The retry backoff is capped (`maxRetryDelay`) and overflow-safe.
- `security/` — the `securitycontract.Token` interface gains `Scope() map[string]any` and `Attributes() map[string]any` so the enriched scope/attribute claims a `TokenEnricher` attaches are readable through the contract for attribute-based access control downstream — previously only `*AuthenticatedToken` carried them and a consumer holding a `Token` had to type-assert. `AnonymousToken` returns empty maps and the `Token` wrapper delegates to the wrapped token. (Additive method on an exported interface — external `Token` implementers must add the two methods.)

### Fixed

- `http/kernel.go`, `http/router_utility.go`, `http/response_writer.go` — a streaming handler (for example one driving `NewServerSentEventWriter`) that writes its own response and returns `(nil, nil)` no longer triggers a superfluous `WriteHeader` call. The kernel synthesized a default `204 No Content` for every nil response and wrote it unconditionally, so after a Server-Sent Events handler had already committed its `200` stream the kernel re-wrote the header on connection teardown — emitting a `net/http` "superfluous response.WriteHeader call" warning once per stream close. The kernel now wraps the response writer in a recorder that tracks whether the headers were committed, and `writeResponse` skips writing whenever the response headers were already committed, so a streamed response is never followed by a superfluous `WriteHeader` — whether the handler returned no response or failed after committing the stream. The recorder forwards `http.Flusher`, `http.Hijacker` and
  `io.ReaderFrom` and exposes `Unwrap`, so streaming, WebSocket upgrades (which type-assert the writer to `http.Hijacker`) and the file-serving sendfile fast path keep working through the wrapper. (Under HTTP/2 the underlying writer is not an `http.Hijacker`, so that assertion is optimistic and the `Hijack` call returns an error, handled like a missing capability; `http.Pusher` is deliberately not forwarded, as HTTP/2 server push is deprecated.) Because `net/http`'s `MaxBytesReader` detects the server response through an unexported-method assertion that does not follow `Unwrap`, the per-request body limiter is given the raw writer rather than the recorder, so an oversized request body still triggers the connection-close signal; and `Flush` records the header commit, but only when the underlying writer actually supports flushing, so a flush-only streaming handler is likewise recognised as having committed its response. The recorder also marks the response committed only when `Hijack`
  actually succeeds, so a handler that attempts a hijack which fails (and returns no response) still receives a default response rather than an empty one. When a handler commits its own response yet still returns one — or the kernel synthesizes an error response after a stream-then-panic — `writeResponse` now closes that discarded response body before skipping the write, so a `FileResponse` returned alongside a self-written stream no longer leaks its open file descriptor. Regression coverage in `http/kernel_test.go` and `http/response_writer_test.go`.
- `http/router_utility.go`, `http/response_writer.go` — `writeResponse` no longer persists the session twice when the response write fails after the headers were committed. `writeResponse` persists the session (`SaveSession`/`DeleteSession`) and then writes the response; if the write fails after the headers were committed it panics, the panic-recovery path re-enters `writeResponse`, and because `SaveSession` does not reset the session's modified flag the session store was written a second time. The recorder now tracks whether the session was already persisted for the request (`SessionPersisted`/`MarkSessionPersisted`) and `writeResponse` persists it at most once — the header-commit flag cannot gate this, as a handler that streamed its own response still needs its session persisted on that first, already-committed call. Regression coverage in `http/kernel_test.go` (`TestKernel_DoesNotDoublePersistSessionWhenWriteFailsAfterCommit`).
- `http/response.go` — `FileResponse` (and `AttachmentResponse`, which delegates to it) now resolves a served file's `Content-Type` through the same built-in fallback table the static file server uses, so a file with an extension the operating-system MIME database does not register (for example a `.ico` favicon or a web font on a minimal system such as Alpine) is served with an accurate type rather than no `Content-Type`. Previously only the static `FileServer` carried the fallback; the helper path called `mime.TypeByExtension` directly. Regression coverage in `http/response_test.go`.
- `http/static/file_server.go` — the static file server now resolves an asset's `Content-Type` through a built-in fallback table of common web types (`.ico`, `.svg`, `.css`, `.js`, web fonts, `.wasm`, …) for extensions the operating-system MIME database does not register. On a minimal system (for example Alpine) `mime.TypeByExtension(".ico")` returns empty, so a served favicon previously fell through with no `Content-Type` and defaulted to `text/plain`; it is now served as `image/x-icon`. Regression coverage in `http/static/file_server_test.go`.
- `http/kernel.go` — the per-request service-container scope is now closed even when request-logger setup fails. The `scope.Close()` defer was registered *after* `requestIdLogger`, so a panic during logger resolution (a nil base logger, or a failed protected-instance override) unwound past the not-yet-registered defer and leaked the freshly created scope on every such request; the defer is now registered immediately after `NewScope()`, with the logger reference nil-guarded for the pre-setup failure path. Regression coverage in `http/kernel_test.go`.
- `application/application_module.go` — `RegisterModule` now guards `ModuleProvider` expansion against a provider cycle. A module that (directly or transitively) provides itself was expanded recursively with no bound, overflowing the goroutine stack and crashing the process at boot; expansion depth is now capped (`maxModuleProviderDepth`) and a cycle fails fast with a `module provider expansion exceeded maximum depth, possible provider cycle` panic instead of an unrecoverable stack overflow. Regression coverage in `application/application_module_test.go`.
- `security/compiled_configuration.go` — `CompiledFirewall.Login` no longer panics with a nil-pointer dereference when a userland `LoginHandler` returns `(nil, nil)`. The contract returns `(*LoginResult, error)`, so a handler returning neither a result nor an error is valid Go, but the firewall previously dereferenced `result.Token` unguarded inside the request goroutine; it now fails closed with a `firewall login handler returned nil result` error before the login-success event is dispatched. Regression coverage in `security/compiled_configuration_test.go`.
- `container/container_resolver.go` — a service resolution that raced `Close()` could store its freshly created instance after the close snapshot was taken, so the instance was never closed (a connection/file-handle leak for standalone container users). The creation guard now fails fast with a `container is closed` error when the container is already closed, and a value whose creation completed while `Close()` ran is closed best-effort instead of being stored; already-created instances remain readable after `Close()`. Regression coverage in `container/container_resolver_test.go`.
- `cache/remember.go` — a **cancelable** `Remember` call whose waiters all timed out cancels the leader's context, but the in-flight entry lingered until the leader's deferred cleanup ran, so a caller that joined in that window inherited the doomed call and received its cancellation error even though a fresh computation would have succeeded. A late joiner now detects the canceled call, replaces the entry, and leads a fresh computation; the leader's cleanup deletes only its own entry so it can no longer evict the replacement. Regression coverage in `cache/remember_test.go`.
- `validation/validation_rule.go` — a regex `validate` tag whose pattern contained a `)`, `]` or `}` **inside a character class** (for example `regex=^[)]a{2,3}b$`, or the parenthesized `regex(value=^[)]$)`) was mis-handled: `hasBalancedBrackets` counted those literals as structural delimiters, so the shorthand splitter mis-split the value at a quantifier comma and the parenthesized form was rejected as "invalid validation tag syntax". A shared `charClassScanner` now treats every member of a `[...]` class (including a literal `]` as the class's first character and a leading `^` negation) as a literal across `hasBalancedBrackets` and `splitByCommaOutsideRegexMeta`, so such patterns parse and enforce intact.
- `http/middleware/static.go` — the static file middleware merged the file server's headers onto an `EmptyResponse` (which seeds `Content-Type: text/plain`) with `Header.Add`, emitting two conflicting `Content-Type` values (the `text/plain` default ahead of the real MIME type) so a CSS/JS asset could be served as `text/plain`. The merge now `Set`s the first value of each header key (and `Add`s the rest), letting the file server's `Content-Type` replace the default.
- `openapi/schema.go` — a pointer numeric field carrying a `greaterThan`/`lessThan` constraint was emitted as `nullable: true` while the validator rejects a null pointer for those constraints, so the spec advertised a `null` the server does not accept. `applyValidation` now clears `Nullable` for `greaterThan`/`lessThan` integer/number fields (a bound-less pointer field stays nullable).
- `mailer/message.go` — a caller-supplied structured identifier header (`Message-ID`, `In-Reply-To`, `References`, `Content-ID`) whose value held a token longer than the encoded-word payload limit was routed through `encodeHeaderText` and wrapped in an RFC 2047 `=?utf-8?q?…?=` encoded-word — which RFC 2047 §5 forbids in msg-id fields, silently breaking mail threading. These headers are now emitted intact (still CRLF-stripped and folded), never Q-encoded.
- `openapi/schema.go` — `applyValidation` no longer leaks a validation keyword onto an `allOf`-wrapped `$ref`. The early-return guard tested only `schema.Ref`, but a nullable struct reference (a `*NamedStruct` field) is emitted by `withNullable` as `{allOf: [{$ref}], nullable: true}` with an empty top-level `Ref`, so an `email` tag on such a field wrote `format: "email"` as a sibling of `allOf` — a position OpenAPI 3.0 ignores, yielding a misleading spec fragment. The guard now also returns when `schema.AllOf` is set, so no constraint is ever attached to a reference wrapper.
- `mailer/message.go` — `foldHeaderLine` no longer emits a header line that exceeds the RFC 5322 998-octet hard limit. The folder broke a value only at spaces against the 78-octet soft limit, so a single unfoldable token longer than ~997 octets — for example a pathological no-space address in `From`/`To`/`Cc`/`Reply-To`, which `mail.ParseAddress` accepts with no length bound — was placed verbatim on a continuation line over 998 octets, a line a strict SMTP server may reject or truncate. An overlong token is now hard-wrapped on rune boundaries so every emitted line stays within the hard limit; values whose tokens are normal-length render byte-for-byte unchanged.
- `storage/local.go` — the local backend now confines every operation with `os.Root` instead of validating the resolved path up-front and then opening it, closing a time-of-check/time-of-use window. An attacker able to plant a symlink at an **intermediate** directory component in the gap between validation and `MkdirAll`/`OpenFile` could previously redirect a write outside the base directory — the prior `O_NOFOLLOW` guarded only the final path component, and `os.MkdirAll` follows intermediate symlinks. `os.Root` re-checks each component against escape as the operation runs, so leaf and intermediate symlink escapes are now both refused atomically with no exploitable window. (Raises the `v3` minimum Go to 1.25 — see `### Changed`.)
- `validation/validation_rule.go` — the parenthesized constraint form `name(value=…)` now accepts a regex whose pattern contains a comma inside a `()` group (for example `regex(value=^(\d{1,3},){3}\d{1,3}$)`). `splitByCommaOutsideRegexMeta` — which splits a parenthesized rule's parameter list — tracked `[]`/`{}`/quote nesting but not `()` depth, so a comma inside a regex group was treated as a parameter separator, split the value mid-pattern, and the trailing fragment failed as `invalid validation tag syntax`. The shorthand form (`regex=…`) already tracked parens via `splitByTopLevelComma` and accepted the same pattern, so the two documented spellings disagreed; the parameter splitter now tracks `()` depth too and the forms agree.
- `mailer/message.go` — a non-ASCII display name (`From`/`To`/`Cc`/`Reply-To`) that also contains an RFC 2047 especial (`,` `(` `)` `<` `>` `;` …) no longer emits that especial literally inside the encoded-word. `encodePhrase` returned Go's `mime.QEncoding` output for any non-ASCII name, but that encoder follows the RFC 2047 *text*-token rules and leaves the phrase especials unencoded, which RFC 2047 §5 (3) forbids in a display-name (phrase) context and which a strict parser can read as a second recipient or a comment. The non-ASCII branch now routes through the same `encodeWordChunks`/`encodeQByte` path used for overlong ASCII names, which Q-encodes both the non-ASCII bytes and the especials, so each encoded word is self-contained and round-trips.
- `openapi/schema.go` — the generated `minimum`/`maximum` for a `greaterThan`/`lessThan` constraint now matches what the runtime validator enforces. The generator parsed the bound with `strconv.ParseFloat`, but the validator instantiates `GreaterThan`/`LessThan` with an integer bound (`validation.parseInt` truncates toward zero), so `greaterThan=9.99` published an exclusive `minimum` of `9.99` while the server only enforced `> 9` — a value such as `9.5` passed server validation but was rejected by a client generated from the spec. The generator now truncates the bound to an integer too, so the published constraint matches enforcement.
- `http/server_sent_event.go` — `ServerSentEventWriter.Send` now strips the U+0000 NUL byte from the `id` field. The EventSource specification ignores an `id` whose value contains a NUL (the Last-Event-ID buffer is left unchanged), so an id derived from an opaque binary cursor would silently break reconnection resumption; the generic field sanitizer (CR/LF only) is unchanged for `event`/`data`/comment, where a NUL is not special.
- `translation/message_format.go` — `plural` selection now resolves the controlling number for every numeric argument type, not only `int`/`int64`/`float64`/`string`. `toFloat` returned `false` for `int8`/`int16`/`int32`, the unsigned kinds, and `float32`, so a plural block fed such a value silently fell to the `other` branch with an empty `#`, even though the same value rendered correctly as a `{placeholder}` (which uses the broader `stringifyParameter`); `toFloat` now covers the remaining numeric kinds so the two paths agree.
- `.documentation/package/VALIDATION.md` — the flagship example tagged an `int` field with `min(value=1),max(value=130)`, but `min`/`max` are string byte-length constraints (`MinLength`/`MaxLength`), so on a numeric field they bound the digit count, not the value — the documented range was silently a no-op. The example now uses `greaterThan(value=0),lessThan(value=131)` for the numeric field and a Footguns note clarifies that `min`/`max` are string-length only.
- `security/token.go` — the `Token` wrapper's `Scope()` and `Attributes()` now return defensive copies (via `internal.CopyAnyMap`) instead of delegating the wrapped token's maps by reference, matching `Roles()` (which already copies) and the defensive-copy contract `AuthenticatedToken` and `InMemoryTokenStore` already honor. A caller that retained and mutated a map obtained through the wrapper could otherwise corrupt the wrapped token's state, and a custom `securitycontract.Token` implementation that returns its live maps had no protection at the wrapper boundary.
- `translation/locale.go` — the Romanian plural rule now classifies a number whose last two digits are `01` (101, 201, 1001, …) as `few` rather than `other`. The CLDR Romanian `few` category is `n % 100 = 1..19` (the value `1` itself resolves to `one` first), but the guard tested `n % 100 = 2..19`, so `101` fell through to `other` and selected the "de"-form (`101 de lei`) where Romanian uses the bare plural (`101 lei`). The lower bound is now `1`; `1`, `2..19`, `0`, and fractional values are unaffected.
- `validation/` — the string constraints (`email`, `regex`, `alpha`, `alphanumeric`, `numeric`, `notBlank`, `min`, `max`) now dereference a pointer or interface field before inspecting it, closing a fail-open on optional `*string` fields. The validator hands each field to a constraint through `reflect.Value.Interface()` without dereferencing, so a field declared `*string` (the idiomatic optional-field shape) arrived as a `*string`: the regex-family constraints' `value.(string)` assertion failed and returned `nil` — a silent PASS for *any* value, including an invalid email or a pattern mismatch — while `notBlank`/`min`/`max` ran `fmt.Sprintf("%v", value)` over the pointer and validated its hexadecimal address (`0xc0000…`), so `notBlank` accepted a nil pointer and `min`/`max` measured the address length instead of the string. A shared `dereferenceValue` helper now unwraps pointer/interface chains (treating a nil pointer as an absent value) before the existing checks, matching the
  dereferencing `greaterThan`/`lessThan`/`notEmpty` constraints already performed.
- `openapi/schema.go` — `splitRuleParameters`, which splits the parameter list inside a parenthesized validation rule (the contents of `regex(…)`), now tracks `()` nesting depth like the runtime validator's `splitByCommaOutsideRegexMeta`. It tracked only `[]`/`{}`/quotes, so a regex whose pattern held a comma inside a `()` group (for example `regex(pattern=^(a,b)$)`) was split at that comma — the generated spec advertised a truncated, syntactically broken pattern (`^(a`) while the server enforced the full `^(a,b)$`. The two splitters now agree.
- `container/container_close.go` — `Close()` no longer calls `Close()` twice on a value-type (non-pointer) service registered with the default options (which register the instance both by name and by its type). Duplicate suppression was keyed by pointer identity only, so the two close candidates that refer to the same value-receiver service — one under its `service:<name>` node, one under its `type:<…>` node — were both closed; a non-idempotent `Close()` could then panic or return a spurious second error (also recorded in the returned failure set). A comparable value is now deduplicated by value identity (gated on `reflect.Type.Comparable()`) alongside the existing pointer dedup.
- `mailer/message.go` — `encodeWordChunks` now splits RFC 2047 encoded-words on rune boundaries, so a multi-byte UTF-8 character in a long non-ASCII display name is never divided across two adjacent encoded-words. The chunker cut the Q-encoded payload at fixed byte offsets and guarded only against splitting a single `=XX` escape triplet, so the two triplets that encode one character (for example `ă` → `=C4=83`) could land in different words — which RFC 2047 §5 forbids and a strict per-word decoder renders as mojibake. Each rune is now encoded as an indivisible token and a new word begins only on a rune boundary (subsuming the previous triplet guard).
- `internal/copy.go` — `CopyAnyMap`/`CopyAnySlice` now deep-copy typed slices and maps, not only `[]any` and `map[string]any`. The previous type switch matched those two shapes and stored every other value (including `[]string`, `[]int`, `map[string]int`, and nested combinations) by reference, so a caller that retained and mutated such a value after a `session` or `storage` save corrupted the stored copy across `Load`/`Save` cycles. A value whose kind is slice or map is now reflected and copied element-wise (scalars and pointers stay shared, as before); a nil interface element is preserved as the element type's zero value.
- `mailer/message.go` — an overlong all-ASCII address display name (`From`/`To`/`Cc`/`Reply-To`) no longer produces a header line past the RFC 5322 998-octet hard limit. A quoted display name is a single space-free token, so the header folder could not break it and emitted it whole on a continuation line; `encodePhrase` now routes a name that contains an overlong token through the same `encodeWordChunks` encoded-word splitting already used for long `Subject` and custom-header tokens. Short names keep the existing quoted form.
- `mailer/message.go` — an overlong all-ASCII attachment filename no longer produces a `Content-Disposition` header line past the 998-octet hard limit. The header was written unfolded with the filename as a single token; when the line would exceed the limit the filename is now emitted as RFC 2231 `filename*0*`/`filename*1*` continuations, each folded under the line limit. Short filenames keep the exact existing `filename="…"` and `filename*=UTF-8''…` forms.
- `openapi/schema.go` — `splitRule` no longer misparses a shorthand `validate` rule whose value ends in `)` (for example `regex=^(foo|bar)`), so the generated OpenAPI schema stops dropping a constraint the server still enforces. The parser decided the parenthesized `name(params)` form purely from "contains `(` and ends with `)`", which also matched a shorthand `name=value` whose value happens to end in `)`; it then returned the bogus rule name `regex=^` and `applyValidation` silently ignored it, omitting the `pattern` (and, for `notBlank`/`notEmpty` shorthands, the `required` flag). It now mirrors the runtime validator's decision (`validation/validation_rule.go`): the parenthesized branch is taken only when there is no `=` or the `(` precedes the `=`, so a trailing `)` inside a shorthand value is preserved as part of the value and the spec matches what the request validator actually checks.
- `cache/in_memory.go` — `Increment`/`Decrement` no longer clear an existing key's TTL on the in-memory backend, matching the Redis backend (whose `INCRBY` preserves the key's expiry). Both paths fed `ttl=0` into the upsert, which replaced the entry with a non-expiring one, so the first increment of a key created with `Set(key, …, ttl)` (a rate-limiter or sliding-window counter) turned it permanent — a silent, backend-dependent leak for an interface meant to be interchangeable. The increment path now reuses the existing item's expiry and only creates a non-expiring entry when the key was absent (or already non-expiring), matching `INCRBY`.
- `mailer/message.go` — the RFC 2047 encoded-word builder used for overlong tokens no longer emits the "especials" (`(` `)` `<` `>` `@` `,` `;` `:` `"` `/` `[` `]` `.` `\`) literally. In a display-name (phrase) context an overlong all-ASCII name routes through `encodeWordChunks`, and a literal `,` or `(` left inside the encoded-word violates RFC 2047 §5 and can make a strict RFC 5322 parser split one recipient into two or treat the name as a comment; `encodeQByte` now Q-encodes those bytes (always valid inside an encoded-word), so each encoded word stays self-contained.
- `http/result_handler.go` — `NormalizeResultToResponse` no longer turns a typed-nil `*Response` into a non-nil `httpcontract.Response` interface. A `ResultHandler` that returns `(*Response)(nil), nil` (the idiomatic "no response" signal) passed the `*Response` type assertion as a nil pointer wrapped in a non-nil interface, so the kernel's `nil != response` check ran the writer and `(*Response).Headers()` panicked on the nil receiver (recovered into a 500 instead of the intended no-content path). The assertion now guards the nil pointer and returns a nil interface, matching the typed-nil handling the reflection-based controller wrapper already applies via `internal.CanReflectValueBeNil`.
- `openapi/` — `collectStructFields` no longer hangs on a self- or mutually-embedded struct. The embedded-field promotion walk re-assigned its work queue every level with no visited-type guard, so an anonymous `*T` that (directly or via a partner type) embedded its own type was re-enqueued forever — an infinite CPU spin that hangs the serving goroutine when such a type is reflected through `SpecHandler`/`Generate` (a request-triggered denial of service). The walk now tracks the types it has already promoted (seeded with the root struct) and skips a repeat, matching `encoding/json`'s `typeFields`; the pre-existing recursion guard only covered struct-typed fields, never the embed walk.
- `validation/` — the `validate` tag grammar now accepts a regex containing a group. `parseValidationTag` classified a rule as parenthesized-form by counting `(`/`)` anywhere in the fragment, so the documented shorthand `regex=^(a|b)$` (the parens are a regex group) was misrouted to the `name(params)` branch and hard-rejected with `"invalid validation tag syntax"` — and the parenthesized `regex(pattern=^(a|b)$)` failed too (two paren pairs tripped the single-pair guard), so no spelling could express an alternation/capture group. Classification is now by position (a fragment is parenthesized only when `(` precedes any `=`), and the parenthesized branch matches the outer parens and validates inner balance, so both spellings carry a grouped pattern verbatim. Same fail-class lineage as the comma-in-char-class and literal-`{` splitter fixes.
- `validation/` — `LessThan.Validate` now emits error code `"greaterThanMax"` instead of `"greaterThan"`. The old value collided with the `ConstraintGreaterThan` tag name (`"greaterThan"`), making a `LessThan` failure indistinguishable from a `GreaterThan` failure in error-handling logic that inspects `ValidationError.Code()`.
- `storage/` — `LocalStorage.Get` now returns an error when the resolved key is a directory. Previously, opening a directory with `O_RDONLY` on Linux succeeds at the OS level, so `Get` returned a non-nil `io.ReadCloser` and a `nil` error; the first `Read` call then failed with `EISDIR`. The directory is now detected via `Stat` immediately after open and rejected with a clear error.
- `session/` — `copyAnyMap` now deep-copies `[]any` slices in addition to nested `map[string]any` values. Previously, a slice whose elements were maps was copied by reference; a caller mutating a map inside a slice returned by `Load` could silently corrupt the stored session data, and vice versa after `Save`.
- `security/` — `InMemoryTokenStore.cloneClaims` and `AuthenticatedToken.copyAnyMap` now deep-copy nested `map[string]any` values and `[]any` slices in `Scope` and `Attributes`. Previously both used a one-level copy, so a caller mutating a nested map retrieved via `Lookup` (or received from `Scope()`/`Attributes()`) could corrupt the stored token entry.
- `openapi/` — the `validate` tag parser now understands the canonical parenthesized constraint syntax (`min(value=3)`, `max(value=64)`, `regex(pattern=^x$)`, `greaterThan(value=0)`) that the `validation` package enforces and the docs prescribe. The previous parser split each rule on the first `=` only, so a parenthesized constraint produced a garbage rule name and emitted no `minLength`/`maxLength`/`pattern`/`minimum` — silently under-specifying the generated spec relative to the runtime validator. Rule splitting is also group-aware now, so a comma inside `{n,m}` or a character class no longer truncates a `regex`/`pattern` value.
- `openapi/` — a `requestBody` is no longer attached to body-less HTTP methods. `buildOperation` added the descriptor's request schema to every verb of a multi-method route, so a route exposing `GET`/`HEAD`/`DELETE` alongside `POST` emitted a `requestBody` (with `required: true`) on the `GET`/`HEAD`/`DELETE` operations — invalid for `GET`/`HEAD` and breaking generated clients; the body is now emitted only for `POST`/`PUT`/`PATCH`.
- `validation/` — the shorthand `regex=PATTERN` tag is now enforced instead of failing open. `createConstraintWithParams` read the regex pattern only from `params["pattern"]` (set by the parenthesized `regex(pattern=…)` form), so the flat `regex=…` form — which stores its value under `params["value"]` — fell through to the match-everything default `.*`; the flat form now binds its value as the pattern.
- `http/server_sent_event.go` — `ServerSentEventWriter.Send` now treats a bare `CR`, a `CRLF`, or an `LF` inside `Data` as a data-line boundary (per the EventSource specification) instead of deleting bare carriage returns. A `CR`-delimited payload was previously merged into a single `data:` line, corrupting multi-line data carried across instances by the backplane; injection remains neutralized because each fragment stays a `data:` line.
- `security/` — `AccessControlBuilder.AllowAnonymous(prefix)` now matches on path-segment boundaries instead of a raw string prefix. `AllowAnonymous("/api/public")` previously also opened sibling paths such as `/api/public-data` and `/api/publicXYZ/secret` to anonymous access; it now uses the segment-aware rule so only `/api/public` and its `/`-delimited children are public.
- `security/` — `NewApiKeyHeaderAuthenticator` now panics on an empty expected value, matching `NewApiKeyHeaderRule`. An empty configured key produced an authenticator that could never authenticate (a misconfiguration that should fail loudly at construction rather than degrade silently).
- `security/` — a signed JWT or stored opaque token with an empty/absent/non-string subject is now rejected instead of authenticating as the empty principal `""`. `InMemoryTokenStore.Lookup`/`Put` copy the `Claims` slice and map fields so a caller mutating returned `Roles`/`Scope`/`Attributes` can no longer mutate the stored entry.
- `messagebus/` — when retries are exhausted and the `FailureTransport` itself rejects the message, the source requeue now carries a backoff `DelayStamp` so a persistently unreachable failure transport no longer spins at full speed. A delivery channel that closes without a cancelled context now returns an error from the consumer (a lost broker connection is no longer reported as a clean exit). The in-memory transport drops a requeue on a closed transport instead of blocking.
- `translation/` — `#` now stays bound to the enclosing `plural` through a nested `select` (ICU semantics); previously a `select` nested inside a `plural` lost the number substitution.
- `mailer/` — long header values are folded at whitespace per RFC 5322 (a long pure-ASCII subject no longer produces a single line over the 998-octet limit); the `Manager` validates every address with `net/mail.ParseAddress` (rejecting malformed/smuggled addresses before delivery); and a message with attachments but an empty body no longer emits a spurious empty `text/plain` part.
- `http/server_sent_event.go` — `ServerSentEventWriter.Send` strips `CR`/`LF` from the `Id` and `Event` fields so a caller-supplied value can no longer inject extra Server-Sent Events fields or events. The `Data` field is split into multiple `data:` lines on `LF` and now also has stray `CR` stripped from each line — a lone `CR` is an Server-Sent Events line terminator, so without this a `CR` embedded in `Data` could inject an extra field client-side; this matters now that the Server-Sent Events backplane carries `Data` across instances as JSON (which preserves `CR`). `ServerSentEventWriter.Comment` likewise strips `CR`/`LF` from its text (it shares the same field sanitizer as `Send`), so a dynamic comment can no longer break out of the `: ` comment line and inject an Server-Sent Events field.
- `http/server_sent_event_hub.go` — `Broadcast` no longer replicates to the `ServerSentEventBackplane` after `Shutdown`: once the hub is closed `DeliverLocal` already returns zero (its subscribers are drained), so a late broadcast was still publishing a cross-instance event no local subscriber wanted and attempting a publish during teardown. `replicate` now short-circuits when the hub is closed, reading the closed flag under the same lock it takes to snapshot the backplane.
- `openapi/` — a nullable pointer to a named struct now emits `{"allOf":[{"$ref":…}],"nullable":true}` instead of setting `nullable` as a sibling of `$ref`, which OpenAPI 3.0 tooling ignores (the field's nullability was being lost).
- `openapi/` — two distinct struct types that share a bare name (e.g. `product.Request` and `order.Request`) no longer collide in `components/schemas`: the component name was keyed on `reflect.Type.Name()` alone, so the second type silently reused the first type's schema and every `$ref` to it pointed at the wrong shape. Each distinct type is now assigned a unique component name (the clashing one is disambiguated with a numeric suffix).
- `lock/` — `InMemoryLocker` `Refresh` rejects a non-positive `ttl` (returning an error) instead of silently converting a TTL lock into a never-expiring one, matching the Redis backend's guard.
- `messagebus/` — the in-memory transport gains `WithLogger`; a delayed requeue dropped on a full/closed queue is now logged instead of vanishing silently.
- `lock/` — `InMemoryLocker` opportunistically purges expired holders during `Acquire`, bounding map growth for locks that expire without an explicit `Release`/`Refresh`.
- `security/` — runtime access-control matching now honors the rule type. `(*AccessControl).Match` already implemented the documented exact → longest-prefix → segment-prefix → regex → fallback priority, but the kernel access-control listener matched requests with a separate prefix-only matcher that ignored `isExact`/`isRegex`/`isSegmentPrefix`, so `NewAccessControlExactRule` was enforced as a prefix, `NewAccessControlRuleWithSegmentPrefix` lost its segment boundary, and `NewAccessControlRegexRule` rules (which carry an empty prefix) collapsed into the single empty-prefix fallback — letting a later protected regex rule be silently shadowed by an earlier public one. The listener now routes through `(*AccessControl).Match`, so a protected `^/admin` regex rule is enforced instead of a request falling through to an earlier `PUBLIC_ACCESS` rule.
- `messagebus/` — `melody:messagebus:consume --limit` no longer overshoots by up to `concurrency-1` messages: the limit budget is reserved before a worker receives an envelope, so a `--limit N --concurrency M` run consumes and acks exactly `N` messages instead of up to `N+M-1` (previously the limit was only checked after a message had already been dispatched and acked).
- `openapi/` — a route registered with multiple HTTP methods now emits a distinct `Operation` per verb with a unique `operationId` (`<routeName>.<method>`) instead of sharing one `Operation` pointer and a duplicate `operationId` across verbs, which is an invalid OpenAPI 3 document and aliased every verb's request/response shape.
- `openapi/` — promoted embedded-struct fields are now resolved by depth, matching `encoding/json`: the shallowest field with a given json name wins regardless of the embed's declaration order, and fields that tie at the minimum depth are dropped as ambiguous (unless exactly one is explicitly json-tagged). Previously the embed pass recursed depth-first with a first-wins skip, so a deeper-but-earlier embedded field could shadow a shallower-but-later one and the generated schema documented the wrong type for that field.
- `mailer/` — `foldHeaderLine` now folds a long opening token onto a continuation line too; previously the first word never folded, so a long single-token header value (a tracking id, a `List-Unsubscribe` URL) left the opening header line unbounded. An indivisible token longer than the limit is still emitted intact rather than split, since folding whitespace injected inside a token would corrupt its value once the receiver unfolds the header.
- `mailer/` — the SMTP transport now fails closed when `SmtpConfig{RequireAuth: true}` is set but no username is configured (for example a secret that resolves to the empty string): the `RequireAuth` check was previously gated on a non-empty username, so the transport skipped authentication entirely and delivered the message unauthenticated, making the control a silent no-op exactly when it mattered.
- `storage/` — `NewLocalStorage` no longer false-rejects every key when the base directory is created lazily under a symlinked ancestor (a common container/mount layout): the symlink-escape guard re-resolves the base each call instead of caching the unresolved path from construction time, so an object resolved through the symlink is correctly recognised as inside the base rather than reported as a symlink escape.
- `security/` — `AccessControlBuilder.AllowAnonymous(prefix)` now emits a rule carrying the `PUBLIC_ACCESS` attribute instead of an empty attribute set. An empty-attribute rule matched the path but then fell through the access-control listener's public-access check to the require-authentication branch, so `AllowAnonymous` actually **denied** anonymous requests (401) — the opposite of its name; routes meant to be public now grant access without a token.
- `openapi/` — wildcard route segments (`*name` single and `*name...` catch-all, both supported by the router) are now normalised to `{name}` in the generated path template and emit a path parameter, instead of being written verbatim. A `*` segment is not a valid OpenAPI 3.0.3 path key, so the previous output produced a document strict validators reject and left the wildcard parameter undocumented.
- `http/` — `JsonHandler[Req]` now rejects trailing data after the first JSON value (matching `Request.BindJson`'s whole-body semantics), returning `400 invalid json`. `json.Decoder.Decode` reads only the first value and silently ignored the rest, so a body such as `{…} garbage` or two concatenated objects was accepted while the manual binder rejected the same input.
- `storage/` — `LocalStorage` no longer follows a symlink at the leaf of a key. A leaf that is a symlink — including a *dangling* one whose target does not exist yet — was approved by the ancestor-only symlink walk, so an `O_CREATE` write followed the link and planted a file outside the base directory; the leaf is now rejected and `Put`/`Get` open with `O_NOFOLLOW` to also close the time-of-check/time-of-use window on a swapped leaf symlink.
- `storage/` — `LocalStorage.Put` now enforces the caller-declared content length: a reader that ends early or runs long returns an error (and the partial object is removed) instead of silently persisting a wrong-sized object, matching the S3 backend's content-length semantics. A negative size means "unknown" and skips the check.
- `security/` — `NewApiKeyHeaderRule` now panics on an empty header name or empty expected value instead of failing open. An empty expected key made a request that omits the header compare `""` against `""`, which the constant-time compare reports as equal — granting every unauthenticated request — mirroring the guard `ApiKeyHeaderAuthenticator` already had.
- `security/` — `NewAccessControlRule`/`NewAccessControlRuleWithSegmentPrefix` now reject `PUBLIC_ACCESS` combined with any other attribute. The listener grants on `PUBLIC_ACCESS` before any token/role/voter check, so a rule such as `(PUBLIC_ACCESS, ROLE_ADMIN)` would silently open the endpoint to everyone and discard the role requirement; the combination now fails closed at construction. The `AllowAnonymous` builder (a lone `PUBLIC_ACCESS`) is unaffected.
- `openapi/` — an optional path parameter (`:slug?`, supported by the router) is now normalised to `{slug}` with parameter name `slug` instead of the invalid template `{slug?}`/parameter name `slug?`; a bare unnamed placeholder (`*`, `:`, `{}`) gets a synthesised positional name instead of leaving the raw router token in the path key — both previously produced documents strict OpenAPI validators reject.
- `openapi/` — routes whose only methods are `HEAD`/`OPTIONS`/`TRACE` are no longer silently dropped from the document: `PathItem` gained `head`/`options`/`trace` and `assignOperation` now maps those verbs.
- `openapi/` — `greaterThan`/`lessThan` emit `minimum`/`maximum` only on numeric schemas and `regex`/`pattern` emits `pattern` only on string schemas, matching the existing `min`/`max` type guard, so a mis-applied `validate` tag can no longer emit a keyword that is invalid for the field's type.
- `messagebus/` — `Manager.Dispatch` rejects a `nil` message with a clear error instead of panicking. A nil message has no reflectable type, so the no-handler path dereferenced a nil `reflect.Type` (`reflect.TypeOf(nil).String()`) and crashed the dispatch/worker goroutine; the no-handler path also reports a safe `<nil>` type name as defence in depth.
- `messagebus/` — the `melody:messagebus:consume` retry-exhaustion path now logs a warning before nacking without requeue when no `FailureTransport` is configured, mirroring the decode-failure poison path, so an operator running the default (no dead-letter) no longer silently loses every message that exhausts its retries.
- `mailer/` — a long *no-space* ASCII `Subject` is now chunked into RFC 2047 encoded-words so every emitted line stays under the RFC 5322 / SMTP 998-octet hard limit. `mime.QEncoding` leaves pure-ASCII unchanged, so such a subject previously folded into one oversized line many MTAs reject or corrupt; adjacent encoded-words are concatenated without their separating whitespace on decode, so the subject round-trips.
- `mailer/` — a caller-supplied custom header now receives the same overlong-token protection as `Subject` (`encodeHeaderText`), so a value that is a single no-space token longer than the line limit (a tracking id, a signed `List-Unsubscribe` URL, a JWT) is chunked into RFC 2047 encoded-words instead of being emitted intact on one line over the 998-octet hard limit that strict MTAs reject. Normal short or whitespace-delimited header values are left byte-for-byte unchanged (`mime.QEncoding` is a no-op for pure-ASCII without an overlong token); only the pathological indivisible-token case is encoded, and it round-trips for RFC 2047-aware readers. Structural address headers still fold at whitespace via `foldHeaderLine`.
- `openapi/` — a `[]byte` field is now described as a base64 `{"type":"string","format":"byte"}` instead of an array of integers. `encoding/json` (used by both `JsonHandler` and `Request.BindJson`) serialises a byte slice as a base64 string, so the previous integer-array schema contradicted the framework's own wire format and a client generated from the spec would send a body the binder rejects. Fixed-size byte arrays (`[N]byte`), which `encoding/json` does not base64-encode, stay integer arrays.
- `mailer/` — `Manager.Send` now rejects a message whose only recipients carry an empty email address. The recipient-presence guard counted slot lengths, but `validateAddresses` skips empty-email entries, so a recipient slot with only a display name passed validation and reached the transport with no deliverable recipient (silently recorded by transports that trust the manager's validation); the guard now counts addresses with a non-empty email.
- `openapi/` — two of a struct's **own** (non-embedded, depth-0) fields that map to the same json name are now resolved like `encoding/json`: the conflict is kept only when exactly one of them is explicitly json-tagged, otherwise both are dropped as ambiguous. The own-field pass was first-wins, so it emitted a property for a json name that `encoding/json` (used by `JsonHandler`/`Request.BindJson`) never serializes or accepts — diverging the generated spec from the wire format. The embedded-field pass already applied this rule; the own-field pass now shares it.
- `http/server_sent_event.go` — `ServerSentEventWriter.Send` no longer emits an empty `data:` line for an event that carries no `Data` (an id-only or retry-only event). A data field — even empty — makes an `EventSource` client dispatch a spurious empty message, whereas an event with only `Id`/`Retry` must update the last-event-id / reconnection time without dispatching; the `data` block is now guarded for an empty `Data`, matching the existing empty-guards on the `Id`/`Event`/`Retry` fields.
- `session/` — `InMemoryStorage.Load` no longer deletes a freshly-saved session when an expired entry is evicted under concurrency. The expiry path released the read lock and then deleted the key unconditionally under the write lock, so a `Save` that landed in that window wrote a fresh entry the stale delete immediately removed; `Load` now re-checks, under the write lock, that the current entry is still expired before deleting it (the same pattern the cache backend already uses).
- `validation/` — `greaterThan`/`lessThan` now reject a floating-point `NaN` instead of silently accepting it. IEEE-754 comparisons against `NaN` are always false, so `NaN >= max` / `NaN <= min` evaluated false and the value passed the bound; the constraints now reject a non-finite float explicitly.
- `session/` — `InMemoryStorage` `Load`/`Save` now deep-copy nested `map[string]any` values (via the same `copyAnyMap` the file backend already uses) instead of copying only the top-level map. A caller mutating a nested map returned by `Load` (or one retained after `Save`) could previously reach through the shared reference and corrupt the stored session; the in-memory and file backends now isolate session data identically.
- `messagebus/` — `NewSendMessageMiddlewareFromRouting` now snapshots the `Routing` map when the middleware is built rather than sharing the builder's live map. A `RouteType` call made after the middleware was constructed could concurrently mutate the map the dispatch path reads (a `fatal error: concurrent map read and map assignment`); the built middleware now holds an isolated copy.
- `messagebus/` — the in-memory transport's `WithLogger` and the delayed-requeue goroutine that reads the logger are now synchronized, removing a data race when a logger is attached while a delayed requeue is in flight (matching the audit storage's logger guard).
- `storage/` — `LocalStorage.Exists` now uses `os.Lstat` instead of `os.Stat`, so it never follows a symlink at the object path. `Put`/`Get` already open with `O_NOFOLLOW` and `resolvePath` rejects a symlinked leaf; `Exists` now matches that no-follow posture, closing a narrow window where a symlink swapped in after the path check could have disclosed the existence of a target outside the base directory.
- `storage/` — `LocalStorage.Put` now removes the partially-written object when the source reader errors mid-stream instead of leaving a truncated file on disk. The copy-error path returned without cleanup while the adjacent size-mismatch path already removed the file, so a streaming upload (`size = -1`, the documented "unknown size" mode) whose reader failed part-way left a partial object that `Exists` reported present and `Get` returned in full with no error — silent data corruption. A failed `Put` now leaves no object, matching the size-mismatch path and the S3 backend's atomic-on-failure semantics.
- `validation/` — the shorthand `regex=PATTERN` tag now preserves a comma inside a character class (`[a,b]`) or a quantifier (`{n,m}`), matching the parenthesized `regex(pattern=…)` form. `splitByTopLevelComma` (which splits a `validate` tag into its rules) guarded only parentheses, so a comma inside regex meta in the shorthand value was treated as a rule separator: the first fragment compiled to a truncated, invalid pattern that rejected all input and the orphan fragment raised a spurious `unknown validation rule`. The tag splitter is now regex-meta aware (`[]`/`{}` depth), so both spellings of the same constraint validate identically.
- `openapi/` — a struct field tagged `json:"-,"` (a field whose JSON name is the literal `-`, the trailing comma disabling the bare-`-` omit meaning) is now emitted under the key `-` instead of being dropped from the schema. `jsonFieldName` split the tag and treated `parts[0] == "-"` as an omitted field, but `encoding/json` (used by `JsonHandler`/`Request.BindJson`) serializes such a field under the key `-`; the bare `json:"-"` omit is still honored, so the generated schema no longer under-documents this field relative to the wire format.
- `validation/` — a shorthand `regex=PATTERN` whose pattern contains a literal `{` (a valid RE2 expression, e.g. `regex=a{`) no longer silently swallows every following rule. `splitByTopLevelComma` incremented its curly-brace depth on the opening `{` and, never seeing a closing `}`, treated the comma that separates the next rule as protected — so `regex=a{,min=5` parsed as a single rule and the `min=5` constraint was dropped with no error (fail-open: a declared constraint silently not enforced). The splitter now pre-checks that brackets balance and, when they do not, treats commas as plain rule separators; a balanced quantifier such as `a{2,5}` still protects its inner comma.
- `openapi/` — the `validate`-tag splitter now honors backslash escapes and quotes exactly like the runtime `validation` parser, so the generated spec no longer diverges from what is enforced. The generator split rules on group depth only, so an escaped comma in a shorthand regex (`regex=a\,b`) was cut into a truncated, invalid pattern (`a\`) and a quoted comma in a parenthesized param (`regex(pattern='a,b')`) was truncated to `'a` — advertising a different (and invalid) pattern than the validator applies. Rule and parameter splitting now mirror `splitByTopLevelComma`/`splitByCommaOutsideRegexMeta` (escape-aware at the top level, escape- and quote-aware inside parameters, with the same balanced-bracket fallback), so both layers agree on the same tag grammar.
- `openapi/` — an embedded struct whose `json` tag carries options but no name (`json:",omitempty"`, `json:",string"`) is now promoted into the parent schema, matching `encoding/json`. `isPromotedEmbed` treated any non-empty `json` tag as a non-promoted field, so the generator emitted the embed as a nested object property (a `$ref`) while the wire format promotes its fields to the parent — a client generated from the spec then sent a nested object the server's `encoding/json` binder rejects. The guard now keys on the tag's name part, so a name-bearing tag (`json:"inner"`) stays nested and a bare `json:"-"` embed stays dropped, exactly as `encoding/json` resolves them.
- `storage/` — `LocalStorage.Put` now surfaces the error from closing the destination file instead of discarding it through a deferred `Close`. `io.Copy` reports bytes accepted into the kernel page cache, but a buffered/delayed-allocation flush failure (a full disk, an exceeded quota, an NFS write-back error) can surface only at `close(2)`, so a `Put` whose `written == size` could still return `nil` for a truncated object. `Put` now closes the file explicitly on the success path and, when that close fails, removes the partial object and returns an error — matching the S3 backend's atomic-on-failure contract where a `nil` return means the object was durably written.
- `container/container_close.go` — `Close()` no longer panics with `hash of unhashable type`, and reliably closes a dual-registered value-type service exactly once. The alias-collapse and dedup logic decided value comparability from the *static* type via `reflect.TypeOf(value).Comparable()`, so a value-type service whose static type is comparable but whose interface field holds an unhashable value (a slice/map/func) passed the check and then panicked when used as a Go map key — aborting the whole shutdown with the container left mutex-locked and never marked closed (every service ordered after it leaked its connection/handle). The check now uses `reflect.ValueOf(value).Comparable()` (runtime contents), and a `type:<T>` node is collapsed onto its backing `service:<name>` structurally via `typeRegistrationNamesByType`, which is correct even for a non-comparable value-type service that previously received its own representative under each alias and was closed twice.
- `translation/message_format.go` — a plural argument (and its `#` substitution) of type `encoding/json.Number` is now treated as numeric. `toFloat` had no `json.Number` case, so a count decoded by `json.Decoder` with `UseNumber()` (the idiomatic way to avoid float precision loss) fell through to the non-numeric branch, selected the `other` category, and rendered `#` as an empty string regardless of the value — while the plain `{name}` placeholder rendered it correctly. `json.Number` now resolves through its `Float64()` like the other numeric kinds.
- `storage/local.go` — `LocalStorage.Exists` now reports a directory key as absent instead of present. `Exists` returned true for any path that `Stat`s, including the implicitly-created parent directory of a previously `Put` object, contradicting `Get` (which rejects a directory key) and `Put` (which fails with `EISDIR`) and diverging from the S3 backend (a prefix with no object at the exact key is absent). It now returns false when the resolved path is a directory.
- `validation/validation_rule.go` — a regex `validate` tag with a literal quote (`'` or `"`) inside a character class no longer mis-parses. In `splitByCommaOutsideRegexMeta` the quote handlers ran before, and independent of, the character-class scanner, so a quote inside `[...]` toggled quote state; an odd number of class-literal quotes left the flag stuck on, swallowing the top-level comma and silently dropping every following constraint (fail-open). The quote handlers are now gated on `classScanner.inClass`, so a quote inside a class is treated as class content. Same fail-class lineage as the comma-in-char-class and literal-`{` splitter fixes.
- `openapi/schema.go` — the `email` validate tag now emits `format: email` only on a string schema, matching the `min`/`max`/`regex` cases (and the runtime `Email` constraint, which is a no-op on a non-string value). A field such as `Mail int validate:"email"` no longer produces the nonsensical `{type: integer, format: email}`.
- `openapi/schema.go` — a pointer field constrained by `greaterThan`/`lessThan` is now marked `required` in the generated spec. The runtime validator rejects a nil pointer for those constraints, so the field must be present; the spec previously advertised it as optional (only `notBlank`/`notEmpty` implied `required`), letting a spec-conforming client omit a field the server then rejects.
- `security/jwt_token_validator.go` — a fractional `NumericDate` `nbf`/`iat` claim now rounds toward the fail-closed direction. `numericClaim` truncated toward zero (floor) for every claim, so a fractional `nbf` (RFC 7519 permits non-integer dates) activated the token up to ~1s before the issuer's stated instant; `nbf`/`iat` now round up (`math.Ceil`) while `exp` still rounds down, so a fractional bound never widens the validity window.
- `translation/message_format.go` — the plural `#` substitution now preserves the exact integer for `int64`/`uint64`/`json.Number` values above 2^53. `#` was rendered from the `float64` used for plural-category selection, so a large integer printed rounded while the `{name}` placeholder rendered it exactly; `#` now formats an integer-typed argument from its exact value.
- `openapi/schema.go` — the `greaterThan`/`lessThan` bound is now emitted even when the tag value carries trailing non-numeric characters, matching the runtime validator. The generator parsed the value with `strconv.ParseFloat` (which fails on e.g. `greaterThan=5x` and emitted no bound) while the validator reads the leading integer via `Sscanf("%d")` and enforces `>5`; the generator now parses the same leading integer, so the spec no longer omits a bound the server actually enforces.
- `validation/value.go` — the string constraints (`email`, `regex`, `alpha`, `alphanumeric`, `numeric`) no longer fail open on a **defined string type** (for example `type Email string`). `dereferenceValue` unwrapped pointers/interfaces but returned the value with its dynamic type, so the constraints' `value.(string)` assertion failed for a named string type and returned `nil` — a silent PASS for any value, the same fail-open the `*string` fix closed for pointers but reached through a domain-typed request field instead. `dereferenceValue` now normalizes a string-kind value to a plain `string`, so all five assertion-based constraints enforce on named string types too (the `fmt.Sprintf("%v", …)`-based `notBlank`/`min`/`max` were already unaffected).
- `config/environment_source.go` — the `.env` preprocessor no longer truncates an unquoted value at an inline `#` that is not preceded by whitespace. It treated every unquoted `#` as a comment start, so `COLOR=#ffffff` became empty and a secret like `PASSWORD=ab#cd` was silently truncated to `ab`, diverging from the bundled `godotenv` parser (which treats `#` as an inline comment only when preceded by whitespace). The preprocessor now matches that rule (comment only at line start or after whitespace), and the per-value `strings.TrimSpace` that defeated quoted-whitespace preservation (`KEY="  padded  "` → `padded`) was dropped, since `godotenv` already trims unquoted values and preserves quoted ones.
- `http/router_utility.go`, `http/kernel.go` — a controller that mutates or clears the session and returns a `nil` response (the idiomatic "no body" signal) no longer loses the session change. Session persistence (`SaveSession`/`DeleteSession` + the `Set-Cookie`) lived only inside `writeResponse`'s non-nil branch, and the kernel did not call `writeResponse` at all on the `(nil, nil)` path — so a logout handler that cleared the session left the server-side session live and the cookie uncleared, and the client received an implicit `200` instead of `204`. The kernel now runs `writeResponse` on the nil path and `writeResponse` synthesizes an empty `204` response so the session block runs and the cookie is emitted.
- `translation/message_format.go` — the plural `#` substitution now renders a `float32` argument with its shortest representation, matching the `{placeholder}` path. `formatPoundValue` lacked a `float32` case and fell through to formatting the widened `float64` (`float32(0.1)` → `0.10000000149011612`), while `{value}` rendered `0.1`; the two paths now agree.
- `openapi/schema.go` — the validation-tag splitters (`splitTopLevelRules`, `splitRuleParameters`, `hasBalancedRuleBrackets`) now share the runtime validator's `charClassScanner`, so a regex with a structural bracket inside a `[...]` character class (for example `regex=^[)]a{2,3}b$`) is no longer mis-split. The generator tracked a raw `[]` depth and treated a `)` inside `[)]` as an unbalanced paren, falling back to blind comma-splitting that truncated the published pattern (`^[)]a{2`) while the server enforced the full pattern; the splitter now treats class members as literals exactly like the validator.
- `openapi/schema.go` — `min`/`max` string-length bounds now parse the leading integer via `parseLeadingInt` (matching the validator's `Sscanf`-based parse) instead of `strconv.Atoi`, so `max=99.5` publishes `maxLength: 99` (what the server enforces) instead of omitting the bound entirely on the parse error.
- `container/container_close.go` — `Close()` is now safe against a concurrent second `Close()` call. `isClosed` was checked at entry but only set after the whole service-close loop ran with the mutex released, so two overlapping calls both snapshotted the same services and closed every one of them twice (the per-call dedup maps are local). `isClosed` is now set while still holding the entry lock, so a concurrent call returns at the guard.
- `container/scope.go` — `OverrideProtectedInstance` now checks the closed-scope flag **inside** the mutex, matching the lookup methods. The check ran before acquiring the lock, so a concurrent `Close()` (which nils the maps under the lock) could slip in between the check and the `instances[name] = value` assignment, panicking with `assignment to entry in nil map` in a detached goroutine instead of taking the structured "scope is closed" path.
- `.example/config/security.go` — the demo access-control no longer locks the operational and demo endpoints behind login. The `^/` catch-all (`RoleUser`) gated `/health`, `/metrics`, `/openapi.json`, `/ws`, and every `*/demo` route the README invites the reader to `curl` anonymously, so those returned `401`; explicit `PublicAccess` rules now precede the catch-all for the documented anonymous endpoints.
- `.example/security/session_login_handler.go`, `session_logout_handler.go` — the reference session login handler now writes `SessionKeySecurityRoles` (from the token's `Roles()`) alongside the user id, and the logout handler deletes it. The token resolver returns an anonymous token when roles are absent, so a login through the firewall handler previously authenticated as anonymous on the next request; the handler now mirrors the route-based login flow.

### Security

- `security/access_control.go` — an exact or anchored-regex access-control rule could be bypassed by appending extra trailing slashes to the request path. The router collapses **all** trailing slashes (`strings.TrimRight`), so `/admin//` routes to the `/admin` handler, but `matchRuleIndex` trimmed only **one** (`strings.TrimSuffix`), normalizing `/admin//` to `/admin/` — which an exact rule `/admin` (or a `^/admin$` regex) no longer matches. With no other matching rule the listener treated the request as unguarded and ran the protected handler anonymously. `matchRuleIndex` now collapses all trailing slashes like the router, so the two path views agree.
